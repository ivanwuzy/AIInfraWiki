# 芯原股份 IP资产、客户交付与机器人 SoC 适配尽调

> Sources: 本地横纵研究报告，2026-08-11
> Raw: [芯原股份VeriSilicon横纵分析报告](../../raw/sources/2026-08-12-芯原股份VeriSilicon_横纵分析报告-4.md)
> Updated: 2026-08-12

## 问题定义

芯原微电子（上海）股份有限公司可确认的交付模式是处理器/接口/模拟 IP 授权与 SiPaaS 芯片定制服务。公开页面不足以确认某一机器人项目的 IP 授权范围、PPA/软件表现、项目经济性、量产责任或资产可转让性。须在任何量产采购、战略投资或资产交易前，将公司级宣传和项目级事实拆开核验。

## P0：IP、软件与项目资产是否可用于目标 SoC

**已有证据：**报告记录 NPU、GPU、ISP、VPU、DSP、接口等 IP 组合，以及面向目标模型的 API/框架适配与 IDE 入口；公司将模式定位为 SiPaaS。

**限制：**未见目标 IP 的版本化权属账册、RTL/软件/文档交付范围、第三方/开源许可证、工艺/PDK/EDA 限制、地域及再许可权、客户隔离义务、缺陷修复和终止后衍生成果归属。

**关闭条件：**在 NDA 下逐项取得 IP 自研/第三方属性、工艺验证、silicon-proven 状态、许可/续期/可转让性、出口管制、源代码/二进制、SDK、工具版本和支持期限；合同须明确 NRE、royalty 计量、验收、PPA、流片/封测/良率、质量、PCN、EOL、RMA 与终止权。

## P0：客户芯片累计出货与商业质量

**已有证据：**公司称采用其 NPU IP 的 AI 类客户芯片累计出货“近 `2 亿颗`”，内置其 GPU IP 的客户芯片累计出货“超 `20 亿颗`”。

**限制：**这些是客户芯片的公司累计口径，未披露芯片型号、客户、应用、地区、一次性授权费、版税、应收、回款、集中度或机器人占比；不能转写为芯原标准芯片出货、订单、收入或机器人商业化。

**关闭条件：**以客户许可的合同、PO、许可/版税报表、项目阶段、出货、验收、发票、回款、应收账龄、退货/RMA、前五客户、续约和支持责任，按法人、IP、产品和工艺拆分核验。

## P0：目标机器人负载、软件与安全责任

**已有证据：**NPU 产品线涵盖 `VIP9000` 与 `VIP9400`，并披露框架/API 适配；公司亦披露部分功能安全与车规项目节点。

**限制：**未有公开、统一且独立复现的机器人/VLA 模型基准、精度、频率、片上/外部存储、工艺、功耗、带宽、热、SDK 可维护性、多卡通信或系统安全闭环。IP 认证/一次流片/匿名车规项目均不能自动证明整颗机器人 SoC 的安全等级、量产、失效数据或售后责任。

**关闭条件：**以固定工艺、IP 配置、模型、量化/精度、SDK/BSP/驱动版本和硬件条件复测算子覆盖、P50/P95、能耗、热、稳定性、异常恢复及模型迭代；另取得 Safety Manual、认证范围、FMEDA/故障树、质量/失效数据及系统级安全责任划分。

## P1：Coral 与开放生态路线的商业成熟度

Google 与芯原的 Coral NPU 路线可确认开源 IP、RISC-V/MLIR 基础、企业版计划与验证芯片开发状态；不能写成已量产、已有机器人客户或等同 CUDA-like 平台。只有取得目标工艺样片、PPA、可复现基准、SDK/编译器/运行时版本、许可/支持条款、设计赢单、量产客户及多代维护记录后，才重新评估其采购和分类含义。

## 决策门槛

1. 未闭环前仅可进行非排他、里程碑付费、可退出的架构/软件 PoC，且不承担量产或独家绑定。
2. 只有项目级 PPA、模型、合同/权属、供应责任和安全验证同时满足目标，才扩大至 IP 授权或 SoC 定制。
3. 资产交易还须额外确认上市公司监管、客户同意、人员承接、第三方许可、未决质量责任与可分拆边界；否则不启动控制权并购。
