## 概览

本页唯一研究、采购与交易判断对象为**杭州飞致云信息科技有限公司**；飞致云（FIT2CLOUD）是该法人官网所用的当前品牌。可见产品与商业线索表明，公司更接近企业混合云控制面、资源治理和可观测性／运维产品商：CloudExplorer 提供多云、多 Kubernetes 集群的统一入口、权限、配额和计量能力，并公开描述基于 Prometheus 的监控告警。它适合成为可隔离、可退出的企业基础设施 PoC 候选，而不是已验证的机器人训练集群单一控制面、跨 XPU 调度平台或可直接估值的整体收购标的。[来源：本页 Raw]

## 主体、品牌与资产边界

- **唯一主体：**官网页脚及其技术博客的 publisher 均写作杭州飞致云信息科技有限公司；这足以支持其与飞致云／FIT2CLOUD 当前官网品牌的映射，但不替代工商连续性、现时股权、分支关系或各产品资产承接材料。[来源：本页 Raw]
- **产品与品牌：**CloudExplorer 是官网持续展示的企业多云管理产品，并有 KA 销售线索。1Panel、JumpServer、MaxKB、DataEase、MeterSphere、Halo、Cordys、SQLBot 及历史 KubeOperator 仅按当前产品组合或历史叙事记录；不得自动归入目标法人的源代码、商标、软著、合同、收入、员工成果或可交割资产包。[来源：本页 Raw]
- **第三方关系：**Zabbix、宏时数据、海光、麒麟、腾讯 TDSQL、NVIDIA、Qwen、DeepSeek，以及官网所列客户与伙伴，分别只是联合方案、软硬件组件、案例或合作线索。没有合同、验收、付款、排他授权或共同 IP 文件时，不将它们写作目标法人的订单、供应控制或可转移资产。[来源：本页 Raw]

## 正式分类

- **主分类：**[3.6 集群管理软件](../segments/3.6-集群管理软件.md)。CloudExplorer 面向公有云、私有云、超融合与容器云提供统一入口和自助交付；历史材料还描述其对多个 Kubernetes 集群的统一门户、租户、权限、配额、运营分析与计量管理。这些功能及其企业控制面的收入承载物，最贴近集群管理软件。[来源：本页 Raw]
- **正式次分类：**[3.7 监控与健康管理软件](../segments/3.7-监控与健康管理软件.md)。CloudExplorer 的 Prometheus 统一监控告警，以及官网销售的 Zabbix 信创一体机和“飞致云管理和数据可视化软件”，形成监控／告警相关产品与方案证据；Zabbix 的 IP、原厂订阅和任何第三方组件并不当然归属飞致云。[来源：本页 Raw]
- **条件性观察（非正式分类）：**[3.4 容器化软件](../segments/3.4-容器化软件.md)。历史材料出现 KubeOperator 自研叙述，官网也将 1Panel 描述为可管理容器的 Linux 运维面板；但未见 KubeOperator 的当前版本、维护、SKU、收入或生产交付，也不能从 Docker 容器管理推导出 Kubernetes 控制面能力。[来源：本页 Raw]
- **不列入：**3.5 调度与编排软件、4.1 跨厂商训推算力调度平台、4.3 推理跨 XPU 异构调度、4.4 多来源算力资源池化与控制面。公开材料未展示 GPU 拓扑、RDMA／NCCL、训练队列、检查点恢复、跨 XPU 迁移或生产基准。[来源：本页 Raw]

## 产品、商业化与交付边界

CloudExplorer 的可见定位是企业混合 IT 与多云环境下的资源接入、IaaS／PaaS 自助服务、权限、配额、成本／合规、自动化和监控。1Panel 的企业版、JumpServer 的年订阅、CloudExplorer 的 KA 销售以及 AI 一体机页面，说明其存在软件授权、支持服务和软硬一体方案等付费形态；这比开源社区热度更接近商业化线索，但仍不能说明每项 SKU 的有效价格、合同主体、安装量、续费、毛利、回款或收入归属。[来源：本页 Raw]

公司官网自述的免费用户、付费企业客户、GitHub Star、下载量、行业案例及第三方新闻中的企业用户数量，均缺少口径、去重、合同、验收和财务材料，不能互相相加或推导 ARR、增长率、订单、机器人客户覆盖或估值。Zabbix 信创一体机的“联合推出”也不等于飞致云持有 Zabbix IP、硬件供货权、排他代理或全部售后责任。[来源：本页 Raw]

## 面向人形机器人的行动判断

| 选项 | 当前建议 | 上调条件与退出边界 |
|---|---|---|
| 采购／合作 | 在隔离开发、仿真、数据预处理或非关键推理环境开展可回滚 PoC；优先测多集群导入、RBAC、配额、资产盘点、告警和数据／配置导出。 | 固定 GPU／NPU、NIC、交换机、存储、驱动、运行时与 Kubernetes 版本，实测多节点训练、推理、节点／网络故障、检查点恢复、升级回滚与日志导出；若缺 GPU、RDMA、NCCL 或作业能力，不将缺项包装为其 CMP 能力。 |
| 战略投资 | 不进入估值或定价，保留以资料室与产品验收为前提的信息期权。 | 逐轮融资协议、登记与交割、现时 cap table、按产品拆分的审计收入／续费／回款、核心 IP 与开源合规均可核验。 |
| 整体并购 | 当前不建议启动。 | 先逐项确认可转让的代码、商标、软著、合同、客户同意、员工、第三方许可证和持续售后责任；不能把品牌产品组合当作已交割资产包。 |
| 自研 | 保留跨 GPU／NPU 作业调度、拓扑／带宽感知、训练与仿真优先级、Checkpoint／数据集版本、失败诊断和推理弹性等差异化能力。 | 外部平台须能提供 API、配置、遥测与迁移出口；对模型、训练数据、生产凭据与核心控制面保持控制权。 |

## 下一步验证

1. 取得杭州主体的工商／关联方、域名法律文本、现时股权和逐轮融资交割资料，建立品牌、产品、IP、人员及客户合同的承接链。
2. 按 CloudExplorer、1Panel、JumpServer、支持服务及一体机拆分审计收入、毛利、续费、回款、前二十客户和服务成本。
3. 索取 KubeOperator 及现有产品的版本、维护、支持矩阵、SBOM、漏洞响应、开源许可证、数据处理、API／遥测导出与 SLA 材料。
4. 在相同硬件与负载下，对多集群治理、GPU／NPU Device Plugin、RDMA／NCCL、训练／推理作业、故障恢复、隔离、升级回滚和退出迁移开展受控 PoC。
