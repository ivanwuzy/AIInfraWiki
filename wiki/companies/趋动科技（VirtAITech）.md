# 趋动科技（VirtAI Tech）

> Raw: [趋动科技（VirtAI Tech）横纵分析报告](../../raw/sources/2026-08-11-virtaitech-横纵分析报告-4.md)

## Overview

趋动科技（VirtAI Tech）以 OrionX AI 算力资源池化软件为核心，公开产品还包括 Gemini AI 训练平台与趋动云入口。其可确认的技术重心是将 NVIDIA GPU 以 vGPU、远程调用、资源调度与统一治理的方式组成数据中心资源池，而不是已经得到充分验证的跨厂商 XPU 调度平台。对人形机器人公司，当前定位为私有训练、仿真和长尾推理资源效率层的受控 PoC 候选；不应作为芯片软件栈替代品、生产单一来源或直接整体并购对象。[来源：本页 Raw]

## 主体、产品与技术边界

报告以北京趋动科技有限公司为研究主体：公开白皮书的版权页把该公司与 OrionX 关联，但这不足以确认当前工商状态、实际控制人、融资后股权、IP 归属或趋动云合同承接。品牌、产品与法人之间的当前边界须以工商、章程、股东名册、软件著作权、专利、劳动与 IP 协议及合同逐项穿透。[来源：本页 Raw]

OrionX 的公开架构由 Controller、Server Service、Client Runtime 与 GUI 组成；控制面包含资源发现、元数据、vGPU 调度与 API，客户端运行时以兼容 CUDA 的方式让应用调用被分配的资源，数据面和 Kubernetes 扩展将其接入既有环境。公开材料同时描述资源切分、远程调用、跨机聚合、配额、队列、优先级、抢占、日志、监控与告警，足以支持其作为 GPU 资源池化及调度治理软件的判断。[来源：本页 Raw]

其公开可审计兼容性证据集中于 NVIDIA GPU、CUDA 与当时的训练框架版本。公司和管理层关于多厂商、国产芯片或异构算力的表述可作为产品路线与尽调方向，但尚无可审计的 XPU、驱动、通信库、框架与生产负载矩阵。因此不能将“异构”写为已经商业化的跨厂商统一控制面，也不能将跨服务器 NVIDIA GPU 池化等同于多来源算力资源池化与控制面。[来源：本页 Raw]

## 商业化与机器人行动判断

公开材料将商业线概括为面向自有 GPU 企业的软件销售、趋动云资源服务及向算力租赁伙伴的软件分成。融资稿、案例和合作名单能够提供客户、项目与生态访谈线索，但不证明合同金额、验收、续费、收入确认、毛利、现金流或当前有效合作关系。采购、投资和并购判断应分别检验软件、云服务与分成业务，不能将三者混算。[来源：本页 Raw]

- **采购／合作：** 在隔离且可回滚的训练、仿真、批处理或长尾推理环境开展 PoC，与裸金属及现有 Kubernetes 方案并行对照；验收利用率、排队、吞吐、尾延迟、训练收敛、故障恢复、网络流量、审计和单位有效 GPU 成本。实时控制与安全决策仍应采用可预测的原生硬件路径。
- **战略投资：** 仅列入战略观察；在法人—资产—合同边界、收入质量、客户留存、资本权利和多 XPU 生产能力闭环前，不以跨 XPU 平台溢价立项。
- **整体并购：** 当前不建议启动。只有私有代码、商标／著作权、人员发明、客户合同、第三方许可证和持续支持能力可核验并交割时，才评估特定资产或团队交易。
- **自研边界：** 保持机器人数据、模型、实验归因、边缘—云边界、权限与安全策略自控；可采购通用资源池化与调度能力，但避免专有运行时、数据路径或队列策略形成不可迁移锁定。

## 分类

- 主类型：[3.5 调度与编排软件](../segments/3.5-调度与编排软件.md)（高置信）。OrionX 的资源发现、vGPU 调度、申请／释放、队列、优先级、抢占及 Kubernetes 调度扩展是直接产品证据；其核心价值是把分散 GPU 按任务和策略分配。
- 次类型：[3.6 集群管理软件](../segments/3.6-集群管理软件.md)（中高置信）。全局资源池、组件拓扑、控制面高可用、GUI、日志、监控与告警构成管理能力，但商业重心仍是池化与调度。
- 不列入：4.1 跨厂商训推算力调度平台 与 4.4 多来源算力资源池化与控制面。公开资料未给出不同 XPU 的版本化兼容、统一资源语义或生产验证矩阵。[来源：本页 Raw]

## 冲突与不确定性

> **Status: Disputed**
> 公司公开材料与管理层访谈将多厂商／国产芯片支持和异构资源池化作为方向；但可审计的兼容清单主要是 NVIDIA CUDA 路径，且缺少独立性能、隔离、故障恢复与生产客户验证。因此该方向仅保留为待验证路线，不作为当前分类或交易结论的基础。[来源：本页 Raw]
