## 概览

本页研究对象仅为**北京清程极智科技有限公司**。报告将“清程极智”“Qingcheng.ai”和 qc-ai.cn 界定为品牌或站点，而非可独立承接资产、合同或收入的法人。公开产品材料指向八卦炉训练加速系统、赤兔 Chitu 推理引擎和 AI Ping 模型评测／API 调用平台；但具名付费客户、合同、验收、续费、收入、毛利和生产 SLA 均未公开核验。因此，本页将其视为国产多 XPU 训练／推理软件的采购与投资观察对象，而非已被证实的规模化软件收入或可收购资产包。

## 主体边界与正式分类

- **法定研究主体：**北京清程极智科技有限公司。官网页脚、ICP／备案信息及与[算能科技（Sophgo）](算能科技（Sophgo）.md)的合作公告均指向该主体；报告未直接取得工商档案、统一社会信用代码、完整股东名册、历次变更或资产承接文件。
- **品牌和 IP 边界：**“Qingcheng.ai”仅在本页作为英文品牌名使用，不等同于已核验的英文法定名称。thu-pacman/chitu 仓库采用 Apache-2.0，且官网称与清华联合开源；这不证明所有代码、商业支持组件、专利、员工职务成果或后续改进均归北京清程极智科技有限公司所有。
- **正式主分类：**5.5 推理及训练运行时优化（S，客户/收入待核验）。八卦炉训练加速与赤兔部署优化均基于既有框架/硬件栈，若以版本化产品和长期支持交付，属于产品化运行时优化；现有材料尚未证明其已达到独立框架或稳定商业收入门槛。
- **条件性次分类：**5.2 推理框架（中等置信度）。赤兔 Chitu 具备多硬件模型执行引擎定位，但主体/IP、独立 SDK、版本矩阵、客户和生产 SLA 仍待核验。
- **不列入 5.1：**八卦炉目前是训练加速系统，不是对标 PyTorch 的通用训练框架。
- **不设正式 4.1 次类：**多芯片适配、算子／计算图／内存优化并不等于跨厂商资源编排、统一调度或多来源算力资源池化与控制面产品。4.1 跨厂商训推算力调度平台仅作观察，不进入正式分类。
- **排除边界：**不归入芯片硬件、2.1 加速计算平台（CUDA-like）、数据服务或模型类型。开源代码、生态致谢、芯片合作和模型 API 均不足以改变上述边界。

## 产品与技术状态

- **赤兔 Chitu：**报告记录 GitHub 在 2025-03-14 发布 v0.1.0，其后逐步披露 DeepSeek-R1 671B、FP8→BF16、FP4 在线转换、昇腾 910B、Qwen3、GLM-4.5 MoE，以及对昇腾、NVIDIA、沐曦、海光和摩尔线程的适配；2026-07 的 v0.6.0 声称支持多节点、多实例和 Prefill／Decode 分离。这些是公开代码／产品演进线索，不能替代版本锁定的第三方正确性、吞吐、精度、可用性或商业部署验证。
- **八卦炉：**官网称其为“大模型训练加速系统”，面向 GPU 集群预训练、国产集群适配和并行方案。报告保留了“平均性能提升30%”“部分算子提升300%”“分布式通信效率提升50%”等厂商口径，但缺少基线、模型、集群规模、客户名称和独立报告，故不得将其作为实际 TCO、性能排名或验收指标。
- **AI Ping：**公开定位为模型服务评测与 API 调用平台。报告没有发现客户量、流量、付费转化、留存、毛利、部署规模或服务等级协议；因此不把它写成已被验证的模型服务平台收入。

## 商业关系、融资与证据边界

- 算能在 2026-01-26 公告称双方于 1 月 7 日签约：以芯片和 SophNet 为 AI Ping 提供算力，并围绕赤兔做算子、计算图、内存调度和部署工具链联合优化。这可以证明公开签约与联合优化意图，不能证明采购金额、排他权、客户订单、性能验收、收入分成或生产 SLA。
- 赤兔 README 对华为、沐曦、海光、燧原、智谱、中国电信和并行科技等的致谢，以及多硬件适配，均只保留为生态或技术协作线索；不得迁入这些主体的订单、收入、IP、人员或可交易资产。
- 2025-07-14 经济观察网经新浪转载报道“过亿元融资”，并称距上一轮“过亿元融资”不足半年，所列跟投方包括上海市属国有创投平台、联想创投、并行科技和奇绩创坛。该报道为融资线索，不公开完整投资方名称、轮次、投后估值、股份比例或资金到账；“首轮数千万元”“A++轮”“累计数亿元”等二手摘要相互不一致，不能累计为融资总额，更不能推导收入、现金余额或估值。

## 商业化反证与关键未知

公开材料未给出具名付费客户、合同、验收单、续费、审计财务、付费 API 使用量、生产 SLA 或机器人项目证据。开源仓库和产品页面能够证明可获取的技术与产品叙事，但不能证明代码的完整商业权属、持续维护能力、跨 XPU 性能一致性或客户复购。报告也未获得机器人 VLA／WAM 专项 benchmark、端侧功耗、实时性或供应连续性证据。

## 面向人形机器人的行动建议

| 动作 | 当前判断 | 触发条件 |
|---|---|---|
| 采购／合作 | 小额、可退出的 PoC 优先；在昇腾、沐曦、海光与 NVIDIA 上以同一 VLA／VLM 负载测试赤兔。 | 在固定版本、模型、并发和精度条件下验收 TTFT、吞吐、功耗、P99 延迟、故障恢复及迁移工时；合同明确代码、数据、SLA、维护年限与退出机制。 |
| 投资 | 仅作里程碑式少数股权观察。 | 取得 cap table、融资交割、客户合同、收入／毛利、开源治理、代码权属和 runway 证据；至少两家付费客户及可复现 benchmark 后再评估追加。 |
| 并购 | 暂不建议。 | 主体与 IP、核心团队绑定、商业支持代码、收入质量和多后端维护成本均完成穿透，且与机器人工作负载的协同可量化后，才进入交易结构讨论。 |
| 自研 | 不自研通用推理引擎；保留上层编排、评测、任务调度和安全能力的自研空间。 | 仅当外部引擎无法满足机器人专用实时性、数据边界或长期可维护性，并且自研成本／团队／供应连续性测算成立时再启动。 |
