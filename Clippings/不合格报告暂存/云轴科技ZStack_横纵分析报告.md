# 上海云轴科技股份有限公司 横纵分析报告

> 研究对象：上海云轴科技股份有限公司（官网品牌：云轴科技 ZStack）  
> 研究类型：公司横纵研究｜研究截止日：2026-08-09  
> 建议主分类：**3.6 集群管理软件**；已商业化副分类：**3.4 容器化软件**；条件性观察：**3.5 调度与编排软件、3.7 监控与健康管理软件**。  
> 研究目的：为人形机器人公司的训练、仿真、数据与推理基础设施评估采购、合作、投资、并购及自研边界。

## 结论先行

上海云轴科技股份有限公司是一家面向企业私有云、虚拟化、容器、存储、异构 AI 资源管理及运维的基础软件供应商。公开材料可以确认其网站由该法人署名、2015 年即有 ZStack 0.6 原型、当前有 ZCF/ZVF/AIOS/Zaku/SDS/CMP 等可见产品目录，并持续通过渠道交付和兼容认证构建商业化网络。[S1][S2][S3]

它对机器人公司的价值不在 GPU 或网络硬件，更接近“把自有服务器、GPU、虚机、Kubernetes 与租户/计量/运维入口组织起来”的控制平面候选。AIOS 对异构算力精分、跨多集群调度、训推与观测提出了较完整的产品主张；Zaku 则将 Kubernetes 与既有 IaaS/物理机衔接。[S2] 但这些多数来自公司产品页，缺少可复现实验、客户部署规模、标准 SKU/订阅价格、生产 SLA、GPU/NIC/交换机支持矩阵、培训作业成功率以及第三方基准。故它可进入**受控 PoC 与专业服务合作池**，不应以“全栈 AI Infra”口号直接进入生产单一来源采购或以平台宣传推导并购估值。

截至截止日，融资轮次、部分投资方和“阿里云战略控股”均仅见公司时间线表述；交割、金额、估值、持股比例、董事席位、控制权、资金到账，以及对应上海主体的资产与合同归属，未获公开原始交易文件闭环。[S1] 因而投资与并购结论是：**先做主体—股权—IP—合同—员工穿透，暂不报估值、不签控股收购意向；可保留小额、带数据室和技术验收条件的战略接触期权。**

### 2. 产业链分类判断

建议主分类为 **3.6 集群管理软件**：官网可见产品横跨虚机、裸金属、容器、存储、网络、租户、配额和运维，AIOS 进一步自述覆盖多集群、多租户、跨智算中心的资源与运营控制面。[S2] 它的当前可见收入承载物更像企业基础设施软件与交付服务，而不是芯片、模型、数据或单点 GPU 调度器。

已商业化副分类为 **3.4 容器化软件**，依据是 Zaku 已有独立产品页、Kubernetes 定位、IaaS 扩展/独立容器云两种形态、HA 与版本升级主张。[S2] **3.5 调度与编排软件**、**3.7 监控与健康管理软件**均只能条件性标注：AIOS 页面确实称有异构资源统一动态调度、实时监控和故障自愈，但缺少版本化功能清单、可复现工作负载和生产客户证明。[S2]

## 二、纵向：从 IaaS 原型到“AI 全栈”叙事

### 1. 2015–2018：以自研 IaaS 原型进入私有云市场

官网时间线将 2015 定为公司成立和 ZStack 0.6 发布年，2016 发布 ZStack Cloud v1.0，并在 2017、2018 分别记录 A、B 轮融资及阿里云、深创投的领投主张。[S1] 这是一条从轻量云平台切入企业 IaaS 的路径：其网站将今天的产品覆盖概括为私有云、虚拟化、超融合、云原生、存储与 AIOS，而非从 GPU、AI 芯片或模型公司起步。[S1]

这段历史能解释当前技术组合：先管理计算、存储、网络和租户，再将容器、多云与 AI 叠加到既有资源底座上。它也留下一个关键反面约束：公开时间线没有披露创始团队逐人履历、早期客户、首个生产集群、代码所有权或 A/B 轮交易文件。不能从“来自硅谷、英特尔、微软、思科、IBM、阿里巴巴等精英人才”的群体性宣传推出任一员工的履历、创始动机或 IP 形成过程。[S1]

### 2. 2019–2021：扩展成云管理、超融合与容器产品组合

2019 年官网记录 CMP 多云管理平台发布；2020 年记录“信创云平台支持一云六芯”、与阿里云发布新裸金属；2021 年记录 ZStack Cloud v4.0、ZStack Cube 超融合、Zaku 容器云的发布，并称中国电信进行了战略投资。[S1]

这不是单纯堆 SKU。CMP 面向异构资源纳管，Zaku 试图让既有虚机/物理机用户渐进接入 Kubernetes，Cube 则将软件与超融合交付组合在一起。现行 CMP 页面声称可纳管 ZStack、VMware、阿里云、华为云、天翼云、移动云、AWS 等 20+ 主流云平台，并能与 CMDB、监控、堡垒机对接；这说明该公司的战略问题已转为“在异构环境保留统一入口”，而非只销售一套单云 IaaS。[S2]

但“发布”不等于“交付”。当前公开页没有给出 CMP 的实际纳管数量、接入 API 覆盖、失败/回滚能力、跨云成本数据或客户合同；也没有给出 Zaku 的 Kubernetes 版本支持期限和漏洞修复 SLA。对机器人公司，这些正是把开发环境从 demo 推到连续训推的关键差别。

### 3. 2022–2023：从基础云扩展到信创与虚拟化替换机会

官网记录 2022 年 ZStack Edge 云原生超融合发布、国家级专精特新“小巨人”、参与云计算标准以及“600+ 合作伙伴”；2023 年记录 ZSphere 虚拟化与 Cube 信创超融合发布，并称有国鑫创投、君联资本领投的 C 轮融资。[S1]

这阶段的商业逻辑是，在国产化/VMware 替代的基础设施改造中，同时出售软件、集成方案、迁移和长期运维。ZVF 页面在产品目录中直接定位为“替代 VMware 的企业级虚拟化基础设施平台”。[S2] 这使 ZStack 可能成为已有虚机资产的迁移工具与云管理候选，而不是机器人训练框架的天然替换品。

公开融资资料的限制在这一段格外重要：公司时间线不披露 C 轮金额、投后估值、交割日、股权比例或 C 轮是否由上海法人承接。报告仅可写“官网记载 C 轮及领投方”，不得写成已审计融资事实或将多轮金额累计。

### 4. 2024–2026：AIOS 把资源管理延长到 GPU、模型与运营

2024 年时间线记录 AIOS 智塔发布；2025 年记录 DeepSeek V3/R1/Janus Pro 支持和多种 CPU/GPU 适配；2026 年记录“阿里云战略控股 ZStack”。[S1] AIOS 的公开架构是算力层、模型层、运营层：裸金属/虚机/容器多引擎，异构算力统一管理与动态调度，模型全生命周期管理，以及多智算中心、多集群、多租户的运营、计费、容错和自服务能力。[S2]

这一演进的优势，是可以将已有私有云用户的 CPU、GPU、容器和数据中心运维整合进一处，而不是强迫用户先换掉所有 IaaS。Zaku 也将这种“平滑演进”写入产品形态：可在 ZStack Cloud 上扩展容器能力，或作为独立容器云复用既有虚机/物理机。[S2]

它的负担也正来自路径依赖。虚拟化/私有云平台擅长资源门户、租户、配额、镜像、虚机和合规运维；大规模训练则还需严苛的 GPU 拓扑感知、collective 通信、队列公平性、故障域、数据管线、容器镜像供应、作业可复现、网络拥塞与低抖动。官网的“GPU透传可达95%物理性能”“1% 量化管理”“数百种大模型”“跨多集群全域调度”等，尚未附同模型、同 GPU/NIC、同网络、同规模下的可复现基线。[S2] 因此应把 AIOS 定位为**已发布且可 PoC 的企业 AI 控制平面**，不定位为已被独立验证的大规模机器人训练调度事实。

## 四、横向：云、容器、调度、集群与监控的当下位置

横向比较采用“可替换的控制面层次”而非把所有产品说成同一种云。ZStack 的强项是把 IaaS、虚拟化、容器、存储、多云纳管和 AI 运营包装为一套企业交付平台；代价是其每个深层能力都需要按版本、硬件和负载拆开验收。

| 层次 | ZStack 的公开定位 | 代表替代路线 | 决策含义 |
|---|---|---|---|
| 云/IaaS 与虚拟化 | ZCF/ZVF，私有云、虚拟化和 VMware 替代；AIOS 可由云平台升级 | VMware/VCF、OpenStack、Nutanix 等企业虚拟化/私有云路线 | 对已有 VM、国产化适配、租户和合规项目，ZStack 可与“重建 OpenStack”或“延续 VMware”比较；机器人训练并不应仅按虚拟化功能选型 |
| 容器 | Zaku 为 Kubernetes 容器云，可复用 IaaS 或独立部署，主张 GPU 显存切分 | 上游 Kubernetes；Rancher/OpenShift 等企业容器平台 | Zaku 适合考察从 VM 到容器的渐进迁移；GPU 切分、版本升级、CNI/CSI、镜像安全与多集群治理需实测 |
| 调度 | AIOS 自述异构资源精分、统一动态调度、跨多智算中心/集群调度；CMP 做资源编排 | Kubernetes Scheduler/Volcano、Slurm、NVIDIA Run:ai 等专用资源/作业调度路线 | ZStack 可能做统一入口；训练队列、gang scheduling、拓扑/网络感知、抢占、公平性和训练作业恢复应与专用调度器同题测试 |
| 集群管理 | 虚机、裸机、容器、多租户、配额、存储和网络被整合进控制面 | OpenStack、Kubernetes 平台、HPC 集群管理栈 | 这是 ZStack 最贴近主分类的层。优点是企业运维表面统一，风险是对大规模 GPU 集群的单一管理面和升级路径未公开验证 |
| 监控/健康 | AIOS 自述实时资源监控、故障自愈；CMP 提及与监控对接 | Prometheus/Grafana、OpenTelemetry 及基础设施厂商告警体系 | ZStack 适合作为汇总门户候选；不应取代原始指标、日志、trace 或独立告警链，尤其不得用“自愈”替代失效演练 |

### 1. 对比的技术底座与边界

OpenStack 的公开文档将自己定义为由多种互补服务组成的开源 IaaS，各服务以 API 集成，并明确其安装指南的最小示例不是生产架构。[S4] 因此“OpenStack 更开源”不自动等于更易运维：企业会在发行版、升级、外围集成和支持上承担集成成本。ZStack 的可辨别机会就在将这一层打包，并把客户的 VM/存储/网络和服务流程放到同一入口；但其当前代码、插件、兼容补丁、CVE 响应和商业支持边界未公开到足以横向证明质量。

Kubernetes Scheduler 的本职是为 Pod 挑选节点，而 Slurm 明确同时做资源分配、任务启动/监控及待执行队列仲裁。[S4] 这提醒一个常被混淆的点：AIOS 的“跨集群/异构调度”即便可用，也未自动证明其在高密度 GPU 训练上替代 Kubernetes 生态的调度扩展或 HPC 的队列机制。对于机器人 VLA/世界模型训练，须实测分布式训练作业、断点恢复、数据局部性和网络拓扑，而不是只看资源切分页。

Prometheus 的公开定义是开源监控告警工具箱，核心服务器拉取和存储时序数据，并通过 exporters 和 Alertmanager 扩展；其资料同时强调其不适合要求 100% 精确的按请求计费。[S4] ZStack 可以把基础设施可观测性汇总成运维门户，但无论产品页如何表述，都不宜把基础平台的监控能力等同于精确的 GPU 成本核算、模型质量评估、数据血缘或安全审计。

### 2. 横向优势、短板与生态位

**可验证优势。** 一是产品面宽：IaaS/虚拟化、容器、SDS、CMP、AIOS 和渠道服务在同一官网持续呈现。[S1][S2] 二是渐进迁移：Zaku 的 IaaS+ 形态可减少既有 VM 用户“全盘重建”的组织阻力。[S2] 三是国内软硬件适配和生态意图：官网宣称多芯适配，且芯展速 V5.0 互认证点名上海主体。[S1][S3]

**主要短板。** 其性能、调度、监控和自愈的强主张多为单方页面描述；没有足以与专用 GPU 调度、Kubernetes 发行版、OpenStack 商业发行版或成熟虚拟化栈对照的公开协议。没有公示的订阅指标与客户回款，也使得软件的粘性、服务毛利和续约质量无法按投资逻辑评估。

**生态位。** 它不应被当作 GPU/NIC/存储芯片供应商，也不应被预设为大模型训练框架。更合理的位置是中国企业的“多形态基础设施控制面 + 私有化交付/运维”候选。对于已有传统私有云、VM、国产软硬件和合规运维约束的公司，它可能有更低的过渡成本；对于追求极大规模、极低通信抖动、主线 NVIDIA 生态或按需云资源弹性的训练场景，专用 GPU/网络/作业调度栈仍是基准，ZStack 需要证明能以开放接口和可回退方式共存。

## 七、横纵交汇与三个剧本

历史路径决定了 ZStack 的当下不是从零构造 AI 训练系统，而是把一个先服务企业 IaaS、虚拟化与信创项目的控制面向 GPU、模型和运营延伸。这个起点提供了客户现场、私有化交付、租户、权限、计费、存储和升级的经验；也使其必须证明 AI 资源管理不是旧云平台上的营销插件。AIOS 的产品叙事越强调“从云平台无缝升级”，越应接受端到端训练作业的测试，而不是只做 GPU 可见性验证。[S2]

## 八、面向人形机器人公司的建议

### 1. 采购：受控 PoC，可选第二来源，不作生产单一来源

建议用 Zaku/AIOS 做一个封闭测试域：同时放入 NVIDIA GPU 与一类国产 GPU、Kubernetes 作业、1 个虚机遗留服务和 1 个多节点训练任务。验收指标应是 GPU 利用率、训练 JCT、失败重试率、P99 作业排队时间、跨租户隔离、节点/网络故障恢复、升级/回滚、Prometheus 原始指标可导出性和 TCO；不得只验收门户可登录或 GPU 可见。合同应要求无锁定的数据/配置/API 导出、软件版本支持矩阵、漏洞响应、二线支持和退出迁移条款。

### 2. 合作：优先“接口 + 验证”而不是泛化的联合营销

可讨论三项具体合作：

- 将 Zaku/AIOS 接入机器人公司的 Kubernetes、Slurm/作业系统、Prometheus/Grafana、CMDB 和模型注册表；明确谁是调度真源、谁负责告警和谁承担 SLO。
- 以公司自报的分布式协同调度为待证假设，联合做多集群训练、仿真数据处理和推理服务弹性测试；测试数据与脚本归己方保存。
- 在分布式存储上，把芯展速兼容认证视为一条候选 SSD 组合，不将它延伸为供应链绑定；单独完成服务器、SSD、网络、备份和 RMA 验证。[S3]

### 3. 投资：暂缓定价，先获取可审计材料

投资前必须完成：上海主体及所有资产持有实体的股权穿透；每轮融资与阿里云战略控股的签约/交割；商业版、开源版和第三方代码的 IP 边界；前十大客户、订单、验收、回款和续费；AIOS/Zaku 的独立收入、毛利、服务成本；关键员工留任；安全事件、许可证义务和债务/担保。未完成前不把官网“5000+ 客户”“数亿元投资”折算成估值模型输入。[S1]

### 4. 并购：当前不建议整体并购，只保留资产型机会

整体并购要求能同时取得代码、商标、客户合同、员工、运维责任、融资权利和关联主体资产。当前材料只能确认官网署名和产品宣传，无法确认它们是否集中于上海云轴科技股份有限公司。故建议暂停整体控股并购；若未来出现可核验的出售机会，可评估**限定资产包**：AIOS/Zaku 某一可独立部署模块、支持团队、客户迁移权或特定行业渠道，并以源码 escrow、IP 赔偿、客户同意和员工留任为交割条件。

### 5. 自研：保留核心调度与可观测控制权

机器人公司不需要自研通用 IaaS、虚拟化或完整 Kubernetes 发行版；这些可采购/合作。应自研或掌握接口控制权的，是与机器人工作负载直接相关的层：GPU/网络拓扑感知训练队列、仿真/真实数据版本与数据血缘、训练—评估—部署闭环、跨训练场/实验室容量策略、模型质量与安全审计、以及供应商退出时的配置/指标/作业迁移。ZStack 可成为底层资源入口之一，不能成为这些核心控制逻辑的唯一承载体。
