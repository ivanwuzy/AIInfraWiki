# 清程极智（北京清程极智科技有限公司）横纵分析报告
> 研究截止日：2026-08-09｜报告日期：2026-08-09｜对象类型：AI基础设施软件公司

## 一、执行摘要

清程极智的唯一研究主体是**北京清程极智科技有限公司**。官网页脚、ICP/备案信息和算能合作公告均指向该法人；“清程极智”“Qingcheng.ai”“qc-ai.cn”是品牌/站点，不应另立法人。公开证据支持其已商业化或公开交付三条产品线：八卦炉（训练加速软件栈）、赤兔 Chitu（多硬件大模型推理引擎）、AI Ping（模型评测与 API 调用平台）。[Raw：主体与产品证据](2026-08-09-清程极智_公开资料摘录.md) 主分类建议保留 **5.1 训练框架、5.2 推理框架**，副分类 **4.1 跨厂商训推算力调度平台（观察）**。目前没有足够证据证明其是独立的多厂商算力交易/调度平台，也没有证据支持将其归入芯片、数据服务或模型公司。

我的判断是：清程极智最有价值的资产不是某个单点 benchmark，而是“国产芯片适配—算子/图/内存优化—模型服务入口”形成的迁移经验和软件交付关系。对人形机器人公司，宜先采购/合作做异构推理 PoC，再以里程碑投资；并购、自研暂不成立。原因是收入、客户复购、代码所有权、团队稳定性和生产 SLA 尚未公开核验。

## 三、纵向分析：从训练提效到推理入口

### 3.1 萌芽期：清华系统软件背景（2023—2024）

官网版权显示站点自2023年起运营。公开二手报道将创始团队描述为清华计算机系博士，CEO为汤雄超；这些报道不是工商或公司公告，团队履历仍应在尽调中以简历和股权文件复核。公司切入点并非再造芯片，而是把底层 GPU/NPU 与上层模型训练、推理连接起来。这个选择回应了国产算力“硬件可买、软件难用”的结构性痛点：芯片型号多、框架后端不一致、低精度算子和分布式通信缺口导致利用率低。

### 3.2 训练加速阶段：八卦炉（2024—2025上半年）

八卦炉页面将产品定义为“大模型训练加速系统”，强调 GPU 集群预训练、国产集群适配和并行方案。页面披露某国产 A512 集群平均性能提升30%、部分算子提升300%、分布式通信效率提升50%，并出现“拓展到10万台服务器、百万亿参数”路线描述。[原始页](https://www.qc-ai.cn/products/bagualu) 没有公开基线、模型、集群规模、客户名称或第三方报告，因此这些数字只能说明公司主张的技术方向，不能直接转成采购 ROI。

这一阶段的关键决策是做“跨硬件软件工程”而非绑定单一芯片。优点是能在国产替代窗口中积累多后端经验；代价是每个后端都要维护编译器、算子、通信和故障处理，研发资源被碎片化。

### 3.3 推理产品化阶段：赤兔开源（2025）

赤兔 GitHub README记录了可复核的演进：2025-03-14 v0.1.0支持 DeepSeek-R1 671B 与 FP8→BF16；2025-04-29 v0.3.0加入 FP4 在线转 FP8/BF16；2025-06支持昇腾910B和 Qwen3；2025-07支持 GLM-4.5 MoE；2025-08适配昇腾、NVIDIA、沐曦、海光；2026-02适配摩尔线程；2026-07 v0.6.0支持多节点、多实例和 Prefill/Decode 分离。[GitHub](https://github.com/thu-pacman/chitu)

赤兔的历史价值在于把“国产卡能跑”推进到“同一 API、同一部署方式、不同 XPU 可迁移”。Apache-2.0 开源降低试用门槛，也把社区 issue、硬件适配和第三方贡献引入产品迭代；但开源并不自动形成可持续收入，专业服务、商业插件和托管平台的收费边界尚未公开。

### 3.4 融资与平台化叙事（2025）

2025-07-14新浪转载经济观察网报道公司“再获过亿元融资”，距上一轮“过亿元融资”不足半年；某知名产业方领投，上海市属国有创投平台、联想创投、并行科技、奇绩创坛跟投。[Raw：融资口径与原文链接](2026-08-09-清程极智_公开资料摘录.md) [来源](https://finance.sina.com.cn/roll/2025-07-14/doc-inffmtum6475987.shtml) 这至少证明产业资本愿意押注其国产算力软件定位，但金额是“过亿元”口径，未披露轮次、投后估值、股权比例和资金到账。微信检索中的“首轮数千万元”“A++轮”“累计数亿元”来自二手摘要且互有不一致，保留为线索，不纳入确定融资累计。

### 3.5 AI Ping 与软硬协同（2026）

官网将 AI Ping 定位为模型服务评测与 API 调用平台；算能在2026-01-26公告称双方于1月7日签约，算能提供 SophNet 云算力，清程以 AI Ping、赤兔参与算子、计算图、内存调度及部署工具链联合优化。[Raw：算能合作证据](2026-08-09-清程极智_公开资料摘录.md) [公告](https://www.sophgo.com/post/492.html) 这显示公司正从“工具交付”向“模型服务入口”上移，但公告没有订单金额、客户量、SLA、性能验收或收入分成。平台化是方向，不是已验证的规模化商业结果。

## 五、横向分析：清程极智活在什么位置

### 5.1 代表竞品一：vLLM

vLLM 是开放社区主导的通用 LLM serving 引擎，生态、文档和模型覆盖广，常被云厂商作为默认后端。其优势是开发者规模和快速吸收新模型；短板是对特定国产 NPU 的深度优化、现场部署和供应商级 SLA 需要额外整合。清程用“多国产芯片 + FP4/FP8 + 交付服务”切入，避开与 vLLM 的纯社区规模竞争。

### 5.2 代表竞品二：SGLang/TensorRT-LLM

SGLang 以高性能图编译、结构化生成和大规模服务见长；TensorRT-LLM 依托 NVIDIA CUDA、TensorRT 和硬件协同，性能上限高但绑定 NVIDIA。清程赤兔的差异是跨厂商后端和国产硬件落地，代价是每个后端的维护深度与性能一致性难以同时达到 NVIDIA 原生栈水平。

### 5.3 代表竞品三：华为 CANN/MindIE 与芯片厂商自有栈

CANN/MindIE 的优势是昇腾硬件、编译器、算子库和售后体系一体化；算能 SophNet 也在推进“芯片+云算力+模型服务”。清程不拥有芯片，因而可被视为中立适配层，但中立性取决于其是否持续支持多家芯片并避免单一客户锁定。算能合作公告证明联合优化意图，不证明清程获得排他权或大额订单。

### 5.4 代表竞品四：云厂商/模型服务平台

火山引擎、阿里云百炼、百度千帆等把 API、计费、监控和模型托管打包，客户购买的是“可用服务”而非引擎。AI Ping 若要竞争，必须证明跨云/私有化部署的成本、延迟、合规和模型覆盖优势；单纯 API 聚合很容易被云厂商价格和流量优势压制。

### 5.5 横向结论

赛道不是一家独大，而是“硬件原生栈—开源通用引擎—中立适配/交付商—云服务平台”四层并存。清程位于中立适配/交付层，优势来自国产多芯片经验和低精度推理工程，短板是品牌规模、收入透明度、长期维护能力和对上游芯片路线的依赖。其真正护城河要由可复现实测、客户续费和跨代迁移成本证明。

## 八、冲突与未确认事项

1. **融资累计冲突**：媒体摘要从“首轮数千万元”到“累计数亿元”不一；以2025-07“过亿元”单轮为唯一B级事实，累计额留空。
2. **性能冲突**：官网+30%、+300%、+50%与赤兔“1.5x/2x/14.45倍”等均缺统一测试条件；不能横向排名。
3. **主体/IP**：需核验北京法人股东、清华资产关系、`thu-pacman/chitu`仓库贡献者雇佣关系、商业支持代码和专利归属。
4. **收入/客户**：未见审计财务、合同、续费率、部署节点、毛利；AI Ping 的流量与付费转化未知。
5. **机器人适配**：尚无机器人客户、VLA/WAM 专项 benchmark、端侧功耗和实时性证据。

## 九、横纵交汇与三剧本

历史上“先做跨国产卡训练，再做推理引擎，最后上移到 AI Ping”的路径解释了清程今天的中立适配位置：早期多后端积累换来迁移能力，开源赤兔扩大了触达面，融资和算能合作则尝试把工程能力变成平台收入。相同路径也制造包袱——硬件碎片化会吞噬维护资源，开源用户增长未必转化为高毛利合同，平台上移又会与云厂商正面竞争。

**最可能剧本（基准）**：清程成为国产算力项目中的专业推理/训练优化供应商，以赤兔开源获客、商业支持和一体机交付变现；收入依赖项目制，跨厂商覆盖有限。触发信号是连续两季具名客户复购、公开版本 SLA 和第三方 benchmark。

**最危险剧本**：芯片厂商把适配能力内生到 CANN、SophNet 等原生栈，云厂商压低 API 价格；清程被夹在中间，融资只能维持研发，开源分叉而商业收入不足。触发信号是主要后端停止更新、核心维护者流失、融资间隔拉长且无客户公告。

**最乐观剧本**：赤兔成为国产多 XPU 的事实标准，AI Ping 以可审计路由、成本和合规服务切入私有化推理，八卦炉在机器人 VLA 训练集群形成稳定订单。触发前提是代码/IP清晰、跨芯片性能接近原生栈、至少两家机器人或工业客户量产部署，并能披露单位 token 成本和 SLA。

## 十、对人形机器人公司的行动建议

|选项|建议|理由与门槛|
|---|---|---|
|采购|**小额采购/PoC**：用赤兔在昇腾、沐曦、海光及 NVIDIA 上跑同一 VLA/VLM 工作负载|验收 TTFT、吞吐、功耗、故障恢复、模型精度和迁移工时；不以宣传倍数验收|
|合作|**优先合作**：联合做机器人视觉语言动作模型推理、量化和 PD 分离|把算能合作模式复制到机器人场景；合同明确代码、数据、SLA、维护年限与退出机制|
|投资|**里程碑式少数股权观察**|先取得 cap table、客户合同、收入/毛利、开源治理和 runway；以两家付费客户及可复现 benchmark 为追加触发条件|
|并购|**暂不并购**|主体/IP/核心团队绑定和收入质量未验证；并购会承接多后端维护负担|
|自研|**不自研通用推理引擎，保留上层编排与评测能力自研**|通用后端维护不构成机器人差异化；自研数据、模型评测、任务调度和安全层更贴近产品壁垒|

## 十一、下一步验证清单

1. 调取国家企业信用信息公示系统及股东名册，确认法人、注册资本、股东和历次变更。
2. 索取三轮融资交割文件、投后估值、到账证明；逐项标注“约/近/过/未披露”。
3. 对赤兔 GitHub 固定 commit 做 NVIDIA/昇腾/沐曦/海光实测，公开模型、batch、并发、精度、功耗和版本。
4. 抽样核验至少三份客户合同/验收单，区分适配、试点、付费部署和续费。
5. 对机器人 VLA 任务做端到端 P99 延迟、故障恢复、量化精度和供应连续性测试。

## 十二、分类结论

主分类：**5.1 训练框架、5.2 推理框架**。副分类：**4.1 跨厂商训推算力调度平台（观察，待证明统一调度、资源编排与多厂商算力池产品化）**。[Raw：产品与合作边界](2026-08-09-清程极智_公开资料摘录.md) 不归入 1 芯片硬件、7 数据服务或 6 模型类型。该分类仅描述已公开产品与价值承载，不代表收入规模或技术性能已被第三方验证。
