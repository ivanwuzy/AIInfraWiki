# 北京共绩科技有限公司（共绩算力／算了么）横纵分析报告

> 研究截止日：2026-08-09｜研究类型：单公司横纵研究｜唯一研究主体：**北京共绩科技有限公司**  
> 研究范围：公开可访问的 `gongjiyun.com`、`suanli.cn` 服务入口及明确指向该法人的服务协议；不把品牌、第三方代码、客户案例、地域平台或未披露关联主体的能力自动并入标的。

## 结论先行

**共绩已经有一个可以直接签约和调用的 GPU 云服务入口，但尚不能被写成“已验证的跨厂商训练控制面”。** 官网页脚及服务协议直接把 `gongjiyun.com` 的产品与服务绑定至**北京共绩科技有限公司**；协议中的裸金属条款又写明平台“整合多家优质供应商的算力资源”。这两条证据足以支持：该法人公开运营着将多来源算力、容器化实例、批处理作业、大模型 API、存储与账单放在一个服务入口的业务。[R1](2026-08-09-gongji-official-entity-history-team-and-claims.md)[R2](2026-08-09-gongji-official-products-contract-and-openapi.md)

但这里的“多家优质供应商”不是供应链穿透图，更不是训练作业可在多种 XPU 间无缝迁移的证明。公开材料没有供应商清单、资源所有权、机房合同、XPU／驱动矩阵、跨厂商通信拓扑、训练 JCT、推理 goodput／P99、故障恢复记录或第三方验收。官网列出的 46 家机房、3,989,489 次调度、99.99% 稳定性及客户降本数字都只能作为公司自述，不能进入采购 SLA、收入模型或估值模型。[R1](2026-08-09-gongji-official-entity-history-team-and-claims.md)

**分类结论：主类为 `4.4 多厂商算力池`，中等置信；`3.5 调度与编排软件`、`3.7 监控与健康管理软件`和`3.6 集群管理软件`仅作条件性观察；不纳入 `4.1 跨厂商训推算力调度平台`。** 最强证据是多供应商资源整合、GPU 动态分配、容器化云主机、Job／Spot、账单和 API；最缺的是对多厂商训练／推理控制面的生产测量。[R2](2026-08-09-gongji-official-products-contract-and-openapi.md)

对人形机器人公司的正确动作是：把共绩作为**非生产、可退出的第二／第三算力来源 PoC**，验证多卡训练、数据处理和突发推理的实际成本、队列、Spot 中断、存储和数据出域风险；不要将其作为关键训练、模型权重、机器人日志或线上推理的单一供应商。投资和整体并购均应暂缓，直到资源供给、客户收入、IP、资本结构和生产 SLO 被原始文件闭环。

## 二、纵向：从“电网式”叙事走到可调用的 GPU 云服务

### 2.1 2023：以闲置资源调度为出发点，资本与资产边界仍不透明

官网称公司成立于 2023 年，创始团队源自清华大学，并在同年获得种子轮投资。[R1](2026-08-09-gongji-official-entity-history-team-and-claims.md) 这条叙事把问题定义得很鲜明：不是再建一个单一厂商公有云，而是像电网调峰一样，把碎片化的闲置算力调度出来，通过“算力削峰填谷”“算电协同”“以算代储”提高利用率。

这一出发点解释了公司今日产品为什么同时出现云主机、裸金属、弹性服务和批处理：前台把资源做成可买的云 SKU，后台试图用需求波动消化异地、异机房和不同供给方的闲置容量。对机器人公司的价值也正来自这里——训练、数据清洗和仿真通常有明显峰谷，短期弹性资源确实可能降低等待成本。

可公开验证的历史到这里就开始稀疏。官网展示付智、许钟子珩、黄力昂、杜昔熺和徐菡蕊等团队名称／职务，但没有股权、雇佣、技术成果转让、项目来源或 IP 文件。[R1](2026-08-09-gongji-official-entity-history-team-and-claims.md) 因此，“清华渊源”只能帮助理解技术和招聘来源，不能被包装成清华持股、技术授权或可收购的高校成果。

### 2.2 2024：推出“算了么”，从愿景转为产品与融资叙事

官网时间线称 2024 年推出“算了么”平台，并称获得奇绩创坛、水木创投“数千万天使轮融资”。[R1](2026-08-09-gongji-official-entity-history-team-and-claims.md) 公开搜索记录还显示一条 36Kr 标题／摘要线索：水木创投领投，奇绩创坛加码，新进创投参与，金额为“数千万元”。这些线索与官网“数千万”的粗粒度口径一致，但没有取得投资方公告、协议、工商增资或资金到账文件。[R4](2026-08-09-gongji-financing-public-search-record.md)

比融资标题更重要的是产品选择。共绩并没有仅发布一个模型 API 门户，而是逐步形成弹性部署、云主机、裸金属、Job、镜像与存储组件的组合。其商业逻辑是把相对不稳定、分散的 GPU 供给包装为开发者可部署、可批处理、可查询账单的标准化服务。这个路径让它与普通 GPU 转售商有些差异，但也把风险推到了供给侧：供应商是否有背靠背 SLA、Spot 是否会回收、跨机房数据传输与数据驻留谁承担、以及高峰期容量是否真能兑现。

### 2.3 2025—2026：区域平台与“调度次数”强化故事，合同化产品仍是最硬的证据

官网称 2025 年创立清华深研院弹性算力调度研发中心，并参与长三角、京津冀、珠三角省级算力调度平台建设；2026 年页面还列出工信部活动、IEEE 和 CEO 荣誉等内容。[R1](2026-08-09-gongji-official-entity-history-team-and-claims.md) 这些材料显示公司试图把“市场型 GPU 云”与“区域算力网络／产业基础设施”连接起来。

不过，区域平台、研发中心和荣誉都没有公开协议、验收、拨款、运营收入或知识产权归属。它们可作为尽调访问对象和业务线索，不能构成标的已经拥有政府项目收入、研究机构 IP 或长期独占资源的证据。

截至研究截止日，反而是 2026-07-02 更新的服务协议和公开 OpenAPI 更能证明真实对外产品存在：用户可以通过 Token 或 RSA API Key 管理服务、查询任务／节点／账单；Job 可做批处理，云主机是 Docker 容器，裸金属被描述为多供应商资源整合。[R2](2026-08-09-gongji-official-products-contract-and-openapi.md) 从纵向看，共绩已从抽象的“电网式算力”叙事走到可调用的计算服务；从投资角度看，它仍未完成把“服务入口”转化为“可验证供给网络与高质量收入”的证明。

## 五、五类分拆合作网络

### 5.1 投资方／股东网络

官网和搜索摘要给出奇绩创坛、水木创投、新进创投及若干后续融资线索。[R1](2026-08-09-gongji-official-entity-history-team-and-claims.md)[R4](2026-08-09-gongji-financing-public-search-record.md) 目前可确认的是公司／媒体曾这样表述；不能确认任何机构目前仍持股、投向的是哪一法人、出资是否到位、是否有董事席位、优先权、代持、回购或关联交易。投资尽调的第一份材料不应是新闻合集，而应是逐轮交易文件、验资／到账、工商变更与完整 cap table。

### 5.2 客户／订单网络

Liblib、Tripo 与鸿蒙 6 Remy 是共绩官网展示的案例对象。[R1](2026-08-09-gongji-official-entity-history-team-and-claims.md) 它们可用于提出回访问题：项目服务是云主机、弹性部署、批处理还是模型 API？合同签约／开票主体是谁？资源来自哪里？高峰期容量如何保证？是否续费？但没有这些答案前，不把上述对象列为确认客户或收入来源。

### 5.3 产业合作与供给网络

“整合多家优质供应商的算力资源”是唯一直接的供给侧主张。[R2](2026-08-09-gongji-official-products-contract-and-openapi.md) 它足以支持 4.4 的初步分类，但没有命名任何机房、云厂商、GPU 供应商、网络或存储合作方。官网所称参与区域算力平台建设也没有公开合同对手、工程范围和验收。[R1](2026-08-09-gongji-official-entity-history-team-and-claims.md) 因此供应网络目前只能写作“多来源供给的未穿透线索”，而不是一张已确认的供应链图。

### 5.4 技术／联合研发网络

OpenAPI、容器化实例、Job、缓存和存储服务说明平台有可调用接口与工程组件；但接口不证明调度算法自研，Docker／存储组件也不等于联合研发。[R2](2026-08-09-gongji-official-products-contract-and-openapi.md) 第三方 `gongjiskills` 仓库显示有 CLI／作业模板接入线索，却由个人账户维护；MoneyPrinterTurbo 的 README 自述也只是第三方适配。[R3](2026-08-09-gongji-thirdparty-github-integration.md) 本轮未找到可以归入北京法人的联合开发协议、论文、专利、官方 GitHub 组织、开源许可证链或客户侧性能基准。

### 5.5 高校／科研渊源网络

共绩官网称创始团队源自清华大学，且称设立清华深研院弹性算力调度研发中心。[R1](2026-08-09-gongji-official-entity-history-team-and-claims.md) 这可解释团队的研究与招聘背景，也可以作为走访清华深研院的线索；但未见校方公告、课题合同、技术转让、IP 许可、成果作价或人员派遣文件。因而不能把“清华渊源”写作清华持股、知识产权授权或独占技术供给。

## 六、横向：共绩真正面对的是“资源池的透明度”竞争

### 6.1 对比对象与比较边界

共绩的竞争并不只来自另一家国内 GPU 云。它同时面对 GPU marketplace、serverless 端点平台、标准 GPU 租赁平台、分布式 Agent 云，以及带有明确异构控制面主张的系统软件厂商。下面的对比只比较公开产品形态，不推断任何一方与北京共绩科技有限公司存在合作、客户或供应关系。

| 代表玩家／路径 | 公开定位 | 与共绩的重叠 | 共绩需要证明的差异 |
|---|---|---|---|
| **Vast.ai** | GPU 租赁 marketplace，含 REST API、CLI、Python SDK、Serverless endpoint 和 hosting。[R5](2026-08-09-vast-runpod-autodl-official-comparison.md) | 都要处理碎片化 GPU 供给和开发者入口。 | 共绩需要证明在供给审查、企业合同、数据驻留和资源确定性上比开放 marketplace 更可靠。 |
| **Runpod** | Serverless 端点，按实际计算时间计费，用户可配置资源与扩缩参数。[R5](2026-08-09-vast-runpod-autodl-official-comparison.md) | 都有弹性服务部署与按量使用逻辑。 | 共绩需展示端点冷启动、扩缩、故障恢复、成本与 SLO，而不只展示卡价。 |
| **AutoDL** | GPU 租赁、容器实例、迁移、镜像、API 与 7×24 服务的公开定位。[R5](2026-08-09-vast-runpod-autodl-official-comparison.md) | 云主机、镜像和容器产品形态相近。 | 共绩若以“多厂商算力池”取胜，应披露其资源弹性和调度净收益，而不是重复单机租赁。 |
| **PPIO** | GPU 容器、按需／包周期与广域节点统一接入、纳管、调度、运营的公开定位。[R6](2026-08-09-ai-infra-competitor-official-positioning.md) | 弹性 GPU 云、Token／Agent 叙事、广域资源调度。 | 共绩需证明供应商整合能够形成客户可见的容量、调度和账单优势。 |
| **硅基流动** | 模型 API、预留实例、推理加速与私有化部署。[R6](2026-08-09-ai-infra-competitor-official-positioning.md) | 大模型 API、推理服务和企业交付。 | 共绩需说明自己是更强的多源算力弹性层，还是只是在 API／实例层面与其价格竞争。 |
| **趋境科技** | 公开主张 CPU+GPU／国产与非国产异构、P/D 分离、统一纳管、软硬一体和联合运营。[R7](2026-08-09-approachingai-official-ataas-products-and-modes.md) | 都使用“Token 工厂／算力调度”语言。 | 共绩尚未公开 P/D、跨 XPU、KV Cache、任务分流和万卡运行的产品证据，不能将两者视作等价。 |

### 6.2 竞争位置：一个有服务入口的多来源资源运营候选

共绩的公开差异，是将多机房／多供应商资源、容器、Job、Spot、裸金属、存储和 API 放进一个面向开发者的入口。这个形态比仅卖单卡小时数更有机会形成运营价值：当供给地理分散、用户需求波动、且负载可中断或可迁移时，资源池可用性与调度策略会影响用户的有效完成成本。

但共绩尚未公开将这种运营能力“产品化为控制面”的关键材料。Vast.ai 的 marketplace、Runpod 的 serverless 配置、AutoDL 的容器产品、PPIO 的广域节点叙事都已经把购买对象讲得相对明确；趋境则把异构推理、P/D 与软件授权／联合运营列成独立命题。[R5](2026-08-09-vast-runpod-autodl-official-comparison.md)[R6](2026-08-09-ai-infra-competitor-official-positioning.md)[R7](2026-08-09-approachingai-official-ataas-products-and-modes.md) 共绩要避免沦为价格中介，必须证明至少三点：供给稳定性、工作负载完成效率和客户迁移／续费黏性。

## 七、证据矩阵、冲突与开放问题

证据等级：A＝目标法人直接签约／合同或监管原件；B＝目标法人官网、条款、产品页与文档；C＝可信媒体的独立原文；D＝搜索摘要、第三方仓库或研究者推断。

| 命题 | 支持证据 | 反证／限制 | 等级 | 当前处理 |
|---|---|---|---:|---|
| 北京共绩科技有限公司是公开服务运营主体 | 页脚与服务协议直接点名该法人。[R1] [R2] | 未取得工商原件和所有关联主体图。 | A/B | 接受为网站／协议服务主体。 |
| 平台聚合多家供给方资源 | 裸金属条款称整合多家优质供应商。[R2] | 无名单、合同、容量、产权、地域或转售权。 | B | 支持 4.4，但不支持 4.1。 |

| 46 家机房、3,989,489 次调度、99.99% 稳定性 | 官网当前指标。[R1] | 无时间口径、样本、审计、定义或第三方报告。 | B | 仅记录为官网自述。 |
| Liblib、Tripo、Remy 是客户且获得收益 | 官网案例卡。[R1] | 未见相对方确认、合同、金额或回款。 | B | 仅作回访线索。 |
| 团队／技术来自清华并享有相关 IP | 官网称团队源自清华、研发中心。[R1] | 无校方公告、权属、转让或许可。 | B | 只记科研渊源，交易前彻查。 |

应优先回答的开放问题是：

1. 北京法人完整的股权、关联方、IP、域名和软件权属是什么？
2. 每一类资源是自有、租赁、客户托管还是供应商转售？相应的背靠背 SLA 与转售权如何？
3. 按机房、地域、卡型和供给方划分的可售库存、利用率、Spot 回收率、故障率和队列时间是什么？
4. 训练与推理在不同供给方／卡型上的性能、网络、存储、数据留存和迁移行为怎样？
5. Liblib、Tripo、Remy 等案例的签约主体、合同期限、验收、续费、回款与相对方证言能否取得？
6. 融资历史、估值、实缴、应收、毛利、现金消耗、供应商集中度与客户集中度如何？

## 八、横纵交汇：从“电网”隐喻到交易上必须回答的物理问题

共绩的纵向逻辑很连贯：如果把 GPU 供给看成带有高峰与闲置的“电”，就自然会从调度愿景走向多机房资源接入、弹性部署、Spot 和批处理。它的机会不是与某一家 GPU 厂商比芯片，也不是与单一模型 API 比模型能力；而是让不稳定、异地、碎片化的供给在客户感知上变成可部署、可计费、可恢复的服务。

横向看，这恰好是最难靠新闻稿证明的能力。资源池价值由三类实体约束决定：供给合同是否稳定，网络／存储能否承受工作负载，以及调度是否真的减少作业完成时间和工程成本。官网的“电网式”语言、调度次数和客户案例描绘了方向，却没有把这三类物理／合同约束披露出来。

我的判断是：**共绩可能已有效运营一个面向开发者的多来源 GPU 云，但它的可投资价值尚未被证明为可复制的软件控制面。** 若利润主要来自资源套利，估值应接近云运营和供给质量；若未来能够以跨来源的队列、容错、工作负载画像与数据通路持续降低用户有效成本，才可能形成更像基础设施软件的留存与毛利。这个区分也是人形机器人公司采购与投资必须分开的原因。

### 三个剧本与触发条件

| 剧本 | 发生机制 | 应观察的材料 | 对机器人公司的动作 |
|---|---|---|---|
| **基准：多来源 GPU 云／弹性池可持续运营** | 公司以容器、Job、裸金属、Spot 和 API 服务研发／中小企业客户；资源整合带来局部成本和容量优势，但透明度仍有限。 | 逐供给方容量、连续三个月可用性、队列、Spot 中断、客户续费、实际单作业成本与数据处理记录。 | 维持第二／第三供应商 PoC，保留跨云迁移。 |
| **上行：形成可验证的异构资源运营控制面** | 供给合同、调度算法和工作负载画像形成可复制的运维与软件能力；可跨地域／供给方给出可复现实测。 | 客户合同、供应商背靠背 SLA、XPU 矩阵、训练 JCT、推理 P99、故障演练、毛利与续费。 | 在验证后扩大非敏感训练／推理采购；可考虑小额分期战略投资。 |
| **下行：资源波动、Spot 回收与数据责任吞噬价值** | 高峰供给不足、价格战、供应方回收资源、容器／存储误用或关联方责任不清导致无法承担生产负载。 | 长时间排队、服务中断、账单争议、数据丢失、客户流失、供应商集中、现金流和应收恶化。 | 停止扩大采购与投资；保持多云／自建调度和可迁移数据路径。 |

## 九、面向人形机器人公司的行动建议

### 9.1 采购：只验证实际完成作业成本

建议启动 **8—12 周、可随时退出、双／三供应商并行** 的 PoC。首批只使用脱敏数据、可公开模型或可替换模型权重，且不接入生产控制链路。应使用相同的视觉／VLA 微调、数据预处理和推理负载，与现有云或自建集群平行测试：

- 训练吞吐、收敛／精度、端到端 JCT、排队时间、失败重跑和工程人时；
- Spot 中断频率、自动重试是否保留检查点、故障恢复和容量保证；
- 存储吞吐、挂载持久性、对象存储出入流量、数据落盘与完整迁移；
- API／推理的 TTFT、TPOT、p95／p99、错误率、限流、模型版本与账单复算；
- 机房／地区、数据处理者、日志保留、删除、备份、事件响应与退出归档。

不要把官网的 99.99%、成本下降 50%+ 或页面单卡价作为 PoC 成功条件。[R1](2026-08-09-gongji-official-entity-history-team-and-claims.md)[R2](2026-08-09-gongji-official-products-contract-and-openapi.md) 成功应以我方固定工作负载、固定数据与合同化的可观测指标定义。

### 9.2 合作：用调度与资源预测做小闭环，而非交出核心数据

可探索资源预测、批作业调度策略、跨云弹性和模型服务监控的联合验证。协议需预先写清：数据、模型权重、训练日志、衍生指标和前景 IP 的归属；访问权限、地区、保留期与不出域要求；故障责任、客户支持、变更通知、开源许可证、供应商替换与退出迁移。公开协议明确云主机内部文件系统可能丢失，因而任何长期项目都需以明确的持久化、备份与恢复责任为前置条件。[R2](2026-08-09-gongji-official-products-contract-and-openapi.md)

### 9.3 投资：暂缓，设置五个硬闸门

在以下材料齐备前，不进入估值或投委会：

1. 现时 cap table、逐轮协议与资金到账、关联交易和完整控制链；
2. 多供应商资源合同、GPU／机房／网络／存储权利、背靠背 SLA 与供应集中度；
3. 按产品拆分的 GMV、净收入、毛利、应收账款、回款、客户 cohort、续费与前十大客户；
4. 调度与运维软件的 IP、开源 SBOM、关键人员、数据安全与事故记录；
5. 至少两个机器人相关工作负载在不同资源来源上的可复现基准与客户侧验收。

满足这些条件后，也应优先采用里程碑分期的小额战略投资，而非根据媒体的“近亿元”标题或品牌流量一次性定价。

### 9.4 并购与自研：不买尚未穿透的“云故事”

**整体并购不建议启动。** 当前无法判断服务器、资源合同、客户合同、数据处理责任、调度软件和 IP 是否同在北京法人，且普通 GPU 云运营的资产可转移性高度依赖供应商同意。若未来出现必须获得的能力，更可行的路径是核验后收购可独立转移的软件／调度团队或以许可方式获取特定组件。

内部不应复制一个公共 GPU marketplace；应保留并持续建设自己的 workload profiler、训练／仿真队列策略、基础设施即代码、统一可观测、基准套件、模型与数据生命周期，以及多云抽象层。这样共绩以及任何其他资源供应商都可以插拔，而不成为机器人研发节奏的单点依赖。

## 最终分类结论

**北京共绩科技有限公司：主类 `4.4 多厂商算力池`（中等置信）；`3.5 调度与编排软件`、`3.7 监控与健康管理软件`及`3.6 集群管理软件`仅条件性观察；`4.1 跨厂商训推算力调度平台`不成立。**
