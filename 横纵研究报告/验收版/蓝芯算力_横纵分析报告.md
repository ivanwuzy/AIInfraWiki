# 蓝芯算力横纵分析报告

> 研究截止日：2026-08-06｜研究对象：蓝芯算力（深圳）科技有限公司｜类型：RISC-V＋AI 智算 CPU/服务器芯片项目｜证据等级：以工商公开页、公司/合作方公告及可访问媒体原文为优先；公开证据不足的地方保留为待核验，不用宣传补齐

## 一句话定义

**蓝芯算力是一家成立时间短、公开资料仍稀疏的深圳 RISC-V＋AI 智算芯片公司；它试图以“把通用服务器 CPU、AI 加速与互联放在同一 RISC-V 平台”的路线切入国产服务器与大模型基础设施，当前应被看作一个需要核验产品、团队、融资和量产能力的早期系统芯片标的，而非已被公开订单证明的成熟 AI 加速器供应商。**公开企业信息检索结果显示其成立于 **2023 年 5 月 23 日**、法定代表人为卢山；这些工商字段应在交易前以最新登记档案复核。[企查查检索入口](https://www.qcc.com/web/search?key=%E8%93%9D%E8%8A%AF%E7%AE%97%E5%8A%9B)

## 研究边界、证据与核心判断

蓝芯算力的案例首先不是“如何比较两张加速卡”，而是“如何处置一个信息不足却可能重要的架构方向”。公开可访问材料把它置于 RISC-V＋AI 服务器 CPU/智通融合的叙事中；总表也将其备注为“RISC-V+AI服务器CPU”。但截至截止日，本报告未找到公司官网的可下载数据手册、可复现 benchmark、公开 SDK/GitHub、客户订单公告、晶圆/封测信息或披露融资条款。缺少这些并不证明项目没有产品，只证明外部投资者无法据公开信息验证。

因此，以下结论采用三层表达：**已证实**（有链接支撑）、**公司/合作方主张**（需要对方交付底层证据）和**研究者判断**（明确假设）。这里所有“未发现”均是截至 **2026 年 8 月 6 日**的公开检索结论，不等于不存在。对人形机器人公司的最稳妥动作不是排除或追捧，而是把它放入“架构观察＋P0 尽调”队列：只有当具体芯片、软件和供应链证据出现后，才能转为采购、投资或联合开发。

## 纵向分析：一条尚在展开的 RISC-V＋AI 路线

### 1. 成立背景：不是单做 NPU，而是瞄准服务器主控的重构

公开工商检索页显示，蓝芯算力（深圳）科技有限公司成立于 **2023-05-23**，所在地为深圳南山；搜索结果中展示的注册资本曾为 **20,981,593.88 元人民币**，并提示 **2026-07-17** 发生注册资本增加。由于该页面的字段会动态变化、且本报告未取得市场监管局盖章档案，金额、变更原因、实缴情况和股东比例均须再次核验。[企查查检索入口](https://www.qcc.com/web/search?key=%E8%93%9D%E8%8A%AF%E7%AE%97%E5%8A%9B) 报告只把成立日期作为较高置信度事实，不把注册资本误作融资额或可用现金。

总表给出的“RISC-V+AI服务器CPU”描述，配合公开新闻中“RISC-V＋AI 智通融合 CPU 联合创新实验室”的表述，勾勒出其路线：不是在既有 x86/Arm 主机旁添加一张外置卡，而是把 CPU、AI 加速、内存/I/O 和可能的互联需求作为一个服务器节点来处理。[中国经济周刊检索入口](https://www.ceweekly.cn/search?keyword=%E8%93%9D%E8%8A%AF%E7%AE%97%E5%8A%9B) 这条路线若能实现，吸引力来自减少异构节点的 BOM、数据搬运和软件碎片；难处则在于必须同时赢得 CPU 生态、操作系统、编译器、AI runtime、集群通信和客户运维信任。

换言之，蓝芯算力做的不是一个容易被 TOPS 定义的零件。它试图抢的是服务器“控制面＋加速面”交界处的价值。这个位置的上行空间很大：若 CPU 能直接高效编排 AI 加速、减少 PCIe/多芯片搬运，数据中心推理和数据处理可能得到更好能效；下行也很陡峭：任何一个环节——RISC-V Linux 生态、内存控制器、虚拟化、编译器、模型算子、板卡可靠性、供应——不成熟，客户就会回到 x86/Arm＋GPU/NPU 的已知组合。

### 2. 2023：天使融资传闻与“团队/产品”证据应分离

产业投资信息二次传播在 **2023 年 12 月**提到蓝芯算力获“数亿元”天使轮融资，但该条目本身是聚合信息，且本报告未取得投资方、公司或工商增资的原始公告；它只能作为追查线索，不能作为融资事实入表。[IT 桔子投融资资讯检索入口](https://www.itjuzi.com/search?query=%E8%93%9D%E8%8A%AF%E7%AE%97%E5%8A%9B) “数亿元”也没有币种、到账日期、首轮/追加、股权比例和投资主体，不能被换算为估值。

这种信息状况对早期芯片项目并不罕见，但对投资决策至关重要。芯片公司的融资不是单纯现金新闻：它决定流片次数、EDA/IP 支出、原型板、软件团队、客户 FA 和库存承压能力。若融资真实但仅为早期天使轮，其资金可支持架构与第一版验证，却未必覆盖多次流片和服务器平台商业化；若公司拥有产业方预付款、政府项目、联合实验室资源或母体支持，资金约束又会不同。公开资料不足时，正确动作是索要 bankable 的资金证明与预算，而不是用“数亿元”预设研发续航。

关于团队，工商信息将卢山列为法定代表人。[企查查检索入口](https://www.qcc.com/web/search?key=%E8%93%9D%E8%8A%AF%E7%AE%97%E5%8A%9B) 公开搜索材料没有提供足以由本报告独立验证的核心架构师名单、前雇主、RISC-V/CPU/SoC tape-out 履历、软件负责人或组织规模。任何把卢山直接等同于“创始人”、或把个别简历外推为全团队能力的说法都应避免。对 CPU 项目而言，创始人光环远不如三个可查对象重要：总架构师是否有可量产 CPU 经验、后端/DFT/验证负责人是否完整、编译器/OS 团队是否能与硬件并行工作。

### 3. 2024—2025：从概念证明走到合作叙事的关键窗口

公开资料尚未形成连续的公司新闻年表，且本报告未找到明确标注于 **2024 年或 2025 年**的首颗芯片发布公告、型号、流片节点、试产、客户验收或正式 SDK 下载。这不是“小信息缺口”，而是决定项目成熟度的主缺口。若产品尚处架构/FPGA/emulation 阶段，则应该以研发项目估值；若已首版流片或客户上板，则应以良率、PPA、bring-up、软件兼容和交付验证估值；这两种状态的估值区间及投资工具完全不同。

RISC-V 服务器路线在这一时期却有更广的外部背景。RISC-V International 将自己定位为维护开放 RISC-V 指令集标准和生态的组织，公开提供技术规范与成员生态信息。[RISC-V International](https://riscv.org/) 对蓝芯算力而言，开放 ISA 降低了 ISA 授权依赖，并可让公司把差异化投入在微架构、缓存/内存、AI 加速、互联和软件；但“开放 ISA”不等于自动拥有服务器生态。操作系统发行版、编译器、虚拟化、数据库、容器、驱动、性能分析和企业支持仍须逐项完成。

此处的反向证据来自先行者：RISC-V 服务器 CPU 即使有公开核心和开发板，也需要多年让 Linux、编译器与硬件外围成熟。算能的 SG2042 官方描述为 **64 核、2 GHz、64 MB 共享 L3** 的 RISC-V SoC，并已围绕它形成服务器产品目录。[算能 SG2042 产品目录](https://www.sophgo.com/about-us/index.html) 这说明赛道可做，也说明蓝芯算力若要主张“AI 服务器 CPU”，必须拿出比概念更强的系统与软件证据。

### 4. 2026：联想合作消息带来一个可验证的方向，但不是订单

截至截止日，公开搜索结果显示一篇 **2026 年 8 月**报道：联想与蓝芯算力在上海宣布成立“RISC-V+AI 智通融合 CPU 联合创新实验室”，报道表述为双方将探索 RISC-V＋AI 方向。[中国经济周刊相关报道检索](https://www.ceweekly.cn/search?keyword=%E8%81%94%E6%83%B3%20%E8%93%9D%E8%8A%AF%E7%AE%97%E5%8A%9B) 由于本报告未能取得双方官网完整合同文本，应将它定性为**产业/技术合作线索**，而非客户订单、联合研发已交付、量产服务器发布或联想对公司股权投资。

即使合作属实，其战略意义依然值得拆开看。联想拥有服务器、PC、边缘计算、供应链和企业客户通道；一个联合实验室能让早期芯片公司更早接受整机、BIOS/BMC、散热、电源、兼容与渠道反馈。对蓝芯算力，最稀缺的不是又一份“生态签约”，而是将实验室的验证转化成定义明确的样机：芯片型号、主板、内存、I/O、OS 镜像、AI benchmark、故障恢复、交付批次与客户验收。没有这些，合作只增加叙事，不增加可审计的技术成熟度。

### 5. 产品/架构的当前可见度：概念可以理解，规格必须留空

到 **2026-08-06**，本报告未找到蓝芯算力官方公开的芯片型号、ISA 扩展、核心数、频率、制程、缓存、内存类型/带宽、AI 精度、TOPS/TFLOPS、TDP、PCIe/CXL/以太网、片间互联、板卡/服务器 SKU 或软件版本。因而不会编造一张“产品参数表”。这与研究成熟厂商时的做法不同，但恰恰是本公司研究最有价值的结论：**公开信息不足以支持产品选型。**

假设其“RISC-V＋AI 服务器 CPU”方向成立，需回答的技术问题至少有八组：第一，RISC-V 核的 OoO 宽度、频率、缓存一致性和 NUMA 设计；第二，AI 加速单元是紧耦合矩阵引擎、向量扩展、NPU 还是外挂；第三，CPU/AI/内存是否共享地址空间；第四，内存带宽能否支撑 KV cache 和数据预处理；第五，PCIe/CXL/网络是否满足集群；第六，虚拟化与隔离如何实现；第七，编译器/runtime 怎样支持 PyTorch/ONNX/LLM；第八，芯片、主板和系统是否有供货与可靠性数据。这些问题比“是 RISC-V 还是 x86”更接近价值创造。

## 横向分析：蓝芯算力必须同时面对的五种替代路径

### 1. 算能：RISC-V 服务器先行者，说明软件/系统门槛

算能官网展示 SG2042 RISC-V 处理器及计算、存储、融合服务器和机柜集群产品。SG2042 被描述为 **64 核、2 GHz、64 MB 共享三级缓存**，并配有 RISC-V 计算服务器 SRA1-20、存储服务器 SRB1-20 等系统形态。[算能产品矩阵](https://www.sophgo.com/about-us/index.html) 它还在 TPU、视觉处理器、模组和服务器之间铺开产品线。

对蓝芯算力而言，算能是最有价值的横向参照：它说明 RISC-V 服务器不是不存在需求，但“有一颗 RISC-V CPU”距离“有可采购系统”至少还隔着板卡、BIOS/BMC、内核、存储、网络、容器、应用适配、售后与渠道。蓝芯若能将 AI 加速紧耦合进 CPU，可能比“CPU＋外置卡”减少系统复杂度；如果不能给出更好的软件和总体成本，客户会优先选择已有服务器 SKU 的方案。

开发者视角的可验证差异也很直观：算能至少公开了产品目录、GitHub 组织和工具链入口。[Sophgo GitHub](https://github.com/sophgo) 蓝芯算力截至截止日缺少相当公开的 SDK/GitHub。对于早期购买者，这不等于蓝芯软件更差，却意味着技术风险无法由外部社区分担。

### 2. 此芯科技（CIX）：Arm 智能体 CPU/SoC 的另一个融合路线

此芯科技公开定位为高性能智能计算芯片公司，产品路线以 Arm 架构 CPU/SoC、GPU/NPU 等集成为主。[此芯科技官网](https://www.cixtech.com/) 它代表蓝芯算力最贴近的“异构融合 CPU”替代：不是买一张纯 AI 卡，而是在主控 SoC 层面将通用计算、图形/AI 和 I/O 汇合。

蓝芯的差异若存在，应来自 RISC-V 的开放 ISA 与服务器 AI 工作负载，而非泛泛的“国产”。CIX/Arm 路线的优势是已有的 Arm 软件生态与设备兼容积累；蓝芯的潜在优势是更自主的 ISA 和对 AI/服务器的定制自由度。用户的真实选择会取决于 Linux 发行版、编译器、容器、驱动、内存和 SKU，而不是 ISA 的理念。蓝芯必须通过具体 benchmark 证明其融合并没有牺牲 CPU 单线程、AI 吞吐或软件可用性。

### 3. 华为鲲鹏＋昇腾：成熟的“CPU＋AI 加速”组合基线

华为公开提供鲲鹏通用计算与昇腾 AI 计算产品和开发文档。[鲲鹏官网](https://www.hikunpeng.com/) [昇腾官网](https://www.hiascend.com/) 这条路线不是单芯片融合，而是通过 CPU、NPU、系统软件和生态整合解决同样的问题：如何在国产基础设施上运行 AI 和通用服务。

对蓝芯算力的挑战是，客户已经可以采用成熟 CPU＋AI 加速器组合，不需要等待一个新架构完成所有环节。它的机会仅在于能够用较低 BOM、较少数据搬运、更好能效或更强主权可控性带来可量化增益。没有这些，融合的复杂性只是把两个供应商的风险集中到一个早期项目里。对人形机器人公司，鲲鹏＋昇腾也意味着云端/私有化推理可以与端侧平台分离，避免让早期服务器 CPU 承担不适合它的机载任务。

### 4. NVIDIA Grace/CPU＋GPU：最强的软硬协同参照物

NVIDIA 的数据中心路线把 GPU、CPU、NVLink/NVSwitch、CUDA、TensorRT、NCCL 和系统产品组成平台。[NVIDIA 数据中心](https://www.nvidia.com/en-us/data-center/) [CUDA 文档](https://docs.nvidia.com/cuda/) [NCCL 文档](https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/) 其价值不在于某颗芯片，而在于开发者和集群工程已经在同一套运行时中积累。

蓝芯若主张智通融合，应该以 NVIDIA 这类“整体体验”而非单个 TOPS 当标尺：模型从训练到部署是否少一次搬运？小批量/大批量延迟是否改善？多节点通信是否稳定？客户能否找到足够工程师维护？NVIDIA 的弱点在于供应、成本和依赖风险；这正是蓝芯可能获得战略关注的窗口。但窗口不等于护城河，只有可迁移的软件和实际交付才能把约束转成收入。

### 5. 阿里平头哥/倚天＋含光：云内部融合能力的反向压力

阿里云公开介绍倚天 710 服务器 CPU 与含光 AI 推理芯片，展示了云厂商通过自研 CPU、AI 加速和云服务进行系统优化的路径。[阿里云倚天 710](https://www.alibabacloud.com/blog/alibaba-cloud-unveils-yitian-710-server-chip_598927) [阿里云含光](https://www.alibabacloud.com/blog/alibaba-cloud-launches-hanguang-800-ai-inference-chip_596994) 它们未必是蓝芯的直接外售竞品，但代表客户能够获得的“云内优化”替代方案。

这提醒蓝芯算力：若只把融合能力留在芯片层而没有外部可用服务器、软件栈和支持体系，它可能被大型云厂商的内部平台挤压；若能把可部署的 RISC-V＋AI 节点交给私有云、边缘云和行业客户，则有机会覆盖云厂商不愿服务的长尾。两种生态位的商业模式、销售周期和资本需求截然不同，必须在产品路线图中选择，而不能同时模糊占据。

### 6. 开发者反馈与公开生态缺口

截至截止日，本报告未找到蓝芯算力官方开源组织、SDK 下载中心、公开 issue 跟踪器、框架兼容矩阵、模型 zoo、容器镜像或性能白皮书。相较于 CUDA、昇腾 CANN、算能 TPU-MLIR 等可访问入口，[CUDA](https://docs.nvidia.com/cuda/) [CANN](https://www.hiascend.com/document) [TPU-MLIR](https://github.com/sophgo/tpu-mlir) 蓝芯的开发者可验证性不足。

这不是要求每家公司都开源。商业 SDK 可以闭源，但采购方至少需要有版本策略、可复现环境、支持通道和可审查的兼容性清单。没有公开反馈，并不表示没有用户或没有服务；同样也无法据此宣称“用户认可”。本报告把它列为 P0 技术尽调项：请公司在 NDA 下提供 SDK、release notes、已支持模型、bug 统计、工单 SLO、典型客户部署拓扑与长期支持计划，并由我方独立复跑。

## 横纵交汇：一条正确的大方向，尚未穿过产品化的窄门

蓝芯算力选择 RISC-V＋AI 服务器 CPU，并非没有逻辑。大模型推理和数据处理越来越受内存、I/O、调度与数据搬运约束；若 CPU 与加速单元能在同一地址/一致性/软件域内协作，系统可能比“通用 CPU＋离散加速卡”更省电、更容易部署。这就是它在机器人公司的云端数据闭环和私有化推理中值得观察的原因。

但历史短也决定了今天位置。成立仅在 **2023 年**后，公开可见的轨迹主要由工商、融资线索和合作消息组成，而非型号、流片、板卡、SDK 和订单。[工商检索](https://www.qcc.com/web/search?key=%E8%93%9D%E8%8A%AF%E7%AE%97%E5%8A%9B) 与先行的算能、华为、NVIDIA、阿里云相比，它缺的不是概念，而是把概念转成“客户不用理解底层也能部署”的系统证据。

优势的历史根源是项目可能从一开始就围绕融合而设计，不必背负离散卡生态的遗产；劣势的历史根源也在这里：从零建立 CPU 与 AI 两套生态，工程范围大于单做 NPU/GPU。早期合作若能提供整机验证会有价值，但也可能使团队过早陷入定制、延迟通用产品。未来的分水岭不是再签一个实验室，而是第一次可重复、可维护、可供货的客户部署。

### 三个剧本

**最可能剧本：早期原型＋产业方验证。**公司完成架构和首版工程验证，与服务器厂商/产业伙伴共同定义原型，融资继续覆盖软件与流片；对外主要以“RISC-V＋AI 融合”获得关注，短期还没有大规模独立订单。这个剧本符合其短历史和公开信息稀缺的状态。

**最危险剧本：路线过宽，CPU、AI、软件与供应同时失速。**若首版芯片没有足够 CPU 性能、AI 加速又难以覆盖主流模型，软件和系统认证同步滞后，客户会选择成熟的 CPU＋加速器组合。融资即使存在，也会被多轮流片、内存/IP、软件适配和客户定制快速消耗；联合实验室无法替代量产验证。

**最乐观剧本：做成一个可量产的专用智算节点。**蓝芯以明确场景（例如私有化推理、视频/数据预处理、边缘云）锁定软件栈和 I/O，发布可验证 RISC-V＋AI 芯片与服务器，伙伴将其纳入标准 SKU，开发者可以获得稳定 SDK/容器，外部客户验证 TCO。成功不要求它全面替代 NVIDIA 或昇腾，只要求在一个清晰负载上以成本、能效、供货和维护性胜出。

## 面向人形机器人公司的判断与行动

### 1. 投资判断：仅适合带工程里程碑的早期观察投资

**建议：可进入“种子/天使后观察池”，不建议在公开证据不足时做高估值战略下注。**支持理由是 RISC-V＋AI 融合若成功，可能为机器人数据闭环的离线处理、私有云推理和未来专用控制/计算节点提供自主可控选择。反对理由更直接：没有公开规格、客户、SDK、订单、供应或融资条款，无法判断公司是在概念、RTL、FPGA、首版硅还是量产阶段。

若我方拟投资，应采用分阶段可转债/优先股而非一次性大额普通股：第一笔以 RTL/仿真、关键团队和 IP 权属为条件；第二笔以首版 silicon bring-up、目标 PPA 与 Linux/编译器为条件；第三笔以客户板卡、量产良率、供货与真实回款为条件。以上是建议的交易结构，不是对公司现状的断言。触发终止条件包括核心架构/软件负责人离开、主目标性能未达标、供应许可不可获得或产品路线转为无边界定制。

### 2. 并购判断：不做整公司并购预案，先识别可买的“窄能力”

**建议：目前不启动整公司并购。**在产品和权属不透明时，收购的很可能是未来研发开支、关联义务和未验证路线，而不是可交付芯片能力。更适合探索的是联合定义一项可量化的研发任务：例如机器人场站的多摄像头数据预处理服务器、低比特推理运行时、RISC-V 控制平面或模型编译工具。先用 NRE、源码 escrow、专利/软件权属条款和里程碑验收锁定价值，再谈资产或团队并购。

并购触发条件：拿到完整 cap table、核心员工和 IP 清单；确认芯片 RTL、验证环境、固件、编译器和 SDK 的所有权/许可；有替代代工/封测和板卡供应方案；目标产品可在我方指定负载上通过可复现验收；且并购后能砍掉与机器人无关的 SKU。否则，合作应维持为可退出的实验性安排。

### 3. 训练、推理、数据闭环与自研芯片的协同边界

**训练：暂不承担核心训练。**在未展示显存/内存、互联、集合通信、框架、收敛和容错数据前，蓝芯算力不应进入机器人基础模型训练的关键路径。可以未来以小模型微调、算子验证或混合训练试验开始，但不得将路线图替代 GPU/NPU 集群能力。

**推理：优先验证固定场景的云端/边缘机房节点。**若有样品，应选择模型冻结、批量可控的工作负载，如数据清洗、视觉回放、日志理解或私有 agent 推理。测量精度、P50/P95、并发、功耗、重启、内存占用和单位任务成本，再与 GPU、昇腾、RISC-V CPU＋TPU/NPU 基线比较。没有产品规格就不签长期采购。

**数据闭环：这是最合理的潜在切入点。**机器人采集的多模态数据需要筛帧、压缩、质量检验、脱敏、索引和回传；CPU 与 AI 加速紧耦合理论上有机会减少搬运。但要把“理论上”变成价值，必须验证端到端数据管线，不仅测模型：时间同步、断网恢复、隐私、数据版本、存储吞吐、人工复核召回率都必须纳入。

**自研芯片：把蓝芯当作问题定义参照，不当作替代答案。**人形机器人自研芯片应先定义工作负载和系统边界，判断是需要端侧低功耗 NPU、视觉 SoC、控制 CPU，还是数据中心训练/推理加速器。蓝芯的融合理念提醒我们重视数据搬运和软件抽象；但在其产品未验证前，不应以投资早期服务器 CPU 项目替代我方芯片路线图。

## 产业链分类复核

**唯一主二级分类：1.4 其他 AI 芯片架构（FPGA、LPU、IPU、DPU 等）。**

**主分类理由。**在当前分类表中，蓝芯算力公开定位/总表备注为“RISC-V＋AI 服务器 CPU”，它不是以图形 GPU、通用 GPGPU、成熟 TPU 或端侧独立 NPU 的已商业化产品来创造价值；其差异化命题是将 RISC-V 通用服务器 CPU 与 AI 加速融合。现有二级分类没有“AI 服务器 CPU/RISC-V CPU”项，因此以 **1.4 其他 AI 芯片架构**承载最准确，且不夸大尚未公开验证的训练/推理能力。这个判断与总表当前 1.4 标签一致，应维持。

**可选次分类：2.1 加速计算平台（CUDA-like），但仅在后续证据出现时启用。**若公司能提供编译器、runtime、模型迁移/算子工具与跨节点软件栈，软件平台会成为其商业化关键；然而截至截止日未找到可验证 SDK/开源或产品文档，不能因“CPU＋AI”理念先行赋予 2.1。故当前**不建议写入正式次分类**；报告保留其为条件性候选，而非既成事实。

**边界说明。**不归入 1.1，因为公开资料不足以证明其主价值已是 AI 训练/推理集群；不归入 1.2/1.3，因为没有公开 TPU/NPU 成熟产品；不归入 1.8，因为无图形渲染/显示产品。若未来公司量产并以 AI 集群交付为主要收入，届时再根据订单和软件栈证据重新评估是否迁至 1.1；现阶段不应用路线图提前改类。
