# 端脑科技（无锡）有限公司（Cephalon Cloud／端脑云）横纵分析报告

> 研究截止日：2026-08-09  
> 研究对象：端脑科技（无锡）有限公司；任务表列出的曾用名为“脑花科技（无锡）有限公司”“端脑科技（深圳）有限公司”  
> 研究原则：法人、品牌、域名、产品后台与第三方名称分别取证；没有连续性证据就不合并  
> 分类结论：**8 其他（法人承接待核验的 AIGC 应用／GPU 租赁候选）**；`4.4 多厂商算力池`仅保留为**条件性观察**，不应作为已证实主类

## 结论先行

本轮可确认的是一个仍在运行的品牌和产品面，而不是一家已经完成主体穿透的 AI infra 公司。`cephalon.cloud/aigc` 将自己描述为“分布式 AIGC 算力网络”，并称可一键部署 AI 绘图 SD 环境；其公开后端同时返回 ComfyUI、Stable Diffusion、SSH、SGLang、Ollama 等任务类别，以及 RTX 5090 的按时计费样例。[S1](../raw/sources/2026-08-09-cephalon-cloud-official-aigc-page.md) [S2](../raw/sources/2026-08-09-cephalon-cloud-public-product-api.md)

但这两条证据没有出现“端脑科技（无锡）有限公司”，也没有出现任务表所列两个历史法人、统一社会信用代码、法定代表人、股权、合同主体或 IP 归属。`cephalon.cloud` 的 WHOIS 仅披露域名于 2023-07-26 注册、注册人国家为 CN，注册人身份不可得；网页归档只能证明最晚在 2023-12-25 已有可访问站点。[S3](../raw/sources/2026-08-09-cephalon-cloud-domain-and-archive.md) 因而不能把“端脑云的产品活跃”改写为“目标法人拥有该产品、其收入归属于该法人”。

这一区分直接改变投资结论：在法人—域名—后台—合同—IP 的链条闭合前，端脑科技（无锡）有限公司不是可进入估值、直投或整体并购流程的标的；也是不应承担机器人训练／生产推理供应责任的供应商。它可保留为一个**以 AIGC 镜像分发、轻量 GPU 租赁和社区工作流为中心的产品观察对象**。如果后续证明目标法人确实持续承接该品牌，最合理的早期合作仍是隔离的开发者工具／内容生产 PoC，而非集群级采购。

## 纵向分析：先长出的是产品面，不是可审计的公司故事

### 2023：域名与品牌入口出现

WHOIS 显示 `cephalon.cloud` 的创建日期为 2023-07-26；CDX 列表中最早的根域名成功快照为 2023-12-25。[S3](../raw/sources/2026-08-09-cephalon-cloud-domain-and-archive.md) 这提供了域名／站点存在的下界，却没有给出注册人、开发团队或目标法人名称。

因此，谨慎的叙事不是“端脑科技于 2023 年成立并上线端脑云”，而是“一个名为 Cephalon Cloud 的网络入口最晚在 2023 年末已可观察”。前一种说法至少多跨了四步：域名持有人是谁、其是否为运营方、运营方是否为目标无锡法人、历史深圳／脑花主体是否连续。每一步都需要独立原件。

### 2024：从 SD／ComfyUI 镜像菜单走向更宽的任务目录

公开分类接口的历史字段显示，`SD_FIRE` 在 2024-04-11、`COMFYUI` 在 2024-04-13、`ASCEND` 在 2024-04-15 出现在该产品目录；2024-11 又可见 `SGLANG_LLAMA`、`SD_WEBUI_FORGE` 等分类。[S2](../raw/sources/2026-08-09-cephalon-cloud-public-product-api.md) [S2a](../raw/sources/2026-08-09-cephalon-cloud-public-product-api-erratum.md)

这些字段支持的最窄结论是：产品团队在持续维护一个可启动的类别目录，早期重心是扩散模型／ComfyUI，后续增加了推理和开发类入口。它们**不**证明 Ascend 对应真实可售的昇腾资源，也不证明 SGLang 已形成生产推理 SLA；接口中的 `type:"unknown"`、缺少硬件 SKU、容量和地域，使其更像产品编排标签，而非采购可用性清单。

这个阶段的选择也勾勒出产品气质：不是先把算力抽象为统一 API 或资源池，再让开发者带工作负载；而是先用现成镜像、教程和具体创作任务降低启动门槛。它适合吸引 AIGC 长尾使用者，却会天然把平台注意力拉向镜像兼容、社区内容和计费转化，而不是企业级配额、审计、数据隔离和集群弹性。

### 2025—2026：目录继续扩展，外部名称增多，但合作关系仍为空

同一公开目录可见带昵称的条目，例如 2025 年的 `HEYGEM`、`DEEPAGENT`，以及多个以教程、创作者或特定 ComfyUI 版本命名的条目；截至采集时，目录 API 返回 `total:122`。公开排序接口还返回各类别的 `used_times`，其中 `COMFYUI` 为 312463、`SSH` 为 10225。[S2](../raw/sources/2026-08-09-cephalon-cloud-public-product-api.md) [S2a](../raw/sources/2026-08-09-cephalon-cloud-public-product-api-erratum.md)

这说明产品接口不是静态落地页，且目录演进覆盖图像、视频、语音、通用开发和推理工具。可是 `used_times` 没有字段定义、统计期间、去重规则或审计口径，绝不能换算为用户数、GPU 小时、订单、GMV 或收入。条目中出现第三方产品名称同样不能证明联合研发、商业授权、数据共享或客户关系；最常见的替代解释是社区镜像或用户提交的工作流。

官网目前仍以“无需部署、在线使用、一键部署 AI 绘图 SD 环境”定位自己。[S1](../raw/sources/2026-08-09-cephalon-cloud-official-aigc-page.md) 公开价格样例提供 RTX 5090、32GB 显存、按 `time` 计费的 `COMFYUI` 任务，但 CEP 的法币换算、实际可用容量、违约补偿、资源来源与持续可用性未披露。[S2](../raw/sources/2026-08-09-cephalon-cloud-public-product-api.md)

### 团队、融资与商业化：证据不能用“暂缺”补成故事

| 项目 | 可确认结论 | 本轮未确认、不得补写 |

## 产品与技术边界：看得见“任务菜单”，看不见“多厂商资源池”

### 已有产品层证据

1. **AIGC 入口。** 官网明确写“分布式 AIGC 算力网络”“无需部署”“一键部署 AI 绘图 SD 环境”。这是公司自述，足以将其归入 AIGC 应用／GPU 租赁候选，不足以证明网络拓扑。[S1](../raw/sources/2026-08-09-cephalon-cloud-official-aigc-page.md)
2. **任务／镜像目录。** 公开接口显示 ComfyUI、SD、CogVideo、Ollama、SGLang、SSH 等类别，并返回 122 个类别的目录总数。[S2](../raw/sources/2026-08-09-cephalon-cloud-public-product-api.md)
3. **一条硬件与计费样例。** `RTX5090` 的公开对象含 `video_memory:32`、`memory:128`、`cpu:12`、`mission_billing_type:"time"`、`cep:48`。这只说明该接口当时的一个配置对象，并不构成性能基准或库存证明。[S2](../raw/sources/2026-08-09-cephalon-cloud-public-product-api.md)

### 分类复核

任务清单将其预置为 `4.4 多厂商算力池`。该标签要求至少能回答：有哪些供应侧、是否跨云／跨芯片、资源如何发现与调度、客户是否面对统一合同和账单、失效时谁承担 SLO。当前资料没有一个问题被直接回答。

`ASCEND` 只是一个目录类别，不能证明对昇腾的真实供给；RTX 5090 样例也无法证明还有第二个厂商或资源所有者。官网中的“分布式”是产品自述，不等于已验证的 P2P、闲置算力撮合、多云调度或资源池控制面。因此应从“已属 4.4”降为：

| 分类 | 结论 | 原因 |
|---|---|---|
| **8 其他** | 主分类 | 已能观察到 AIGC 镜像／GPU 租赁产品面，但无法归属目标法人，也未形成基础设施池证据 |
| **4.4 多厂商算力池** | 条件性观察 | 需以供应商名册、异构资源清单、统一调度／账单、容量和合同主体补证 |
| 4.1 跨厂商训推调度 | 不成立 | 未披露跨厂商编排、训练作业、调度策略或性能／SLO |
| 4.3 推理跨 XPU 调度 | 不成立 | 无跨 XPU 路由、KV／PD、兼容层或生产推理指标 |

## 合作网络：五类分拆，而不是把目录名称当成生态关系

| 网络类型 | 已确认关系 | 不能确认的原因与下一步原件 |
|---|---|---|
| 投资方／股东 | 无 | 需工商股东穿透、融资协议、交割证明与投后 cap table |
| 客户／订单 | 无 | `used_times` 无客户身份和统计定义；需客户同意披露、PO、验收、回款或审计收入抽样 |
| 产业合作 | 无 | 需 GPU／IDC／云厂商协议、资源供应量、地域、期限、保底与违约条款 |
| 技术／联合研发 | 无 | HEYGEM、ComfyUI、SGLang、Ollama、Ascend 等仅为目录字段或标签；需联合公告、授权、代码提交、API 合同或 IP 归属 |
| 高校／科研渊源 | 无 | 需学校、实验室或论文作者的一手任职／项目材料 |

这张空网络表本身就是决定性发现。对轻量级 AIGC 消费产品来说，许多镜像名称可以在没有正式合作的情况下存在；但对投资和并购而言，资源供应、合同和 IP 正是价值与风险所在，不能省略。

## 横向分析：端脑云所在的不是单一“算力池”赛道

与其将端脑云直接同企业级多云调度平台比较，更合理的横截面是“降低 GPU／AI 工作负载启动成本的产品”。这个切面至少有三种不同的生意：资源市场、开发者云与镜像型 GPU 租赁。

| 代表产品 | 官方可观察形态 | 与端脑云的真正差异 | 对端脑云的启示 |
|---|---|---|---|
| Vast.ai | 官网描述为 GPU 租赁、托管与自动化的平台／市场，列出 REST API、CLI、Python SDK、Serverless GPU endpoints 与 GPU hosting | 把供给侧托管和开发者自动化做成显性产品；端脑云目前只见任务目录和计费样例，未见供应者侧、开发者 API 或资源市场契约 | 若要主张“分布式／多厂商”，先披露资源接入、隔离、结算、信用和故障处理机制，而非只扩镜像目录 [S4](../raw/sources/2026-08-09-vast-runpod-autodl-official-comparison.md) |
| Runpod | Serverless 文档说明可通过 Endpoint 执行代码、配置算力和缩放参数，按实际计算时间付费 | 重点是可编程端点与扩缩容操作面；端脑云的公开入口更偏预置任务与创作工具 | 对机器人推理真正有价值的是可版本化 API、限流、鉴权、观测与缩放，而不只是可手工打开的 UI [S4](../raw/sources/2026-08-09-vast-runpod-autodl-official-comparison.md) |
| AutoDL | 官网提供 GPU 租用、秒级计费、AI 镜像和技术社区；文档列有 GPU 选型、容器实例、迁移实例、摩尔线程 GPU 与 Pro API | 和端脑云最接近的是“镜像＋按量 GPU”体验；它公开呈现的文档化范围更接近研发者基础设施而非单一 AIGC 门户 | 端脑云若希望进入专业研发采购，需要可复现环境、可迁移存储、硬件选择边界、API 与责任条款 [S4](../raw/sources/2026-08-09-vast-runpod-autodl-official-comparison.md) |

端脑云的可见差异化并不在“硬件数量”或“异构调度算法”，因为二者都没有可核验资料。它真正可能拥有的产品楔子，是针对中文 AIGC 创作场景把镜像、教程、社区版本和按时计费粘在一起。这种楔子有获客效率，但壁垒更可能来自内容分发、镜像运维与社区，而不是难以复制的 GPU 控制面。对人形机器人公司而言，它最多映射到数据内容生产、演示素材和低风险研发试验；不能替代训练集群或在线推理底座。

6. 是否有真实企业客户、收入、毛利、回款、融资或可转让 IP？若无，估值和并购标的究竟是什么？

## 横纵交汇：早期产品取向如何塑造今天的投资边界

纵向看，端脑云先出现的是 AIGC 页面和一长串预置类别，随后逐步加上语言模型、开发和创作工具。横向看，Vast.ai、Runpod 与 AutoDL 分别把供给市场、可编程端点或容器化研发体验公开成了可审计的产品面。[S4](../raw/sources/2026-08-09-vast-runpod-autodl-official-comparison.md) 这解释了端脑云当前的位置：它有能力把“开一个可用环境”做成低摩擦体验，却没有公开证据表明已把“跨资源稳定地交付企业工作负载”做成产品。

如果把“分布式”理解为它的野心，早期大量教程／镜像目录既是优势也是包袱。优势是能以细分场景收集需求、测试镜像并获得长尾流量；包袱是每新增一个镜像都增加安全补丁、模型许可、依赖版本、存储和运维责任。到了机器人公司所关心的训练或线上推理，评判标准会从“能不能一键启动”变成“能否复现、隔离、审计、按合同交付、在故障时可恢复”。公开资料还没有跨过这个门槛。

更深的一层是主体问题。产品如果属于未穿透的法人集合，任何产品黏性都不能自动转化为可收购资产：代码、域名、客户数据、镜像版权、GPU 合同和支付流水都可能落在不同主体。因此当前最大的风险不是端脑云会不会被另一家 GPU 云压价，而是标的边界本身尚未可交易。

### 三个有触发条件的剧本

| 剧本 | 发生逻辑 | 触发／验证条件 | 对机器人公司的动作 |
|---|---|---|---|
| 最可能：长尾 AIGC 工具持续运营 | 任务目录和镜像继续增加，靠低门槛与小额按时计费维持产品活跃 | 目标法人无法证明承接；无企业合同和供给控制面；核心指标仍是目录／UI 活动 | 不进入生产采购与资本流程；只观察开发者产品能力 |
| 最危险：品牌与法人／资产断裂 | 域名、后端、支付、代码或 GPU 合同并不由目标法人持有，历史名称也非连续 | 尽调中无法取得更名档案、域名／备案、IP、合同、数据授权和财务闭环 | 立即从投资、并购和供应商候选池移除；不传输机器人数据或模型 |
| 最乐观：主体闭环后升级为可编程异构资源平台 | 目标法人证明品牌和 IP 承接，并披露多源资源、统一调度、客户和企业控制面 | 提供股权链、代码与域名归属、至少两类硬件／供应商、统一账单、可复现 SLO、付费客户验收 | 先做隔离 PoC；PoC 达到技术及合同阈值后再讨论小额战略投资，不先谈整体收购 |

## 面向人形机器人公司的建议

| 选项 | 当前建议 | 允许触发条件 | 禁止事项 |
|---|---|---|---|
| 采购 | **不准入生产采购** | 仅可在主体、合同、数据处理、资源可用性与支持边界闭环后，考虑非关键开发者环境 PoC | 不承载训练集群、在线推理、机器人遥操作数据或唯一备份 |
| 合作 | **不主动开展商业合作** | 若目标是 AIGC 宣传素材／非敏感合成内容，可在不上传内部数据、无自动续费、可随时退出的条件下试用 | 不把目录名称视为获得模型、框架或芯片厂商授权 |
| 投资 | **暂缓** | 取得连续工商、融资交割、cap table、收入与资源供应证据；并验证产品不是简单镜像分发 | 不以 `used_times`、域名历史或“分布式”自述作为估值基础 |
| 并购 | **暂缓，当前不具备资产收购边界** | 可枚举并转让：代码仓库、域名、商标、镜像版权、客户合同、GPU 合同、数据与团队；无权属瑕疵 | 不进行整体并购、预付款或排他绑定 |
| 自研 | **保留核心控制面自研** | 若未来确证其有用户触达，可考虑采购其非核心镜像运营／社区分发能力 | 不外包异构资源调度、模型／数据安全、资源准入、成本归因与生产 SLO |

建议的尽调闸门顺序为：

1. 工商：统一社会信用代码、全量名称变更、股权及实际控制人；
2. 品牌：ICP／公安备案、域名账户、支付／发票、服务协议／隐私政策主体；
3. 资产：代码仓库、商标、镜像／模型许可证、客户数据处理授权；
4. 供给：GPU／IDC／云资源合同、型号、容量、地域、合规和故障补偿；
5. 商业：客户清单抽样、PO—验收—回款、收入／毛利与留存；
6. 技术：多硬件可用矩阵、隔离、可观测性、版本回滚、调度／计费一致性和故障演练。

任何一项在前三步失败，都应停止后续估值、竞标和并购讨论。这样做不是降低对端脑云产品的评价，而是避免把一个可用的网页服务错误地当成可交割、可持续承担机器人关键工作负载的公司资产。

## 方法说明

本报告采用横纵分析法：纵向只追踪有可复核时间锚点的品牌／产品演进，横向把同类 GPU 产品按供给控制面、可编程性和企业可采购性比较。由于唯一法人与品牌的连续性尚未闭环，所有结论均以“条件性观察”表述，不用产品自述替代公司、资产或交易事实。
