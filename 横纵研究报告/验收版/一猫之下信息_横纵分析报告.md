# 一猫之下（长沙）信息技术有限公司 横纵分析报告

> 研究截止日：2026-08-11｜研究对象类型：公司（早期实体，产品/IP/商业化待核验）｜任务清单暂定方向：`3.3 算力中心集成`｜结论置信度：低—中低

## 研究摘要与结论先行

**一句话定义：**截至研究截止日，唯一可以强确认的“一猫之下（长沙）信息技术有限公司”是一家于 2025-06-17 在长沙设立、法定代表人为邓皓天、注册资本 222.2222 万元的法人；其登记经营范围覆盖计算机硬件、云计算设备、系统集成、AI 软件和集成电路相关项目。[R1] 这些是可经营的法定边界，**不是**已经研发、制造、销售、交付或运维这些产品的证明。

公开网络上同时存在署名“一猫之下科技”的 B 站账号和 GitHub 组织 `1CatAI`。前者在 2026-01 展示名为 WQX22C 的“四卡 V100 128G 显存全液冷 NVLink 互联显卡坞”，称已在闲鱼、淘宝上架；后者维护面向 Tesla V100/SM70 的 `1Cat-vLLM` 工程分支。[R5][R6][R8] 它们都使用“一猫之下”或 `1Cat`，却都**没有**显示目标法人的统一社会信用代码、合同／发票销售主体、店铺经营者、雇佣关系或 IP 授权。因此，本报告把它们写成“可能相关的品牌／技术线索”，而不是目标法人的产品、收入、代码资产、客户能力或交付能力。

对于人形机器人公司，这是一项很实用的区分。若将品牌材料自动合并，标的看起来会同时拥有硬件整机、液冷、NVLink、多卡推理软件、线上销售和天使融资；逐项按法人归属审查后，能够落到题目法人名下的，仍只是工商登记和两篇带自动生成声明的融资传播。[R1][R3][R4] 当前不能建立其收入、客户、供应链、制造、运维、研发团队或核心 IP 的事实表。

**最终建议：**主分类从任务清单暂定的 `3.3 算力中心集成` 收紧为 **`8 其他——早期算力硬件／本地部署候选，法人产品与商业化待核验`**。`3.3 算力中心集成` 仅保留为条件性观察：只有当目标法人能提交以其为签约、开票、质保和售后责任主体的服务器／工作站／集群项目证据，且能说明设计、供货、验收和运维责任，才可重新纳入。现在不进入生产采购、战略投资或并购流程；可在不接触真实机器人数据、权重和生产网络的条件下，保留一次严格受限的技术／主体核验入口。

## 一、实体边界：先锁定法人，再讨论“一猫之下”

### 1.1 唯一研究对象

本报告的唯一研究对象是：**一猫之下（长沙）信息技术有限公司**，统一社会信用代码 **91430104MAELWAJQ7W**，法定代表人 **邓皓天**，注册地址为湖南省长沙市岳麓区学士街道学士路 336 号慧谷科技产业园 B1 栋 501-A，成立于 **2025-06-17**，注册资本 **222.2222 万元**。[R1] 亿欧数据页的名称、成立日和地址与此相符，可作为辅助交叉定位；该页不是工商档案的替代品。[R2]

登记范围很宽：包含计算机软硬件和工业控制计算机的制造／销售、云计算设备销售、计算机系统服务、AI 软硬件、系统集成、互联网数据服务、集成电路设计／制造／销售、租赁和维修等。[R1] 早期公司往往会采用宽范围经营表述，所以这里有两个不能跨越的边界：

## 二、纵向分析：从法人设立到品牌线索，证据链仍未汇合

### 2.1 2025-06：法人设立是唯一可靠的起点

2025-06-17 是目前可核验的公司起点。目标法人于长沙登记成立，注册资本 222.2222 万元，登记经营范围覆盖本地算力硬件和相关服务可涉及的若干环节。[R1] 但成立背景、实际创始团队履历、出资构成、首批雇员、创办动机、原始产品和早期客户在本轮可访问材料中都没有闭环。不能因为法定代表人是邓皓天，就为其补写其教育、前雇主、技术贡献或控制权比例。

宽范围登记会给研究者一个“无所不做”的错觉。对算力中心整合而言，真正承重的是 GPU／CPU／主板／网卡／存储／电源／液冷的供应来源，整机 SKU，机房或 IDC 的责任边界，部署容量，验收与故障响应。这里一个字段也没有出现。因此，2025 年的正确阶段名是“**法人设立与业务范围登记**”，而不是“服务器／云／芯片业务启动”。

### 2.2 2026-01：品牌层出现 V100 多卡与液冷的产品叙事

2026-01-14，署名“一猫之下科技”的 B站账号发布 WQX22C 视频。标题称其为“万元级最强本地AI方案”，文字称“**一猫之下WQX22C全液冷NVLink互联显卡坞**”，并写有“四卡 V100 128G 显存”“支持 300GB/s NVLink”“无CRC 无ECC报错”“星形互联 全互联”“已经在闲鱼淘宝上架”。[R5] NVIDIA 的原始产品页确认，V100 的 NVLink 版本平台规格可以达到 300 GB/s 双向互联带宽；这只能说明该数值与原始 GPU 平台规格一致，不能验证任何 WQX22C 产品的拓扑、实际装卡、链路配置或压力测试。[R7]

产品叙事中有两个积极线索。其一，它把重点放在存量 V100 的多卡再利用，而不是宣称制造一颗新 GPU；这是一个更加可理解的早期切入点。其二，V100、NVLink、液冷与本地大模型推理确实是相互关联的工程问题，若能用标准化机箱、线缆、转接、散热和软件配置降低部署失败率，就可能形成细分交付价值。

但它没有跨过采购证据的最低门槛：无完整 SKU／规格书、GPU 形态（SXM2／PCIe）、NVLink 拓扑图、散热液路、功率／噪声／热负载、兼容主板与电源、BOM、关键部件来源、序列号追溯、质保、RMA、发票主体、店铺主体、销量、买家身份、客户验收或售后记录。[R5] “无 CRC／ECC 报错”也没有给出运行时间、模型、并发、日志、环境和复现方法，不能作为可靠性结论。

更关键的是，这一段仍是**账号史，不是目标法人公司史**。视频账号未显示题目法人名称或统一社会信用代码，不能回填为该法人的产品上线、收入或交付里程碑。

### 2.3 2026-02：融资传播看似出现，证据却互相削弱

2026-02-10，亿欧一篇页面称目标法人完成天使轮，投资方为“麓山创星创投资”；DoNews 同日快讯称“一猫之下”完成天使轮，投资方为“麓山投资”。[R3][R4] 亿欧数据库的同名企业档案也列出一笔 2026-02-10 天使轮，行内金额为“未披露”，投资方为“麓山创星创投资”。[R2]

这些材料的硬伤在于来源属性。亿欧文章明确写“本文由小欧AI基于亿欧数据生成”；DoNews 明确写“本文内容由开放的智能模型自动生成，仅供参考”。[R3][R4] 它们没有引向投资方公告、基金法定名称、协议、工商变更、资金到账、股份比例、估值、董事席位或融资文件。两篇文中的“自研芯片迭代”“边缘算力平台”“小规模商用验证”等，也没有产品与客户字段，不能由融资传播转化为商业化事实。[R4]

数据库内部还有金额冲突：顶部写“融资总金额：500万人民币”，但唯一融资行的金额却写“未披露”。[R2] 在缺乏一手文件时，最严谨的处理不是取中值或选择看起来更具体的 500 万，而是将金额统一记为**未确认**。对投资决策而言，融资事件目前只提供“需向所谓投资方核验”的线索，尚不能形成 cap table 或现金跑道判断。

### 2.4 2026 年内：开源软件线索提供技术入口，不提供法律归属

`1CatAI/1Cat-vLLM` 的 README 把自身定义为面向 Tesla V100/SM70 的 vLLM 分支，提到 AWQ、注意力后端、长上下文稳定性、MTP、运行时默认值和部署路径；公开参考目标包括 4 张 Tesla V100 32GB 与 2 张 Tesla V100 32GB。[R6] 这些材料值得作为工程审查的起点：能够检查 build、依赖、测试、issue、release 与许可条款，而不是只能看 PPT。README 也明确把 FP8、MTP、DFlash 的部分路径标成实验性，避免将研究性路径说成生产默认。[R6]

本轮对 GitHub API 的复核显示，该仓库由 `1CatAI` 组织于 2026-03-10 创建，最近一次推送为 2026-08-04，许可证字段为 Apache-2.0；截至 2026-08-11 的公开计数是 588 stars、99 forks。[R8] 这至少说明项目不是静态截图，且可作为许可证、维护节奏和上游差异的技术尽调入口。平台热度没有说明代码由题目法人出资、雇佣、持有或为客户提供支持，不能并入法人技术资产、客户数或估值。

可这份技术可见性仍没有解决交易对象问题。仓库没有把 `1CatAI` 映射到目标法人，未出示著作权、员工发明、代码贡献者的劳动关系、开源合规、第三方依赖清单或对外商业支持主体。[R6] 即使代码在技术上可用，也不等于目标法人拥有可收购 IP，或能够签署带 SLA 的企业支持合同。应把它视作“可做许可证与安全审查的外部开源项目”，而不是“已证实的公司软件资产”。

### 2.5 纵向结论：可见叙事比可见责任链长得多

这条时间线的结构很清楚：先有一个登记范围广的新法人；随后出现“一猫之下”品牌的 V100 硬件叙事与开源软件叙事；再有一轮看似乐观但来源明确为自动生成的融资传播。它还没有形成一条可追溯的“**题目法人 → 产品／IP → 客户合同 → 交付验收 → 售后与回款**”链条。

这不是对产品路线的否定。存量 GPU 再利用与本地推理在特定预算敏感场景可能有意义。只是历史材料尚不足以判断这条路线由谁在做、在哪儿做、卖给谁、以什么质量责任出售。对人形机器人公司来说，前者可以进入技术雷达，后者才有资格进入供应商和交易模型。

## 四、横向分析：应比较可替代的采购责任，而非虚构已证实竞品

### 4.1 横向场景判定

目标法人的实物和商业化边界尚未公开，无法诚实地列出其已被验证的直接竞品。本报告采用“**采购替代集**”：任何计划建设本地推理／小型训练环境的机器人公司，都可以选择继续使用现有 GPU 服务器／工作站和开源推理框架、购买有明确法人和质保责任的整机／集成服务、租用外部算力，或在主体闭环后评估“一猫之下”候选方案。它们是买方可选项，不表示与目标法人存在竞争、合作或客户关系。

| 维度 | 目标法人：一猫之下（长沙）信息技术有限公司 | “一猫之下科技”账号／`1CatAI` 线索 | 有明确责任主体的整机／集成商 | 自建存量 V100 平台＋上游开源栈 |

这张对比表的核心不是判断谁的“参数更高”，而是判断谁能承担责任。V100 平台在 NVIDIA 原始规格上确有 16/32GB 配置与最高 300GB/s NVLink 信息。[R7] 但买方购买的永远不是一项裸 GPU 参数，而是兼容、供货、散热、固件、数据安全、故障处理和长期维护组成的系统责任。WQX22C 的传播把技术焦点放在前一半，却没有公开后一半；而且尚未被映射到目标法人。[R5]

### 4.2 两条可能路线及其真正的竞争门槛

若未来证明 WQX22C 等硬件确属目标法人，路线一将是“**存量 V100 多卡本地推理／开发工作站**”。它的潜在优势不是代际绝对性能，而是从二级市场或既有资产中压低显存容量成本，并将多卡互联、散热和软件环境打包。真正需要打败的替代方案不是“另一家 AI 芯片公司”，而是客户用既有服务器自行拼装，或购买成熟整机。分水岭是可复现的 TCO、上线时长、稳定性、功率与热管理、维保和备件，而非一个标题中的“万元级最强”。

若未来证明 `1Cat-vLLM` 属于目标法人，路线二将是“**旧代 GPU 的推理软件适配与支持**”。开源代码能成为获客入口，但开源存在本身不等于收费能力，也不等于企业服务。需要验证商业许可证与上游许可证的兼容、依赖 SBOM、release 维护频率、CVE 响应、模型／驱动支持矩阵、现场支持、客户是否为软件付费以及代码权利人。该仓库 README 自己标注部分功能为实验性，正说明应以实测而非品牌主张来选择路径。[R6]

两条路线若同时成立，可能形成“硬件＋软件”一体化卖点；但这仍是未来假设。仓库、店铺、硬件设计和法人之间只要有一环属于不同主体，所谓一体化就会在合同、质保、IP 和并购交割上解体。横向位置因此应保持为“待验证的本地算力候选”，不能提前看作数据中心集成商或推理平台供应商。

### 4.3 用户与运维视角：公开口碑不能替代客户验收

本轮没有获得由客户、IDC、服务器 OEM、店铺经营者或独立运维方提供、同时能关联到题目法人的项目反馈。公开视频的播放、互动或“上架”文字不等于付费客户，也不反映连续运行中的告警、泵／风扇／冷却故障、PCIe/NVLink 稳定性、服务器兼容、退货率、备件和售后时效。[R5]

对机器人公司而言，最重要的测试不是一次本地模型跑通，而是连续工程行为：长上下文与多模态推理负载下的错误率，断电与节点重启后的恢复，模型与驱动升级回退，连续满载温度／功耗曲线，远程日志与安全补丁，及维修期间谁承担模型迭代延误。当前公开资料不能回答其中任何一项。因此不能用“用户口碑良好”或“已实现商业验证”来填补空白。

## 五、横纵交汇与三个剧本

### 5.1 历史如何塑造当下位置

目标法人的历史非常短，且法人证据与品牌技术叙事尚未合流。这直接塑造了它现在的位置：它可以是一个值得跟踪的“旧代 GPU 再利用＋本地推理”线索，但不能被当作已验证的算力中心集成供应商。登记范围提供了未来可能承接相关业务的边界；B站和 GitHub 提供了待核验产品与工程方向；自动生成融资稿提供了潜在资金方线索。[R1]-[R6] 三者都不是可交付能力。

潜在优势也正来自这种聚焦。若同一团队确实同时掌握 V100 多卡硬件设计、热管理和旧 GPU 推理适配，就有机会在预算敏感的本地部署场景压缩试错成本。风险的历史根源也在同一处：公开叙事出现得比法人权属、销售合同和客户证明更早。早期传播能帮助发现项目，却不适合作为供应商准入或资产收购的依据。

### 5.2 三个剧本：用触发条件代替想象性预测

| 剧本 | 叙事 | 可验证触发条件 | 对机器人公司的动作 |
|---|---|---|---|
| 最可能：长期受限观察 | 法人持续存在，品牌与开源材料持续传播，但销售／IP／融资／客户链条仍不公开或不能对账。 | 不能把 WQX22C、店铺、仓库、融资和法人统一社会信用代码映射到同一套合同与权属材料。 | 不生产采购、不投资、不并购；只在公开信息更新时复核。 |
| 最危险：主体与分类误判 | 品牌账号、店铺、开源组织或所谓投资方属于不同实体；产品并非题目法人资产，或只是零售级组件而非集成服务。 | 发票／质保／店铺／IP／雇佣／融资主体不同，或无可持续供货与售后责任。 | 从 `3.3` 候选完全撤出；停止一切基于“硬件＋软件一体化”的协同和估值假设。 |
| 最乐观：形成可审计的本地算力交付闭环 | 目标法人证实品牌、产品和代码权属，针对限定服务器／V100 形态完成批量交付与可复现支持。 | SKU、BOM、供应链、代码许可、测试报告、发票／质保、客户验收、SLA、RMA 与融资交割逐项闭环。 | 先在隔离的非生产环境做小规模 PoC；通过 TCO、稳定性和服务测试后，才考虑非关键负载的双源采购与小额战略投资。 |

三种剧本都不是概率预测。它们的目的，是防止“技术上可能有趣”跳过“资产和合同上可交易”的台阶。最乐观剧本中的每一项都必须有相应原始材料，而不能由一个更精美的产品视频或一篇融资快讯替代。
