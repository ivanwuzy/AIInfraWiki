# 北京云思畅想科技有限公司 横纵分析报告

> 研究截止日：2026-08-09｜研究对象：北京云思畅想科技有限公司｜品牌/产品名称：时速云、TenxCloud、TCAP、KubeData、NeoStack、AIStack（仅在下述证据边界内使用）  
> 建议主分类：**3.4 容器化软件**；建议副分类：**3.5 调度与编排软件、3.7 监控与健康管理软件**。AIStack 的异构训推调度只作为 4.1 的条件性观察，不据此改写主分类。  
> 研究问题：该法人是否有可采购、可合作或可交易的云原生/智算平台能力，能否帮助人形机器人公司的训练、推理、数据闭环与运维？

## 结论先行

**主体结论：可将“时速云”确定为北京云思畅想科技有限公司的品牌；“TenxCloud”在官网被用作 TCAP 的英文产品名/标识和域名体系的一部分，而不是已被证实的独立法人。** 官网公司介绍直接写作“时速云（北京云思畅想科技有限公司）”，并在产品页页脚标注“时速云 ©2022~2026 北京云思畅想科技有限公司”。这足以把官网所列的品牌、TCAP、KubeData、NeoStack 与 AIStack 视为该法人的**对外产品主张**；但不能单凭网站将任何关联方、开源项目、客户部署、集团资源或收入并入法人。[官网主体与产品页](../raw/sources/2026-08-09-tenxcloud-official-aboutus.md) [AIStack/TCAP/KubeData](../raw/sources/2026-08-09-tenxcloud-official-aistack-tcap-kubedata.md)

**投资结论：不适合作为独立一级市场股权标的推进。** 公开材料只足以支持其在 2021 年与世纪互联体系发生“加入”或股权变更的历史事实线索，无法提供截至截止日的股东名册、交易协议、付款状态、实际控制人、优先权或可转让股权。若项目需要股权敞口，应先向潜在控股体系取得最新工商档案、股权结构及转让限制；在此之前不做估值、投资条款或“旧轮次累计融资额”推算。

**并购结论：不建议以整体收购北京云思畅想科技有限公司为前提。** 关键代码、商标、软件著作权、客户合同、员工劳动关系、云资源账户及后续支持责任均未闭环，且历史控制关系变化会放大资产/同意权风险。可保留“特定产品团队或可分割技术资产”的探索权，但只在权属、可转让性和持续支持可审计时进入交易尽调。

**采购/合作结论：可做封闭 PoC，不作生产准入或单一来源采购。** 对人形机器人公司，优先验证 TCAP/AIStack 是否能在隔离网络中同时调度既有 GPU 与国产算力、承载多机多卡训练作业、建立推理服务与可观测性；不要将官网所称“头部具身智能企业”匿名案例当作同业背书或性能保证。PoC 成功也只证明本次环境可用，不能替代合同、SLA、漏洞响应和长期运维能力核验。

## 二、纵向分析：从容器平台到“智算平台”展示

### 阶段一：以 Docker/Kubernetes 容器化切入（2014–2016）

这条路线最初瞄准的不是 AI 训练，而是企业应用如何更快地打包、集成、部署和运行。2019 年报道回顾称，2015–2016 年的产品以 Docker 与 Kubernetes 容器云为主，基于公有云为客户建立容器化应用的构建、集成、部署、运行平台，主要服务开发与运维环节。官网的时间线则写有 2015 年发布“国内首个基于 Kubernetes 的容器云平台”、取得天使融资，以及 2016 年推出企业级容器 PaaS 和签署首批私有云行业客户。[2019 年报道](../raw/sources/2019-09-02-36kr-tenxcloud-bplus-round.md) [官网时间线](../raw/sources/2026-08-09-tenxcloud-official-aboutus.md)

这是一种典型的容器 PaaS 起点：产品价值来自统一运行环境、应用交付和运维流程，而不是出售通用算力。官网叙事中的“公有云、私有云并举”是品牌发展口径，不能直接转化为该法人某一年度的订阅收入、IaaS 资源自有率或真实客户数。

### 阶段二：私有云 PaaS、微服务与交付服务并重（2017–2019）

2018 年 36 氪报道把产品描述为私有云 PaaS 解决方案，包括容器云 PaaS 与微服务治理；前者涵盖应用管理、交付中心、CI/CD、DevOps、集群管理，后者覆盖服务注册、API 网关、调用链追踪、配置、熔断和异常处理。报道还称其历史收费方式为“按 License 节点和服务两种收费方式”。这些信息支持“软件许可/订阅式授权加专业交付服务”的商业模式假设，但只反映报道时点，不能替代当前合同与财务数据。[2018 年报道](../raw/sources/2018-01-17-36kr-tenxcloud-b-round.md)

在这一阶段，2018 年报道宣布近亿元 B 轮：泰达科技投资领投，朗玛峰、九合、众海继续跟投；同时回溯 2015 年天使和 A 轮。2019 年，36 氪报道宣布时速云获得琥珀资本的 B+ 战略融资；官网时间线亦写“完成 B+ 轮融资，琥珀资本领投”。两项材料互为品牌事件交叉佐证，但都没有融资协议、目标法人工商增资页或到账凭证。因此，它们只能形成**时速云品牌的历史融资链**，不能直接得出北京云思畅想的逐轮持股或累计募资额。[2018 年 B 轮](../raw/sources/2018-01-17-36kr-tenxcloud-b-round.md) [2019 年 B+ 轮](../raw/sources/2019-09-02-36kr-tenxcloud-bplus-round.md) [官网时间线](../raw/sources/2026-08-09-tenxcloud-official-aboutus.md)

这段历史也形成了当前公司的能力路径依赖：它擅长的问题是把容器、CI/CD、服务治理、日志/监控与项目交付放到企业私有环境中统一管理；这与人形机器人训练集群所需要的基础设施有交集，却不等于已经具备针对多节点大模型训练、推理 P/D 分离或机器人数据治理的经过第三方验证的产品能力。

### 阶段三：渠道、信创与集团关系变化（2019–2023）

官网称 2019 年签约首批 36 家渠道生态合作伙伴；2020 年推出容器云 v5.0、成立武汉研发中心并进入信创工委会相关工作组；2021 年“时速云加入世纪互联”；2022 年发布 NeoStack、联合信通院打造云原生安全测试平台；2023 年发布 Kubebb、继续被列入信通院相关图谱。这些事件说明品牌从容器 PaaS 向“软硬一体、生态、信创与数据平台”扩展，但每一个产品、合作或组织身份均需独立核验其法人合同和 IP 归属。[官网时间线](../raw/sources/2026-08-09-tenxcloud-official-aboutus.md)

第三方页面称 2021-07-15 目标法人股东变更为深圳云原生科技有限公司，并列出旧股东；该页没有工商变更原件、交易协议或付款凭证。它可作为“法人控制关系发生过重大变化”的**中低置信线索**，不应在本报告中被写成截至 2026 年的现行股权结构。官网“加入世纪互联”的表述也只能确认品牌关系口径，不能替代股权穿透。[第三方收购报道](../raw/sources/2021-07-15-baijiahao-tenxcloud-vnet-acquisition.md) [官网时间线](../raw/sources/2026-08-09-tenxcloud-official-aboutus.md)

### 阶段四：AIStack 与机器人相关主张（截至 2026-08-09）

当前官网将 AIStack 定义为覆盖异构算力管理、模型训练、推理服务与模型资产的“一站式智算平台”，并自述支持 NVIDIA、昇腾、海光 DCU，GPU 虚拟化/切分、监控告警、分布式训练、TMaaS、模型资产以及“分布式与分离式推理”。它也展示了一个不具名的“某头部具身智能企业智算平台”案例，给出 60%+ 算力利用率提升和 40% 训练周期缩短等结果。[AIStack 产品页](../raw/sources/2026-08-09-tenxcloud-official-aistack-tcap-kubedata.md)

这代表产品叙事已延伸到训推与异构调度，但仍是**厂商展示层**：没有具名客户确认、任务规模、GPU/网络拓扑、模型类型、基线、测量周期或验收报告。它不能证明目标法人已经在具身智能行业形成可复制订单，也不能将“调度”升级为跨厂商训推算力调度平台（4.1）的成熟分类。主价值创造与历史可证路线仍是容器化应用与 PaaS，故主分类保留 3.4。

## 五、横向比较：当前切面

横向比较的目的是选部署路径，不是把缺少同一口径测试的厂商排成“性能排名”。北京云思畅想的可确认出发点是容器 PaaS/企业交付；当前 AIStack 是对异构训推管理的产品主张。其最接近的竞争压力来自更完整的企业云原生平台、云厂商托管 Kubernetes，以及客户自建 Kubernetes/调度层。

### 横纵交汇判断

北京云思畅想的优势若存在，来自较早进入 Kubernetes 企业落地、容器交付、微服务治理与服务化运维所积累的工程表达；官网当前把这些能力包装成 TCAP、NeoStack 与 AIStack 的连续产品线。其短板也来自同一历史：以企业应用 PaaS 为主的产品叙事，并不自动解决大规模多节点训练、GPU 网络拓扑、数据版本治理、仿真/真实数据闭环、长时间推理服务的确定性问题。

因此，评估重心不应落在“是否也写了 AIStack、P/D 分离、具身智能案例”，而应落在它能否将原有容器/运维能力在真实机器人训练负载上转化为可测量的可用性、利用率与支持责任。与已有 Kubernetes 体系相比，采购它应带来可验证的实施速度、故障恢复或异构资源利用改善；否则，团队应继续采用自建或已有平台，而不是因品牌历史而引入新的控制面。

## 八、面向人形机器人公司的行动建议

### 8.1 采购：只做有退出机制的 PoC

建议采购的是一个 **8–12 周、隔离环境、固定工作负载** 的 PoC，而不是年度平台合同。将供应商合同主体固定为“北京云思畅想科技有限公司”；若由集团/渠道公司签约，必须披露转售、知识产权、售后和数据处理责任链。

PoC 的最低验证集：

1. 在现有 GPU 与至少一种国产算力环境安装并升级/回滚；清楚列出不支持项。
2. 以同一 VLA/视觉训练作业、数据处理作业和推理服务作基线，测量排队时间、有效 GPU 利用、作业恢复、推理 P95 延迟、日志/指标/追踪可得性和故障恢复时间。
3. 演示 GPU 切分、配额隔离、多租户权限、数据不出域、节点失效后的训练作业处理；不得只展示控制台。
4. 提供漏洞响应、升级窗口、出口数据处理、工单 SLA、源代码/第三方依赖责任和支持团队名单。

通过 PoC 后可作为训练场或非关键模型服务的候选二供；未达到基线即退出。它不应被部署到机器人本体实时控制、安全闭环、唯一训练控制面或唯一数据资产目录。

### 8.2 合作：以成果交付替代生态口号

可以探索“机器人训推平台适配”合作：由我方定义作业、数据安全和验收指标，对方交付容器/调度/观测集成。合作文件应明确 API、插件、模型/数据不归属对方、开源组件许可、性能数据可使用范围和故障责任。官网伙伴 Logo、联合解决方案、认证或实验室成员身份不替代联合开发协议，也不形成自动的技术/IP 归属。[官网伙伴机制](../raw/sources/2026-08-09-tenxcloud-official-partner-support.md)

### 8.3 投资与并购：先穿透，再谈价格

- **投资：暂停。** 必须取得当前股权、过去融资交割、控制权、重大债务/诉讼、限制性权利和关联交易清单；确认可投资的到底是目标法人、控股平台还是可分割新主体。
- **并购：暂停整体交易。** 若战略价值来自某个调度/运维团队，应先做资产清单、代码归属与人力留任尽调，再评估技术资产或团队合作；不得为官网展示能力支付整体公司溢价。
- **估值：不做测算。** 当前没有可审计的收入、现金流、净债务、合同续费或可交易股权，因此任何估值倍数都会制造虚假精确性。

### 8.4 自研：保留机器人差异化控制面

建议自研/牢牢控制三层能力：机器人数据版本、数据权限与合规；训练任务与实验元数据；模型服务/边缘到云端的发布与回滚策略。通用 Kubernetes 生命周期管理、CI/CD、基础监控与部分集群交付可以采购或合作。这样的分工既保留对 VLA/世界模型训练闭环的差异化控制，也避免在未核实的供应商资产上建立不可替代依赖。
