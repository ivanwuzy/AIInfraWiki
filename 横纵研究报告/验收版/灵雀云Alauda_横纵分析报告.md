# 北京凌云雀科技有限公司 横纵分析报告

> 研究截止日：2026-08-09｜研究类型：公司横纵研究（严格法人边界）｜研究对象：北京凌云雀科技有限公司

## 结论摘要

**唯一研究主体是北京凌云雀科技有限公司，但品牌—法人映射尚未由可访问的一手材料闭环。** 可访问的 `alauda.cn` 材料能证明“灵雀云 / Alauda”品牌持续展示 ACP、企业级容器平台、Alauda AI、服务和客户案例；却没有直接写出北京凌云雀科技有限公司是域名/ICP 主办单位、产品许可方、合同/开票方、代码权利人或融资交割方。[主体边界核验记录](../raw/sources/2026-08-09-alauda-legal-entity-boundary-check.md)

所以，本报告把品牌材料作为**需要穿透到该法人的业务线索**，而非把品牌业绩自动放进该法人。对北京凌云雀科技有限公司的主分类建议为：**8 其他（主体承接未闭环）**；只有取得品牌、产品/IP、客户合同和服务收入由该法人承接的证据后，才调整为 **3.4 容器化软件**，并将 **3.5 调度与编排软件、3.6 集群管理软件、3.7 监控与健康管理软件** 作为已公开产品能力对应的副标签。[产品与服务](../raw/sources/2026-08-09-alauda-official-products-and-services.md)

对人形机器人公司，当前动作是**受限、无排他、无生产承诺的技术 PoC 候选**，而不是生产采购、直接投资或整体并购对象。PoC 前必须拿到法人承接、版本/许可证、漏洞与支持 SLA、部署基准、数据边界和退出机制；在这以前，报价、合同、收入、运维责任、供应链和 IP 都不能假定成立。

## 1. 研究范围、唯一法人和排除对象

这一隔离不是否定品牌产品存在，而是避免把“可见的品牌”误写为“可交易的法人资产包”。它也是投资、并购和供应商准入之间最关键的差别。

### 1.3 必须补齐的主体证据

1. 国家企业信用信息公示材料：统一社会信用代码、存续状态、法定代表人、登记地址、股东及历史变更。
2. ICP 主办单位查询结果，或由北京凌云雀科技有限公司签发的官网隐私政策/服务协议/报价单，能把域名与法人连接起来。
3. ACP、Alauda AI、相关商标和软件著作权的权属/许可链；对开源组件还需 CLA、商标政策和商业发行版差异。
4. 至少一份由目标法人签署的客户合同、验收、发票或回款抽样，证明产品和服务的商业承接。
5. 历次融资的投资协议、工商变更、交割文件和当前 cap table；品牌时间轴不能替代这些文件。

## 2. 一句话定义与当前分类

在**品牌层**，灵雀云 / Alauda 是一个以 Kubernetes 为底座的企业云原生平台组合：ACP 与企业级容器平台覆盖容器、应用交付、多集群管理、可观测性和运维；Alauda AI 又宣称覆盖 GPU 调度、模型训练、推理服务与全链路观测。[产品与服务](../raw/sources/2026-08-09-alauda-official-products-and-services.md)

在**法人层**，北京凌云雀科技有限公司是否就是上述组合的产品、IP、合同、服务收入和融资承接方，尚未证实。因此分类不能跳过主体核验：

| 标签 | 当前判定 | 触发条件 |
|---|---|---|

| 条件副：3.6 集群管理软件 | 暂不授予 | 官网称统一界面多集群管理，但要有目标法人交付/维护证据。 |

## 3. 纵向分析：品牌轨迹与法人承接断点

### 3.1 2014—2016：从容器云先发叙事到 SaaS 线索

官网时间轴称品牌在 2014 Q3 于西雅图和北京同时成立，2014 Q4 获高榕资本数百万美元天使投资；2015 Q1 进入微软加速器并发布 CaaS 平台，Q2 在中美发布 CaaS 商业化版本并称获得 50,000+ CaaS 用户，Q3 获宽带资本与高榕资本千万美元级 A 轮；2016 Q1 发布 Alauda Cloud / Alauda Cloud PRO SaaS 版本，Q2 称获得 100+ 企业客户。[品牌历史（校正配对）](../raw/sources/2026-08-09-alauda-official-about-brand-history-2.md)

这段历史揭示的路线选择是：早期以容器服务（CaaS）切入，然后把产品从开发者服务推进到企业级客户。不过这些表述只有品牌主体，且“用户”“客户”没有客户名单、注册口径、付费口径、活跃口径或主体承接。对目标法人而言，2014—2016 的问题不是故事是否连贯，而是：**这些产品、融资、账户和收入是否留在该法人，还是分布在未披露的境内外或关联实体中。**

### 3.2 2017—2020：转向金融/行业私有化与全栈平台

品牌时间轴在 2016—2017 年依次记录运营商、能源、证券、汽车与股份制银行进入；2017 Q4 记录腾讯云战略领投、高榕资本和宽带资本跟投的超亿元人民币 B 轮。2018 Q2 记录英特尔投资领投、明照资本等跟投的新一轮融资，Q3 将产品线描述为 ACE 与 ACP，Q4 记录 CNBPA 与中国石油梦想云；2019 Q1 记录 CDF；2020 年记录腾讯云私有云“全面战略合作”、ACP v3.0、浦信金融科技基金投资；Kube-OVN 进入 CNCF Sandbox 的品牌叙述在 2021 Q1。[品牌历史（校正配对）](../raw/sources/2026-08-09-alauda-official-about-brand-history-2.md)

这是一条从 SaaS 容器云向私有化、行业场景和平台化扩张的品牌路线。它的商业逻辑与机器人公司的需求有交集：大型企业通常购买的不只是 Kubernetes，而是合规、迁移、运维和持续服务。官网目前也明确展示规划咨询、落地交付、持续运维、驻场、TAM、7×24 售后和培训等服务形态。[产品与服务](../raw/sources/2026-08-09-alauda-official-products-and-services.md)

但这也放大了尽调难度。软件许可证、实施服务、驻场运维、培训认证可以由不同主体签约、开票或外包交付。没有合同/发票/人员雇佣和项目责任证据，不能把这一阶段的品牌商业化规模写入北京凌云雀科技有限公司的收入或订单。

### 3.3 2021—2023：开源生态、行业标准与品牌可信度叙事

时间轴继续记录 Harbor 企业版、Linux Foundation 相关加入、Gartner 相关入选、Aeraki Mesh 进入 CNCF Sandbox、FinOps 工作组、奖项和参与信通院《应用现代化建设指南》。这些节点可以支持其品牌围绕云原生生态、金融信创和应用现代化建立话语权。[品牌历史（校正配对）](../raw/sources/2026-08-09-alauda-official-about-brand-history-2.md)

需要特别拆开的是开源与 IP：Kube-OVN README 显示它是 CNCF Sandbox、Apache-2.0 项目，并宣称具备多集群网络及 Prometheus/Grafana 指标集成；这证明项目存在和可供评估的技术能力，却没有列出北京凌云雀科技有限公司为权利人或唯一维护人。[开源边界](../raw/sources/2026-08-09-kubeovn-open-source-boundary.md) 因此，这个项目可作为 ACP 的生态兼容线索，不能作为并购中可自然转移的专有资产，更不能直接等同于目标法人的技术护城河。

### 3.4 截止日产品切面：从云原生平台延展到 AI 平台

可访问页面展示“ACP v4.0”、企业级容器平台与 Alauda AI。ACP 的公开定位是以 Kubernetes、DevOps、微服务覆盖开发—测试—部署—运维；容器平台页面列出多集群、多租户、插件、安全、可观测、网络存储、虚拟化、跨集群自动化运维等；Alauda AI 页面则列出异构 GPU 统一管理与任务级共享、模型仓库、模型训练/微调、模型托管与推理服务、Agent 编排、训练到推理的全链路监测治理。[产品与服务](../raw/sources/2026-08-09-alauda-official-products-and-services.md)

这条延展在技术上合理，却暂时只到**公开产品声明**：未找到版本兼容矩阵、GPU/网络/存储组合、性能复现、模型工作负载、生产 SLO、漏洞处理记录，也未找到其由目标法人销售/运维的证明。特别是“显存 1Mi / 算力 1% 切分”“标准 OpenAI 接口”“生产就绪”等词，不能替代机器人训练与推理集群上的实测。[产品与服务](../raw/sources/2026-08-09-alauda-official-products-and-services.md)

## 7. 三个剧本（截至截止日后的条件推演）

|---|---|---|---|

## 8. 面向人形机器人公司的策略建议

### 8.1 采购：仅限受控 PoC，暂不生产准入

可以探索的范围是研发用 Kubernetes/AI 平台：仿真任务、离线训练、模型评测和内部推理服务；先验收多集群治理、GPU 资源隔离、训练/推理可观测、升级回滚和离线环境恢复。Alauda AI 的 GPU 调度、模型训练和推理功能均只是官网自述，应让供应方在我方指定硬件、驱动、网络和模型上验证。[产品与服务](../raw/sources/2026-08-09-alauda-official-products-and-services.md)

采购门槛：

- 法人盖章的产品报价、授权链、服务/支持条款和开票主体；
- 软件版本、SBOM、开源组件清单、CVE 修复责任和数据处理协议；
- 在机器人 VLA/视觉模型训练、仿真数据管线、批量推理的真实 workload 上对比自建方案；
- 以可迁移的 Kubernetes API、数据导出、基础设施即代码和退出演练避免供应商锁定；
- 不将机器人真机控制、密钥、原始数据或唯一生产集群交给未完成主体核验的平台。

### 8.2 合作：围绕可验证工程，不签排他或共同 IP

可提出一个短周期、隔离的联合技术验证：异构 GPU 资源调度、Kubernetes 网络/存储兼容、模型服务弹性、告警和平台升级。验收物应是配置、日志、基准方法和故障演练，而非品牌宣讲。Kube-OVN、Cilium、Ceph、MinIO 等均涉及开源或第三方组件，必须分别审查许可证和安全更新责任。[开源边界](../raw/sources/2026-08-09-kubeovn-open-source-boundary.md)

合作前不应授予排他、客户数据使用权、共同 IP 或长期最低采购承诺。腾讯云、CNCF、信通院等公开关系也不构成对目标法人的合作信用背书。[客户与合作](../raw/sources/2026-08-09-alauda-official-customers-and-cooperation.md)

### 8.3 投资：暂停定价，转为法人/商业质量尽调

现阶段没有可归属目标法人的 cap table、历史融资交割、收入、续费、毛利、客户集中度或现金流，不能做估值锚定。品牌时间轴所列腾讯云、高榕、宽带、英特尔、明照、浦信等只应作为待回溯的线索。[品牌历史（校正配对）](../raw/sources/2026-08-09-alauda-official-about-brand-history-2.md)

恢复投资讨论的最低条件是：工商与控制链、融资轮次/金额/交割、产品与商标/软著归属、经客户许可核验的订单和回款样本、关键研发/交付人员的雇佣主体、开源合规和未决法律风险。

### 8.4 并购：不建议整体并购，先做资产可转移性清单

整体并购的第一道门槛不是产品宽度，而是资产边界：谁拥有 ACP/Alauda AI 商标、商业发行版源代码、客户合同、维护人员、Kube-OVN 相关贡献和全球站权益。现有材料不能回答这些问题。开源 Apache-2.0 项目与商业产品并存时，尤其不能把社区代码、品牌影响和可独占的专有 IP 混成一个收购标的。[开源边界](../raw/sources/2026-08-09-kubeovn-open-source-boundary.md)

若未来主体证据闭环，也优先评估小范围资产/团队合作、产品授权或服务承接，而不是在没有可转移性证明时收购“品牌叙事”。

### 8.5 自研：保留控制面能力，不急于重造全栈容器平台

机器人公司应自研或牢牢掌握：工作负载定义、训练/仿真/数据闭环编排、模型与数据权限、部署策略、SRE 可观测标准、成本核算和跨云/跨芯片抽象。通用 Kubernetes 控制面、镜像仓库、日志指标和部分模型服务可以采购或采用上游开源，但必须保持迁移能力。

当前不建议因品牌页面的全栈功能清单就自研一个完整 ACP 替代品，也不建议交出训练平台的控制权。正确的顺序是先用同一套测试集比较受控 PoC、自建组件组合和其他企业平台，再把真正具有机器人特异性的调度、数据治理和仿真工作流沉淀到内部。
