# 算能科技（Sophgo）横纵分析报告

> 研究截止日：2026-08-06｜研究对象：公司｜口径：公开资料、产品文档与开源仓库；未获独立验证的信息明确标注为待核验

## 一句话定义

**算能科技（Sophgo，产品品牌“算丰 SOPHON”）是一家以自研 TPU 推理处理器、RISC-V 通用处理器及其板卡、服务器和工具链为交付单元的中国算力公司；已被验证的收入承载场景以视频智能分析和边缘/专用推理为主，而“云端大模型训推一体”是正在扩展、但尚需以客户、性能和供应链证据验证的第二增长叙事。**公司官网将其定位为覆盖“云、边、端”的定制算力提供商，并列举智算中心、大模型应用、城市管理和智能终端等应用；这属于公司自述，不能替代订单、收入或独立基准测试。[公司介绍](https://www.sophgo.com/about-us/index.html)

## 研究问题、边界与证据等级

本报告服务于人形机器人公司关于端侧推理、数据采集回灌、训练资源与供应安全的投资/合作决策，而不是对“国产算力”作抽象评价。研究截止日为 **2026 年 8 月 6 日**。凡是官网宣布的产品、合作、性能与生态状态，都标注为公司/合作方一手口径；媒体报道仅用于识别需尽调事项；无可访问一手材料支持的融资金额、客户订单、实际出货量、良率和大模型集群规模一律不补写。

证据强度分为：**A**＝产品文档、开源代码、监管文件或双方公告；**B**＝单方正式新闻稿；**C**＝权威媒体或产业媒体；**D**＝未能复核的二次传播。这里最关键的结论不是“有无芯片”，而是：一个机器人团队能否在确定的模型、功耗、热设计、摄像头/总线、维护周期和供货条件下，将其从 Demo 变成可复制的量产节点。

## 纵向分析：从“算丰”到算能的两条时间线

### 1. 起点不是大模型，而是应用驱动的专用推理

官网叙事把 **2016 年**定为算丰 SOPHON 品牌问世、聚焦应用驱动算力产品的起点；随后列出 **2017 年 BM1680**、**2018 年 BM1682 与 BM1880**、**2019 年 BM1684**，并称算能公司成立于同年。[官网发展历程](https://www.sophgo.com/about-us/index.html) 这条顺序十分重要：它说明公司的起家路径并不是在训练集群上正面复刻 NVIDIA，而是在安防、交通、城市治理等高路数视频场景中，把解码、预处理、INT8 推理、主机/模组和行业方案打包交付。

对客户而言，这类产品的卖点不只是一个 TOPS 数字。大量摄像头意味着视频解码吞吐、内存搬运、热约束、批量部署、故障替换和现场集成同等关键。官网今天仍把 BM1688 的典型能力描述为 **16 路**高清视频智能分析、**16 路**高清硬解码和 **10 路**高清硬编码，把 BM1684X 描述为 **32 路**分析、**32 路**硬解和 **12 路**硬编；这些是厂商标称条件而非通用模型 benchmark，比较时不能外推成机器人 VLA token/s。[产品矩阵](https://www.sophgo.com/about-us/index.html)

这也解释了算能此后较少以“单芯片峰值”争夺注意力、而持续出售模组、边缘盒、微服务器、1U 服务器和行业设备的选择。它让销售更靠近可交付结果，也使公司更依赖渠道、系统集成商和行业项目节奏。前者是进入长尾边缘场景的通道，后者则可能把收入锁在项目制、低复用软件和较长验收周期里；两面性将一直贯穿后文的判断。

### 2. 2019—2021：公司化、视觉 SoC 延展与生态并入

官网披露 **2019 年**公司成立、BM1684 发布；**2020 年**发布 CV183；**2021 年**发布 CV182，且“算丰合并入算能，完成 A 轮融资”。[公司发展历程](https://www.sophgo.com/about-us/index.html) 公开页面没有列出 A 轮金额、投资方、估值、法律主体或交割日期。因此，市场流传的具体融资额即使存在，也不应进入承重结论，尽调时应以工商变更、股权穿透和投资方公告逐笔核验。

CV 系列把产品从以 PCIe/服务器承载的推理加速器进一步推向低功耗视觉 SoC。官网当前列有 CV186AH、CV184x、CV180x 与 CV181x；其中 CV180x、CV181x 被表述为 RISC-V 的微/轻智能深度学习视觉处理器。[处理器目录](https://www.sophgo.com/about-us/index.html) 这类路线的战略含义是，把“处理器”变成摄像头、盒子、机器人感知模组中可设计进 BOM 的部件，而不只是云端卡。代价是 SKU 多、客户定制多，且不同硬件代际与系统镜像之间的迁移成本会侵蚀生态一致性。

团队层面，官网只披露公司在北京、上海、深圳、青岛等国内 **10 多个城市**及新加坡设研发中心，研发人员占比“超过 **70%**”、硕博士“超过 **80%**”；页面另一处使用超过 **73%** 和超过 **78%**，可见宣传版本存在口径差异。[公司介绍（两处口径）](https://www.sophgo.com/about-us/index.html) 对“核心创始团队的履历、实际控制人与比特大陆/相关主体的关系、关键架构师留存”本报告不作断言：这是影响供应合规、团队稳定与并购可行性的一级未确认事项，而不是可由招聘宣传替代的事实。

### 3. 2022：BM1684X 与 A+ 轮，推理硬件走向完整货架

官网将 **2022 年**记为 BM1684X、CV181 与 CV180 发布及 A+ 轮完成。[发展历程](https://www.sophgo.com/about-us/index.html) BM1684X 在官网的存续 SKU 中仍被用于模组、SE7 微服务器、SE8 服务器和多类行业一体机；例如 SE8 288-EA6-72 的说明为 BM1684X、**288 路**高清视频智能解析，另有基于 BM1684X 的 **1U、8 芯或 12 芯**集群服务器产品。[硬件目录](https://www.sophgo.com/about-us/index.html)

这表明公司并非只卖裸芯片。它至少试图控制从芯片、板卡/模组、整机到训练推理方案的更多环节。对机器人采购方，这种“模组到整机”的纵向一体化可降低首期 bring-up 难度；但真正的价值不应以广告页的“路数”判断，而应由四项验收决定：目标检测/跟踪/分割/多模态模型能否通过编译；端到端延迟是否包含图像采集和后处理；标称功耗是否在持续负载而非短时峰值下成立；升级驱动、模型和系统后是否仍能复现。

A+ 轮同样只被官方历程确认“完成”，未披露金额与投资方。[发展历程](https://www.sophgo.com/about-us/index.html) 对投资研究，这一“有轮次、无资本结构”的不透明度并非小瑕疵：若拟战略入股或并购，必须先取得 cap table、优先权、质押、关联交易、知识产权归属、境内外主体与代工/封测合同。没有这些文件，不应从轮次名称推导估值或控制权。

### 4. 2023：SG2042 把 RISC-V 放进服务器，而非只做端侧 MCU

**2023 年**官网列出 BM1688、CV186 系列和 **SG2042**；它把 SG2042 称作“行业首款 **64 核** RISC-V 处理器”。[官网发展历程](https://www.sophgo.com/about-us/index.html) 当前官网的产品描述是：SG2042 为基于 RISC-V 内核、主频 **2 GHz**、**64 核**单 SoC、**64 MB**共享三级缓存的处理器，并围绕它售卖 SRA1-20 计算、SRB1-20 存储、SRM1-20 融合服务器及 SRC1-10 机柜级集群。[SG2042 与服务器目录](https://www.sophgo.com/about-us/index.html)

这一步代表公司试图取得控制平面与通用计算生态，而不仅是 NPU/TPU 加速面。若 RISC-V 主机和推理加速器均来自同一供应商，边缘节点可以减少异构 BOM；软件层还可塑造“开源、自主可控”的差异化。然而 RISC-V 服务器在成熟度、操作系统、驱动、数据库/中间件、性能调优和第三方 ISV 支持方面并不天然等同 x86/Arm。官网的“软硬件全栈国产化、开源可控”是产品定位，[服务器目录](https://www.sophgo.com/about-us/index.html) 不是能够替代 SPEC、容器兼容矩阵或客户生产 SLA 的证据。

SG2042 与 BM168x 的组合更适合被理解为一个可选的边缘/专用服务器平台：通用 CPU 处理编排、I/O 和服务逻辑，TPU 处理视觉/推理。它不是训练 GPU 的直接等价物。将其拿来比较大模型训练，需要另行披露互联、显存/内存、集合通信、混合精度、分布式框架、checkpoint 和集群可用性；截至截止日，本报告未找到由算能发布且可独立复跑的、可与主流训练 GPU 平台一一对应的完整数据集。

### 5. 2024—2026：向大模型训推叙事扩张，证据仍以推理和生态合作为主

官网称 **2024 年**发布“大模型训推一体处理器 BM1690”；**2025 年**发布第二代服务器级 RISC-V 处理器 SG2044，并写入“第二代训推一体处理器、CV184 系列、第五代边缘处理器即将发布”。[发展历程](https://www.sophgo.com/about-us/index.html) “发布”“即将发布”“可购买”和“规模量产”是四种不同状态。页面没有公开 BM1690 的完整规格书、第三方稳定性报告、出货/客户数量与长期软件支持政策；故本报告仅把 BM1690 视为公司已公布的产品方向，不能将其算作已验证的机器人训练底座。

公司在 **2026 年 1 月**公告与清程极智签约：拟围绕云端算力、推理引擎和大模型服务平台协同，称清程极智的“赤兔 Chitu”将与算能芯片做算子、计算图、内存调度和部署工具链联合优化；公告还称 SophNet 依托自研 TPU 提供模型服务。[双方合作公告](https://www.sophgo.com/post/492.html) 这是一项双方面向未来的技术/产业合作，能证明适配意图，不能证明采购金额、推理性价比或生产 SLA。

官网还公布 **2026 年 1 月**与 360 集团签署战略合作的新闻，并将其描述为智能体生态协同；同月也有面向边缘硬件适配 MoltBot 的公告入口。[新闻列表](https://www.sophgo.com/post/index.html) 这些事件说明公司在将既有边缘硬件连接到 agent 与大模型软件热点，但它们未自动改变公司的收入内核。对研究者来说，关键问题仍是：大模型客户购买的是稳定的云 API、卡/整机、私有化交付，还是一次性联合营销；后三者的毛利、复购和供应约束显著不同。

### 6. 软件栈：开源是资产，也是一场工程验收

算能在 GitHub 组织公开了 **tpu-mlir**、**sophon-demo**、**sophon-sail**、**LLM-TPU** 等仓库，至少给外部开发者留下了可检查的编译、示例和部署接口。[Sophgo GitHub 组织](https://github.com/sophgo) [TPU-MLIR](https://github.com/sophgo/tpu-mlir) [Sophon Demo](https://github.com/sophgo/sophon-demo) [LLM-TPU](https://github.com/sophgo/LLM-TPU) 这与只提供封闭 SDK 的芯片商相比，降低了“第一天无法启动”的风险，也便于采购方将 CI、模型转换和问题单留痕。

但 GitHub 存在不等于开发者生态成熟。验收应逐仓库核对：目标芯片和目标 OS 是否仍在支持矩阵中；最新版 commit 与发布镜像是否匹配；ONNX、PyTorch、TensorFlow 或 LLM 图的算子覆盖率；量化精度回归；issue 的响应节奏；许可证是否允许商业修改/再分发；容器、驱动和固件之间是否存在锁版本。任何没有在我方模型和硬件上实际跑通的“适配”，只能按候选能力计价。

## 横向分析：算能处在什么竞争图谱里

### 1. 竞品场景判断

算能面对的是竞品充分的场景（C）：端侧视觉/机器人感知会遇到 NVIDIA Jetson、华为昇腾边缘产品、地平线与 Rockchip 等；国产云端推理和“训推一体”叙事又会遇到华为昇腾、寒武纪、壁仞、摩尔线程、沐曦等不同架构。这里选择五个代表性坐标：**NVIDIA、华为昇腾、地平线、寒武纪与瑞芯微**。它们并非都与算能一对一重叠，但共同界定采购方可选的系统路线。

### 2. NVIDIA：生态和工具链是最难复制的基线

NVIDIA 的 Jetson 产品线将 GPU、CUDA、TensorRT、JetPack、相机/传感器接口和机器人软件生态组合在一起。官方 Jetson 页面将其定位为边缘 AI 与机器人平台，并提供不同模块的性能/功耗档位；CUDA、TensorRT 和 Isaac 形成了从模型到机器人部署的连续工具链。[Jetson 官方页](https://www.nvidia.com/en-us/autonomous-machines/embedded-systems/) [JetPack 文档](https://docs.nvidia.com/jetson/jetpack/introduction/index.html) [Isaac ROS](https://nvidia-isaac-ros.github.io/)

用户选择 NVIDIA 通常不是因为某个单项 TOPS，而因为大多数视觉模型、容器、驱动、开发板、社区排错记录和工程师招聘市场都已在该栈上积累。它的弱点同样清晰：采购受出口、价格、供货、型号政策与平台锁定影响；高端 GPU 的能耗和散热也未必适合每一个机器人关节附近的计算盒。对算能而言，NVIDIA 不是一个“参数竞品”，而是软件迁移成本和开发确定性的标尺。

算能的机会在于：若目标任务可稳定量化到 INT8/BF16，且主要是多相机检测、跟踪、分割、视频编解码或专有视觉模型，那么 BM168x 模组的成本、功耗和定制空间可能有吸引力。其短板是公开可见的第三方机器人参考设计、ROS 2 深度集成、通用多模态/VLA 性能基线和长周期兼容承诺较少。故不应以“国产替代”采购，而应把具体模型转换与 30 天连续运行作为准入门槛。

### 3. 华为昇腾：强系统能力与合规/供应复杂度并存

华为将昇腾定位为 AI 计算产业生态，提供 Ascend CANN 软件栈、硬件产品和开发资源；CANN 文档公开列有算子、图编译与运行时等组件。[昇腾官网](https://www.hiascend.com/) [CANN 文档](https://www.hiascend.com/document) 这使它在国内政企、云与大模型生态中拥有更强的平台覆盖度。对于机器人公司，昇腾的优势是本土集成、云边协同与较强的组织投入；但其模型迁移、私有算子和版本锁定同样需要实测，不能假设与 CUDA 等价。

与昇腾相比，算能的可辨识位置不是“全栈规模更大”，而是更早深耕专用视觉推理、RISC-V 与边缘产品货架。算能可尝试用较轻的硬件组合赢下摄像头密集、成本敏感的感知节点；昇腾更可能在需要大规模 AI 基础设施、广泛行业集成或云端服务时占优。二者也可能同机并存：昇腾/其他加速器处理中心训练或大模型，算能承担某些边缘视频节点。但这条混合路线会增加运维栈，只有在 TCO 和供应风险收益明确时才值得。

### 4. 地平线：机器人/车载端侧竞争最值得正视

地平线以车载智能计算为核心，官方公开征程系列产品与开发工具，并在新闻/产品资料中强调面向智能驾驶的软硬协同。[地平线官网](https://www.horizon.auto/) [征程产品](https://www.horizon.auto/product) 对机器人而言，地平线的关键意义不在于它完全替代算能，而在于它代表“面向实时感知、安全、量产和长生命周期”的端侧芯片公司类型。若机器人未来需要多摄像头、低延迟感知、严格热设计和认证节奏，来自汽车量产经验的竞争压力会很直接。

算能相对地平线的潜在优势是：已有视频智能分析服务器/盒子历史、RISC-V 服务器尝试和更开放的开源工具链入口；潜在劣势是公开材料对机器人传感器融合、功能安全、量产质量体系和主机厂式交付的验证较少。地平线的公开材料也不能自动证明它适合每种通用人形机器人模型；然而它提醒我们，真正的端侧竞争不是“谁的芯片能跑网络”，而是谁能将传感器、软件、供货和生命周期一起承担。

### 5. 寒武纪：从推理卡到云端加速的国产加速器坐标

寒武纪公开把产品分为智能加速卡、智能边缘产品与软件平台，官方资料中有 MLU 系列、Neuware 软件栈和面向训练/推理的定位。[寒武纪官网](https://www.cambricon.com/) [产品页](https://www.cambricon.com/index.php?m=content&c=index&a=lists&catid=44) 作为上市公司，其公告、财报和风险披露相较非上市同业更可审计。[上交所公司信息](https://www.sse.com.cn/assortment/stock/list/info/company/index.shtml?COMPANY_CODE=688256)

对算能的横向意义在于，寒武纪将“芯片＋软件栈＋系统”做成更面向数据中心和 AI 加速的可比较对象。算能若要把 BM1690 推到“训推一体”，就必须回答与此类公司相同的问题：框架覆盖、集群通信、可靠性、供应、软件支持和客户复购；不能只用边缘视觉时代的工程能力来替代云端证明。反过来，寒武纪的云端重心也不自动覆盖算能在视频编解码与小型边缘整机的历史优势。

### 6. 瑞芯微：低成本视觉 SoC 的现实替代，而非新闻中的“算力大战”

瑞芯微公开提供面向 AIoT 的 SoC、开发板与 SDK，产品覆盖视觉、显示、编解码和端侧 AI。[瑞芯微官网](https://www.rock-chips.com/) [开发资源](https://docs.radxa.com/en/rock5/rock5b/getting_started) 对量产机器人而言，它代表另一种替代方案：不追求一个独立 TPU 厂商的全栈闭环，而是在成熟 Arm SoC、广泛板级生态和低成本供应中，以 NPU 完成足够的视觉任务。

算能若能在同等功耗下以更好的模型性能、视频能力、开发支持或供货条件胜出，才有理由取代这类方案；否则客户会偏好更成熟、BOM 更简单的通用 SoC。瑞芯微也提示一项反对证据：边缘场景需要的往往不是最高算力，而是长期可采购、软件稳定、可快速二次开发的综合产品。算能必须拿出实际的 SDK 生命周期与产线交付记录来回应。

### 7. 开发者/用户反馈：可验证的内容与缺口

可验证的开发者触点包括算能 GitHub 组织、TPU-MLIR、sophon-demo 和 LLM-TPU 仓库；这些可供采购方自行检查 README、issue、release、许可证和模型样例。[Sophgo GitHub](https://github.com/sophgo) [TPU-MLIR issue 列表](https://github.com/sophgo/tpu-mlir/issues) [Sophon-demo issue 列表](https://github.com/sophgo/sophon-demo/issues) 这种反馈比营销文案更有用，因为 issue 可以暴露版本依赖、模型转换失败与修复响应。

但截至截止日，本报告**没有把零散 issue 个案概括成“用户满意/不满意”的统计结论**：公开仓库的 issue 数不能等于用户数量，关闭状态也不能等于生产问题已解决。对比 NVIDIA 的 JetPack/Isaac ROS 文档和社区体量、华为的 CANN 文档、地平线和瑞芯微的 SDK 入口，可以确认的是开发支持形式不同；尚不能确认的是算能在机器人开发者群体中的真实采用率和平均问题解决时间。应向算能索取匿名化工单分布、LTS 版本表、关键客户 NPS 与参考设计，且由我方工程师复现。

## 横纵交汇：历史怎样塑造当下位置

算能今天最有辨识度的优势，并非一句“国产 TPU”，而是由早期视频推理与行业交付反复塑造出来的产品形态：芯片、视频 I/O、模组、盒子、服务器和应用方案可以被一起售出。BM1684/BM1684X 的多路视频定位，以及从 CV 到 SG2042 的产品扩张，解释了公司为什么有条件服务大量固定摄像头与边缘节点。[产品与历程](https://www.sophgo.com/about-us/index.html) 这是一种“工程集成优势”，其根源在于历史选择了场景，而非只选择峰值算力。

同一历史也形成包袱。视频智能分析的成功会鼓励组织继续以项目、行业方案和多 SKU 解决问题；大模型推理乃至训练需要的却是高频软件迭代、统一 runtime、集群管理、模型服务和可审计 SLA。BM1690、SophNet 及与清程极智的合作是跨越鸿沟的尝试，[合作公告](https://www.sophgo.com/post/492.html) 但“宣布联合优化”尚未证明公司完成了从硬件/项目商到平台型供应商的组织转变。

把竞品放回各自时间线，差异更清楚：NVIDIA 长期积累 CUDA 与开发者网络；华为以大型系统生态推动昇腾；地平线以车规量产和感知链条建立约束；瑞芯微在通用低成本 SoC 里锻炼交付；寒武纪则必须用公开市场下的产品和财务压力证明数据中心路线。算能较少拥有前两者的生态广度，也尚未公开证明后两种量产/财务可验证性；它拥有的机会是找到不需要复制所有人、却对边缘视频和本土供应足够有价值的窄而深的阵地。

### 三个剧本

**最可能剧本：边缘推理守住、云端推理渐进。**算能继续以 BM168x/CV、模组与整机在视频、工业、城市治理和部分私有化推理场景获得订单；BM1690 和 SophNet 通过伙伴适配增加大模型服务入口，但训练和高端集群不成为主要收入支柱。该剧本需要的不是惊人的单芯片宣传，而是可持续的 SDK、渠道与供货；它符合公司公开产品货架和合作类型。[官网产品矩阵](https://www.sophgo.com/about-us/index.html)

**最危险剧本：供应、合规和软件支持同时收紧。**2024 年路透社报道称，台积电在一颗芯片于华为产品中被发现后暂停对 Sophgo 的出货；报道中的关联与交易细节应由法律尽调和一手监管文件复核，不能在本报告中裁决。[Reuters 报道](https://www.reuters.com/technology/tsmc-halts-chip-shipments-china-based-firm-sophgo-after-chip-found-huawei-product-2024-10-25/) 但它足以说明供应链声誉与出口合规是实质风险。若先进制程/封装或关键软件依赖受限，同时 SDK 版本碎片化、合作不能转为订单，客户会优先转向有更强供应保障或更成熟生态的平台。对于机器人，停供一个模组会牵连整机认证和售后，不是可接受的“研发波动”。

**最乐观剧本：以可验证软硬协同切入机器人与国产推理。**公司将 tpu-mlir、Sophon SDK、RISC-V 主机和推理芯片收敛为少数长期支持的平台；清程极智等伙伴把模型服务优化转为可复现 benchmark 和付费部署；一批机器人/工业客户以量产订单验证多相机感知节点。此时算能的价值不在全面替代 CUDA，而在“以较低系统成本为指定模型提供可控的边缘推理”。成功前提包括透明的供货与合规路径、可迁移模型工具链、持续供货和外部客户证言；四者缺一不可。

## 对人形机器人公司的决策建议

### 1. 投资判断：观察优先，不建议在证据不足时以战略稀缺性定价

**建议：进入“工程验证＋供应链尽调”的观察池，不建议在未取得融资/股权、订单、供应与软件数据前做高溢价财务投资。**支持理由有三点：一是公司有从芯片到模组/服务器的真实产品货架与开源入口；二是长期视频推理经验与机器人多摄像头感知存在结构性相邻性；三是 RISC-V＋TPU 的组合为自主可控边缘系统提供了不同于纯 GPU 的选项。[官网产品目录](https://www.sophgo.com/about-us/index.html) [开源仓库](https://github.com/sophgo)

反对理由同样强：融资结构未公开、客户/订单/出货量未公开、BM1690 的第三方性能与生产状态不明、公开材料中缺少机器人量产案例，且供应链合规风险必须独立审查。[融资表](#融资历史逐项复核) 因此投资价值不能从“国产替代”推导出来。触发投资委员会重新评估的条件应是：连续两个产品周期的供货承诺；我方 VLA/感知模型的精度、P95 延迟和持续功耗达到预设阈值；至少两家非关联客户提供可验证量产/回款证言；完整 cap table 与 IP 权属无重大障碍。

### 2. 并购判断：当前不宜以整家公司并购为默认选项

**建议：不启动整家公司并购流程；可探索对特定软件、边缘模组团队或联合实验室的资产/人才合作，但须以清晰 IP、客户合同和出口合规审查为先决条件。**理由是公司产品线横跨 TPU、视觉 SoC、RISC-V、整机和行业方案，整并将同时带来 SKU、客户支持、供应链和潜在关联方复杂度。所谓“买芯片能力”很可能实际买入一套依赖外部代工、工具链和项目交付的系统。

并购触发条件应更严格：目标实体、专利/软件著作权/源代码权属闭环；关键架构师与编译器团队锁定；不存在会阻断交割或后续供应的制裁/许可风险；能将 80% 以上研发投入聚焦于我方两到三个明确平台，而非维持无边界 SKU；并且有替代来源可覆盖在产机器人。若这些条件不满足，少数股权投资、NRE 联合开发或长期供货框架更可逆。

### 3. 协同路线：把“芯片评估”拆成四条可验收工作流

**端侧推理。**先选一个计算边界清楚的任务，例如多相机 2D 检测/跟踪、仓内安全识别或低风险语义分割；在算能模组与 NVIDIA/地平线/通用 SoC 基线同测。指标包括精度、P50/P95 延迟、端到端功耗、冷启动、热稳态、故障恢复、模型升级耗时和单位成本。不得用视频“路数”代替机器人帧率。

**数据闭环。**算能在视频解码/边缘分析上的积累可用于采集端筛帧、事件过滤、脱敏和本地质量控制；但训练数据的价值取决于传感器时间同步、标注策略、长尾抽样和回传治理。建议将它定位为“数据入口的可选计算节点”，不把芯片供应商自动当作数据基础设施平台。

**云端训练与推理。**把训练与推理拆开招标。BM1690/SophNet 可进入离线推理、蒸馏、量化或小规模服务的 PoC；大规模训练只有在分布式框架、通信、容错、单位有效 token 成本和供应可得性均通过测试后才可承担关键任务。公开合作中提到的算子、图优化和内存调度，[清程极智合作公告](https://www.sophgo.com/post/492.html) 可作为联合 benchmark 的切入口，而不是采购结论。

**自研芯片。**算能的存在对我方的最大启发是：机器人自研芯片应从确定工作负载出发，而非先定义“做一个通用 GPU”。可研究多路相机 ISP/编解码、视觉特征提取、低比特 Transformer、确定性 I/O 和安全域的组合；但只有当年需求、软件团队、验证资源和供应链可覆盖时才进入立项。短期与其自研大模型训练芯片，不如先建立多供应商的模型编译/运行时抽象层，保留算能、GPU、NPU 等后端替换空间。

### 4. 风险、触发条件与下一步验证计划

| 优先级 | 待验证问题 | 行动与通过标准 | 不通过时的决策 |
|---|---|---|---|
| P0 | 目标模组/芯片是否可持续供货且合规 | 取得芯片、封装、板卡的供货承诺、原产/许可声明、停供通知和替代方案；由法务审查 | 不进入量产 BOM，只保留实验用途 |
| P0 | 我方模型能否稳定运行 | 用冻结模型与公开基线跑 30 天；记录精度、P95、功耗、崩溃、恢复和升级 | 不能替代现有平台，停止专项适配 |
| P0 | 软件栈是否可维护 | 从公开仓库和厂商 SDK 重建镜像、CI 转换、issue 闭环；明确 LTS | 限制为一次性项目，不做平台依赖 |
| P1 | BM1690/云服务的真实能力 | 要求第三方可复现 benchmark、计费口径、容量与 SLA；区分训练/推理 | 不把核心训练迁移至该平台 |
| P1 | 资本/控制权/IP 结构 | 获取 cap table、专利与软件权属、关联交易、质押和核心人员协议 | 不投资、不并购，仅签短期采购合同 |
| P2 | 机器人协同是否有经济性 | 在 50/500/5,000 台三种规模计算 BOM、NRE、售后和停供成本 | 只在局部场景使用，不做全机标准件 |

## 产业链分类复核

**唯一主二级分类：1.2 TPU（ASIC）。**

**理由。**按《产业链分类规则》，主分类应反映公司已商业化能力的核心价值创造与收入承载物。算能官网持续以 BM1684X、BM1688 等“TPU 处理器”为产品核心，并将模组、服务器、盒子及行业方案建立在这些专用推理芯片之上；其商业路径是以自研专用 AI 加速器连同板卡/整机交付视频智能分析和边缘推理，而不是以图形渲染 GPU、通用 GPGPU 或单纯软件订阅为主。[官网产品矩阵](https://www.sophgo.com/about-us/index.html) BM1690 的“训推一体”宣传不改变这一主判断，因为公开可验证商业化仍不足以把公司归入训练 GPU 平台。

**可选次分类：2.1 加速计算平台（CUDA-like），理由为次要。**TPU-MLIR、Sophon SDK、示例与 LLM-TPU 表明算能拥有服务于芯片部署、模型转换和运行时的工具链，[TPU-MLIR](https://github.com/sophgo/tpu-mlir) 这对客户迁移与生态有价值。但软件栈是将其 ASIC 产品售出的关键配套，公开资料尚不足以证明其独立软件平台收入或跨硬件中立性；故只能作为次分类，而不应取代 1.2。

**不建议列为主分类的相邻项。**SG2042/SG2044 的 RISC-V 服务器业务可作为公司产品线描述，但现有分类表没有“RISC-V CPU”二级项，且其官网呈现的主营硬件矩阵仍以 TPU/视觉推理交付为重；不建议因 RISC-V 宣传将其泛泛归入“8 其他”。如总表当前把算能归为 1.1 GPGPU 或 1.3 NPU，建议更正为 **1.2 TPU（ASIC）**；若已归为 1.2，则维持主类并补注上述 2.1 次类理由。
