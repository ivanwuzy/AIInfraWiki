# 派欧云（PPIO；派欧云计算（上海）有限公司）横纵分析报告

> 研究截止日：2026-08-11 ｜ 研究对象类型：分布式边缘云、GPU 云与 AI 云服务商 ｜ 主体：派欧云计算（上海）有限公司 ｜ 研究问题：PPIO 从边缘云转向 GPU/模型/Agent 服务后，究竟是可采购的 AI 云与分布式资源运营商，还是已被证明的跨厂商 XPU 统一算力池；其对人形机器人训练、数据和推理部署的战略价值是什么。

## 研究边界与结论先行

PPIO 的公开交付物是按量付费的边缘云、GPU 容器、Serverless GPU、模型 API、Agent/沙箱等云服务；其价值主张是把分散的边缘和 GPU 资源通过统一接入、调度与运营转成可购买容量。它不出售 GPU 芯片、不以软件许可证为主要公开收入承载物，也没有公开证明自己是跨 NVIDIA、AMD、昇腾等多类 XPU 的统一算力控制面。[S1][S3][S4][S5][S6]

1. **业务判断：是有真实产品、历史收入和规模化资源运营证据的 GPU/AI 云，但主业仍是边缘云。** 官网可见 GPU 容器实例、按需/抢占式计费、Serverless、模型 API；2026 年媒体转述的第二次港股申请材料显示，2025 年收入中边缘云约占 84.5%，AI 云约占 15.5%。因此应把其看作“边缘云打底、AI 云高速扩张”的服务商，而不是纯推理软件公司。[S4][S5][S6][S9]
2. **技术判断：资源聚合/调度成立，不等于多厂商 XPU 池成立。** 上市材料的转述支持其把第三方分散、异构算力资源接入平台并做统一调度；但官网公开 GPU 规格仅见 NVIDIA H200/H100/H20/RTX 4090，未发现 AMD、国产 GPU/NPU 的独立 SKU、跨 XPU 相同作业迁移、统一性能/SLA、统一账单或生产基准。故不把“异构”或模型 API 的多模型目录写成 `4.4 多厂商算力池`。[S4][S8][S9]
3. **财务与商业判断：有可审阅的增长，也有不可忽视的毛利/集中度压力。** 媒体按招股书转述的 2023—2025 年收入为 3.584/5.580/7.703 亿元，毛利率由 17.7% 降至 9.4%，且前五客户收入占比仍为 79.0%。AI 云收入增长很快，但 2025 年该业务毛利率仍为负。对投资人，Token 增长、节点数和注册用户不能替代单位经济、供应合同和客户留存。[S8][S9]
4. **人形机器人结论：适合做云端训练、仿真/数据处理或可中断推理的供应商 PoC；不应成为安全关键在线控制、单一数据底座或端侧算力替代。** 采购价值来自弹性、Spot 和开发者入口，而不是已证明的机器人训练优化或异构系统护城河。[S4][S5][L1]

## 一、纵向分析：从分布式边缘云到 Token/Agent 云

### 1. 起点：PPTV 的分布式网络经验与边缘云供给

官网称 PPIO 由 PPTV 创始人姚欣与原 PPTV 首席架构师王闻宇于 2018 年共同创立；两人的公开履历把视频分发、P2P、云服务和车联网经验连接到新公司的分布式云路线。[S2] 这一出身解释了公司最初为何瞄准低时延、高带宽、地理分散的边缘计算，而非从 GPU 集群训练软件或芯片切入。

2021 年的融资报道将其定义为“去中心化分布式云服务平台”：以共享经济模式汇聚网络边端的专业服务器资源，并称公司已在 2020 年启动商业化。该报道称当时覆盖中国 800 多个市县地区、累计融资超过 3 亿元，均为该时点的公司/媒体口径，不应与当下节点数、收入或硬件能力混同。[S7]

### 2. 2021：资本验证了边缘云模型，尚不是 AI GPU 云验证

2021-12-02，阿里云创新中心转载投资界报道称，PPIO 完成金额“过亿元人民币”的 A-1 轮融资，由创世伙伴 CCV 领投，张江科投、磐霖资本等跟投，蓝驰创投、沸点资本和华业天成追加。报道并称 A-2 接近完成。[S7] 这确认了融资事件和边缘云客户开发阶段，却不等于每一个列名机构仍持有股份，也不证明其已构建 GPU 多厂商资源池。

### 3. 2023—2025：AI 云成为新增长曲线，但仍未替代边缘云基本盘

2026 年对第二次港股申请的媒体解读援引招股书称：PPLabs Technology Limited（派想未来，PPIO 的境外上市主体）2023—2025 年总收入分别为 3.584、5.580、7.703 亿元；其中 AI 云收入由 26.5 万元、1,039 万元增至 1.192 亿元，2025 年占比 15.5%，边缘云收入仍为 6.511 亿元、占 84.5%。该资料把 AI 云描述为 2023 年推出、以分布式 GPU 资源提供推理需求的业务。[S9]

这段变化重要但不应被夸大：AI 云收入增幅显示产品-市场匹配正在形成，边缘云仍是主收入和资源网络基础；同时，媒体转述 2024/2025 的 AI 云毛利率分别为 -95.1%/-10.7%，改善不等于已盈利。[S8][S9]

### 4. 当前产品族：购买的是服务容量与调用，不是自有模型/芯片

| 产品层 | 官网可确认的公开交付物 | 可证明的价值 | 不可证明的价值 |
|---|---|---|---|
| GPU 云 | GPU 容器实例；H200/H100/H20/RTX 4090 等公开规格；按量和抢占式价格；镜像、存储、OpenAPI | 可购买的 NVIDIA GPU 容器与弹性/Spot 计费入口 | GPU 为公司自有、每种型号的总容量、训练集群 SLA、跨 XPU 统一池 [S4] |
| Serverless GPU | 私有镜像托管、弹性伸缩、负载均衡、按秒计费、日志/Endpoint 监控、秒级冷启动的公司主张 | 面向推理/应用的托管部署形态 | 所有模型的冷启动/P99、自动扩缩容上限、可靠性或成本优势 [S5] |
| 模型 API/MaaS | 多家模型 API、按 Token 价格、Fusion 融合模型网关 | 是模型访问与计费产品，不只是营销口号 | 模型权属、每一个模型均部署在 PPIO 自有 GPU、模型厂商排他授权 [S6] |
| Agent 云/沙箱 | 官网将 Agent 云、MCP/工具链接入列为服务方向 | 对 Agent 开发有产品入口 | 生产级安全隔离、企业 SLA、客户付费结构或机器人控制能力 [S3][S6] |
| 边缘云 | 分布式节点接入、算力管理和边缘服务 | 历史主业、供给获取和低时延场景能力 | 自动等价于 AI 训练集群或多 XPU 调度平台 [S1][S7] |

### 5. 2026：规模叙事增强，必须与审计时点区分

官网当前称平台有 5,000+ 全球分布式算力节点、66.6 万+注册用户、200+上架模型，并给出“日均 12,000 亿+ Tokens”等数值；其 About 页又称 2026 年 4 月日均 Token 消耗 10,280 亿、超 67 万注册开发者。数字口径和日期不同，均属于公司陈述，不能取最大数作为审计结论。[S1][S2]

相较之下，媒体转述的招股书节点为 2025-12-31 的 4,600+ 计算节点、覆盖 1,340+ 县市和 2026-04-30 的 57.4 万注册开发者。它可作为较严格的历史时间截面，但仍应在正式尽调中直接比对招股书和后台日志。[S8][S9]

### 合作网络 B：客户、订单与可购买交付

1. **中国铁塔案例：有具名项目叙述，边界清楚。** PPIO 首页称其为中国铁塔智联算力管理调度平台构建者，并称已接入北京、天津、广东、陕西、山东、湖北的 8 个节点、服务数十家下游客户。它是官网客户案例，可证明公开案例和所述资源纳管范围；仍不能证明 PPIO 拥有这些节点、项目合同金额、续期、毛利或可复用于 PPIO AI 云的 GPU 容量。[S3]
2. **其他 logo/行业覆盖：只作线索。** 官网客户案例区域出现特赞、百川智能、学校等名称/About 页称覆盖八类行业；未找到合同、采购额、验收、时间范围或双方公告，故不把 logo/行业文字写成客户订单。[S2][S3]
3. **自助可购服务：是最强的产品化证据。** GPU 容器和 Serverless 页面展示可用型号、计费方式、镜像与 OpenAPI/Endpoint 功能；服务条款也说明客户可在线购买云服务器、云存储、大模型 API 等服务。这支持“可购买服务”，不支持“已被大规模企业客户采用”。[S1][S4][S5]

### 合作网络 C：供给、生态与模型关系

PPIO 官网称与 GitHub、Hugging Face、OpenRouter、vLLM、SGLang 等“建立紧密合作”，且页面提供模型目录、MCP/工具入口。此处更稳妥的表述是 **生态接入/兼容或公司自述的合作关系**；在没有联合公告、合同、代码治理权或资源采购披露时，不称其为上游 GPU 供应商、模型 IP 权利人或独家渠道。[S2][S3][S6]

2026 媒体转述的招股书更重要的一点是：公司的边缘/AI 云模式整合第三方分散算力，且部分客户与供应商角色重叠，供应商主要是算力资源方。这支持“平台型资源运营”而非“全部自建数据中心”的判断；但其并未公开列出各 GPU/XPU 厂商、资源方、产能合同、地域合规或故障切换机制。[S9]

### 合作网络 D：技术与高校网络

本轮材料未发现 PPIO 与高校/实验室有可核验的联合研发项目。创始团队的 PPTV、车联网和分布式系统履历是人才来源，不应据此创建高校合作或把历史视频 P2P 技术等同于当前 GPU 推理的自有 IP。[S2]

## 三、横向分析：PPIO 的优势是供给与产品入口，不是已证明的跨芯片控制面

| 对手/路线 | 客户购买物 | 与 PPIO 的差异 | 应比较的实证指标 |
|---|---|---|---|
| 阿里云/腾讯云/火山引擎等综合云 | 自有/深度绑定的计算、网络、企业合规和全栈 PaaS/MaaS | 规模、区域合规和企业交付强；PPIO 主打分散供给与弹性价格 | 同区域 GPU 可用率、数据出入、故障恢复、SLA、总账单 |
| 硅基流动等模型 API/推理服务 | 模型 API、推理优化、企业部署 | PPIO 同时卖 GPU 容器、Serverless 与 Agent 资源；模型层的自研推理软件公开深度较低 | 同模型/同硬件的 TPOT、P99、首 Token、Token 成本与模型授权 |
| Vast.ai/Runpod/AutoDL 等 GPU 弹性服务 | GPU 租赁/市场、容器、Serverless | PPIO 的差异在中国边缘节点基础、国内主体和全球节点叙事 | 供给审查、容量确定性、实例中断率、冷启动、数据驻留和支持 |
| 无问芯穹、趋境等异构算力/训推系统 | 多芯片适配、运行时、调度或联合运营 | 后者若有跨 XPU 的模型性能与任务调度证据，技术控制面更深；PPIO 当前公开优势在资源服务 | 能否跨 NVIDIA/AMD/国产 XPU 迁移同一任务、编译/精度成本、Goodput、池化收益 |

### 1. 对综合云：PPIO 以供给利用率和价格灵活性竞争

GPU 页面公开 H100/H20/4090 的按量与 Spot 价格，以及地域覆盖、模型下载加速和镜像环境，说明其可把开发者的第一步购买简化为卡时/容器服务。[S4] 对预算敏感、可中断的训练、数据预处理、渲染和批推理，这种供给运营有现实价值；对需要严苛合规、多年合同、专线网络和可验证 SLA 的企业，则需直接与大型云的综合能力比较，不能只比卡时价。

### 2. 对模型 API 公司：PPIO 的模型服务是北向入口，不等于模型或推理引擎控制权

模型 API 页面展示大量第三方模型和按 Token 定价，Fusion 网关也指向“融合模型推理”。这证明其提供模型访问与计量，不证明公司训练这些模型、独占 GPU、掌握每个模型的许可，或拥有可与 vLLM/SGLang 一一对比的自研推理引擎。[S6] 因此，人形机器人使用 PPIO API 时应测试模型版本锁定、数据处理、容灾、限流和成本，而不能把目录的数量写成模型技术壁垒。

### 3. 对跨 XPU 平台：最关键的缺口是同一工作负载的跨芯片实证

IPO 材料转述的“异构算力资源池、统一调度多样化计算单元”可以解释 PPIO 如何把很多资源接入运营平台；“异构”可能是地域、服务器代际、CPU/GPU、网络或资源提供者的混合，并不自动等于多家 AI 芯片厂商的工作负载可迁移性。[S9] 当前公开 GPU 产品页列出的具体卡型均是 NVIDIA，因此尚未达到 `4.4` 所需的多厂商算力池证明。

若公司希望把该能力变为投资护城河，应公开或向尽调披露至少：芯片清单和地域可用性、同一模型跨 XPU 镜像/框架/编译器路径、计费与调度 API、故障重试、精度和性能回归、客户生产级 SLA 与资源归属。没有这些，资源来源多只说明采购/运营网络广，不说明技术控制面深。[S4][S9][L1]

## 四、横纵交汇：边缘供给网络是优势，AI 云的盈利与控制面决定上限

PPIO 的路线连续：PPTV/分布式网络经验 → 边缘云资源接入和低时延服务 → GPU 容器与 Spot → Serverless、模型 API 和 Agent 云。[S2][S4][S5][S6][S7] 这种演进使其可以把既有节点、运维和供给关系转为 AI 云入口；也使其在竞争中受制于资源采购成本、模型价格战、客户集中度与运维复杂性。

### 三个情景（未来 24—36 个月）

**最可能：成为区域性、价格敏感 AI 推理和 Agent 工作负载的弹性供给层。** 边缘云继续贡献现金流，AI 云依靠 GPU/Serverless/API 的组合扩大规模。前提是可用容量、模型服务可靠性、客户续费和资源成本保持平衡。[S4][S5][S9]

**最危险：Token 与节点增长掩盖了负毛利和集中度。** 2025 年整体毛利率下降、AI 云仍为负毛利，且客户集中度高；若 GPU 价格竞争、模型厂商直销或上游资源提价，平台模式的收入增长可能放大现金与履约压力。触发信号包括 AI 云毛利不转正、前五客户集中度无法下降、Spot 中断/SLA 争议或供应商与客户重叠引致条款风险。[S8][S9]

**最乐观：资源聚合升级为可验证的多区域、多芯片 AI 控制面。** 只有当 PPIO 公开并交付跨 XPU 任务迁移、统一调度、稳定的性能/成本收益和企业 SLA，分布式资源网络才会从价格渠道变为技术平台。现有公开材料尚不能证明该情景。[S4][S9][L1]

## 五、面向人形机器人的投资、并购、采购与自研建议

### 1. 投资：先穿透 AI 云的单位经济和资源权属

**建议动作：列入“可采购、可观察”的基础设施服务商，不基于公开资料作直接股权判断。** 正面是产品服务可见、上市材料提供了收入结构/网络/客户集中度的可审阅切面、AI 云收入增长快；反面是 AI 云毛利仍为负、边缘云仍是主业、平台依赖第三方资源且多 XPU 控制面未证实。[S4][S5][S8][S9]

**投资闸门：**取得最新招股书/审计报表；拆分边缘云、GPU 容器、Serverless、API、沙箱的收入、毛利、获客与续费；调阅资源方合同、最短供货期、定价波动、地域和出口限制；核验节点定义、GPU 实际容量/利用率、Top 客户/供应商重叠；以同一机器人多模态/VLA 负载测试成本和性能。若没有这些资料，注册用户、Token 或节点数不应决定估值。[S2][S8][S9][L1]

### 2. 并购：不建议；购买服务比购买运营网络合理

对人形机器人公司，收购 PPIO 会带入边缘节点、资源方合同、互联网内容/云合规、模型 API 和客户集中风险，并不能自动带来芯片、数据、训练框架或端侧控制的核心能力。公开信息未能证明可转移的多芯片调度 IP、独占 GPU 供给或机器人客户。除非我方将长期经营独立算力网络且经验证 PPIO 能显著降低训练/推理完成成本，否则优先采用可退出的采购/联合 PoC，而非控制权交易。[S1][S4][S9][L1]

### 3. 采购：以可中断云端任务开始，建立数据和模型退出机制

| 阶段 | 测试内容 | 通过门槛 | 停止条件 |
|---|---|---|---|
| 0：供应准入（2 周） | 核验可用区域、GPU SKU、账户主体、数据处理、模型许可、出口/监管和工单支持 | 书面明确数据驻留、删除、SLA 和责任方 | 不能满足机器人数据合规或服务条款不清 [S1][S4] |
| 1：容器/Spot（2—4 周） | 运行非机密的数据预处理、仿真、渲染或可恢复训练；测实例获得率、中断、网络、存储、恢复时间和真实账单 | 成本/完成时间优于备选云，且检查点恢复可重复 | 容量/中断使有效成本失控 [S4] |
| 2：Serverless/API（4—6 周） | 用非安全关键的多模态助手、标注质检或研发 Agent 测 P50/P99、冷启动、限流、模型版本、数据流与 Token 成本 | 有可量化的业务收益和可替代的模型/云出口路径 | 只能靠单模型/单云绑定，或数据处理不可接受 [S5][S6] |
| 3：小规模生产 | 仅在非安全关键云端功能部署，审计告警、故障演练、配额、账单、备份、退出和供应商支持 | SLA、成本、合规和灾备合同达标 | 任何一项无法合同化 |

不得把 PPIO 的云端模型 API 或 GPU 容器放入人形机器人的安全关键闭环控制；端侧感知/控制仍需独立的本地计算和安全降级设计。[L1]

### 4. 自研：自研工作负载可移植性与成本可观测，不自建“PPIO 式”节点网络

应自研的资产是 VLA/视觉/仿真任务的容器、数据脱敏、检查点、模型版本、跨云基准、作业编排、成本归因和故障降级，使 GPU 云成为可切换的供应。除非已证明公司自有负载足以长期填满多地域节点并且外部云无法满足数据、成本或供应安全要求，否则不应复制 PPIO 的资源聚合、边缘运维、市场供给和计费网络；后者会把本可由采购处理的运营风险变为组织性资本投入。[S4][S5][L1]

## 八、产业链分类复核

**主分类：`8 其他（分布式边缘云/GPU 云/AI 云服务）`。**

当前最能解释 PPIO 客户购买理由与公开收入承载物的是按量计费的边缘云、GPU 容器、Spot、Serverless、模型 API 与 Agent 基础设施；公司通过资源运营、计费和服务交付获得价值，而不是售卖独立调度软件许可证、芯片或完整数据中心集成项目。[S1][S4][S5][S6][S9] `8` 并非否定其技术调度能力，而是避免现有分类把“云资源服务商”误写成已被证明的异构控制面公司。

**正式次分类：不设。**

- **不归 `4.4 多厂商算力池`：**公开资料仅说明第三方分散/异构资源由平台统一调度；GPU 产品页可见 SKU 全为 NVIDIA，未见至少两家 AI 芯片厂商的可购买资源、同一作业跨 XPU 迁移、统一运行时/基准/计费/SLA证据。多地、多代、多个资源方或多模型不等于多厂商 XPU 池。[S4][S9]
- **不归 `4.1 跨厂商训推算力调度平台`：**没有公开独立软件授权、跨厂商训练/推理调度控制面、框架适配、客户生产实测或可验证的软硬件分离产品证据。其调度目前是云服务的内部/交付能力。[S1][S4][S9]
- **不归 `3.4 容器化软件`/`3.5 调度与编排软件`：**容器、弹性和调度是云服务功能；客户主要购买 GPU/模型/Agent 的容量和调用，不是可独立部署的容器/调度软件。[S4][S5]
- **不归 `5.2 推理框架`：**模型 API、Fusion 网关和 Serverless 证明托管推理服务，未证明 PPIO 交付独立推理框架或拥有对应核心 IP。[S5][S6]

若后续获得 AMD/国产 XPU 等真实 SKU、跨芯片工作负载迁移、统一账单/SLA、生产基准和客户案例，可重新评估 `4.4`；若它将调度控制面以软件形式独立销售，可再审查 `4.1/3.5`。
