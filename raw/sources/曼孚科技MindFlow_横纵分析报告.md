## 摘要：数据服务是主业，平台化是降低交付成本的手段

曼孚科技将自己定位为“数据驱动的 AI 基础设施平台”，可见交付物包括 DaaS 数据标注、数据处理、自动标注、数据管理、模型训练和面向自动驾驶、视觉、语音、文本等场景的项目服务。官网明确展示 2D／3D 点云、连续帧、分割、语音转录、OCR 与文本任务，核心经济含义是以平台、算法和人机协作生产符合客户规则的训练／评测数据，而不是出售通用基础模型或拥有客户原始数据。[S1][S2]

公司平台化覆盖面很宽：数据生命周期治理、数据托管和版本管理、AutoLabeling、AutoML／MaaS 等均出现在官网。但研究结论不应被产品菜单带偏：公开材料中最连续、最贴近客户采购动作的仍是数据标注、数据清洗、数据处理与项目管理。因此应归入 **7 数据服务（高置信）**；不以“模型训练平台”“MaaS”或自动驾驶场景宣传将其提升为训练框架、推理框架或机器人模型公司。

对人形机器人公司而言，曼孚有作为视觉、点云、视频、语音／文本、具身操作数据清洗和标注供应商的潜在价值。采购的前提是先把数据权属、处理者身份、人员访问、跨境、脱敏、回传、删除、标注一致性与失败赔偿写进合同。没有这些条款，标注服务越深地嵌入数据闭环，风险反而越大。

## 一、研究问题、证据分层与边界

本报告回答四个问题：

1. 曼孚的真实商业承载物是数据项目交付、软件订阅、模型服务，还是几者混合？
2. 自动标注和数据管理是否构成可复用平台能力，还是以人工项目为主的交付工具？
3. 自动驾驶经验能否迁移至人形机器人数据闭环？
4. 客户数据、标注结果、预标注模型、合成数据和模型训练产物的权属如何验证？

本次获得的一手材料以公司官网为主。官网可以证明公司对外提供某项产品或声称支持某类数据，不证明该能力已有大规模订单、客户使用量、算法精度或客户授予其训练权。公开百科中出现的工商、融资和创始人相关信息仅作 **L3 线索**；在没有注册档案、公司公告或投资方公告前，不用其推导估值、累计融资、股权和控制权。

## 二、纵向分析：从标注项目走向数据生命周期平台

### 2.1 起源：数据不是一个文件，而是一条生产线

AI 应用落地常把难点误判为模型选择。对自动驾驶、机器人和工业视觉而言，模型迭代往往被更早的一环限制：原始多传感器数据怎样安全进入系统、怎样被筛选和定义任务、谁来标、怎样复核、怎样回流到训练和评测。曼孚官网的产品组织恰好围绕这条生产线：DaaS 数据标注平台、数据管理、自动标注、模型训练和项目管理共同出现。[S1]

公开百科记录的法定主体为杭州曼孚科技有限公司、成立于 2018-11-16、法定代表人为章越；这些需以国家企业信用信息公示系统、工商档案或公司盖章材料复核。[S3] 本报告不把法定代表人自动称为创始人，也不虚构其履历。相较“谁提出概念”，更能解释公司路线的是中国智能驾驶和计算机视觉客户对点云连续帧、目标轨迹、分割、OCR、语音和多轮质检的持续需求——它天然要求人机协作的生产体系，而非一次性爬取数据。

### 2.3 产品演进：从“标一个框”到数据闭环的可配置工具

官网把平台分成五类，形成了清晰但需谨慎解释的产品地图。

1. **DaaS 数据标注平台。** 公开说法包含数据标注、数据处理、预训练大模型自动标注与项目管理；页面展示 2D 框、多边形、语义分割、3D cuboid、点云连续帧、语音转录、OCR 转写和文本分类等任务。[S1][S2] 这是最贴近数据服务主标签的产品。
2. **谷仓 AI 数据管理。** 宣称提供数据托管、可视化、版本管理和数据 API，指向数据集在团队之间的组织、追踪和再利用。[S1] 此类功能可降低数据闭环摩擦，但未证明它是独立订阅产品或客户已将核心数据资产托管。
3. **AutoLabeling。** 官网称以预训练大模型、AI 与 RPA 驱动自动化标注。[S1] 自动化的经济意义是提升预标注覆盖率，让人转向疑难样本和质检；不是对外公开承诺“无人工、无限质量”的模型服务。
4. **模型训练／MaaS。** 官网将其描述为自动化 AI 训练平台与“模型即服务”，面向缺少 AI 团队的企业。[S1] 这是一条潜在扩张方向，但公开资料没有披露其底层训练框架、模型 API、客户数或收入；不应据此认定公司主业已转为 5.1／5.2。
5. **行业化交付。** 自动驾驶是页面最具体的行业入口，涉及 3D 点云连续帧、车辆方向和 track ID 等细粒度规则。[S2] 这显示团队理解时序／空间标注生产流程，但不自动证明掌握车辆原始数据、道路采集网络或感知模型 IP。

这条演进路线有合理的商业逻辑。单纯人工标注会被人力成本、人员流动和质量方差侵蚀；把规则、预标注、任务分配、审核和版本管理沉淀进系统，才可能在下一轮项目中降低交付成本。真正的护城河不是网页上的功能名，而是客户级 schema、质检数据、项目管理能力、受控交付队伍和对特定传感器／任务的错误模式知识。它们是否归属于曼孚、客户还是共同控制，必须逐合同确认。

### 2.6 数据权属是此类公司的第一尽调问题

数据服务公司最容易被误解为“拥有大量数据”。现实通常更复杂：客户可能保留原始图像、点云、日志和标签规范的全部权利；供应商只是受委托处理者；也可能存在客户允许将匿名化、聚合化数据用于改进标注模型的有限授权。三种安排的资产价值和风险完全不同。

对于曼孚，至少要把下列权利逐项写明：

- 原始数据、脱敏副本、导出数据、任务元数据和 QA 记录的所有权；
- 标注结果、ontology／schema、预标注模型和纠错反馈的权属与可迁移性；
- 是否允许用客户数据训练 AutoLabeling、基础模型或其他客户项目；
- 数据驻留、人员／分包商访问、远程标注终端、日志、加密、泄露响应和删除证明；
- 对合成数据的来源、生成模型、版权、肖像／隐私、是否与真实客户数据混合；
- 客户终止后数据回传格式、时限、模型／缓存清除和审计权。

官网提到数据托管和自动化能力是正面信号，但任何网页表述都不能替代 DPA、保密协议、安全附件、数据处理说明、人员管理制度与实际渗透／审计报告。[S1]

## 三、横向分析：标注供应商的竞争不是“谁的页面更像平台”

曼孚处在数据服务、标注软件、自动化预标注和垂直交付的交叉点。横向比较必须同时看四类替代：传统项目型数据服务、国际大规模数据平台、以软件为主的标注工具、自建数据引擎与内部团队。

| 路线／代表 | 主要交付物 | 与曼孚的关系 | 人形机器人公司应比较什么 |
|---|---|---|---|
| 曼孚科技 | DaaS 标注、数据处理／管理、AutoLabeling、行业项目交付 | 以人机协作和自动驾驶点云等场景为公开重点。 | 标注准确率、返工率、时序一致性、数据权限和私有部署。 |
| 海天瑞声、数据堂等数据服务商 | 语音、文本、视觉等数据采集、清洗、标注和数据集服务 | 同属数据生产／交付市场，垂直、质量体系、地域和数据来源不同。 | 比较数据来源合规、规模、长尾任务、语言覆盖、价格和交付能力。 |
| Scale AI、Appen、TELUS Digital 等国际服务商 | 企业数据标注、RLHF、评测或众包／全球交付 | 在跨境项目、全球劳动力、流程成熟度上可替代，亦有数据主权约束。 | 比较中国数据驻留、跨境、机器人场景专长与供应链安全。 |
| Label Studio、CVAT、Supervisely 等工具／开源栈 | 标注工具、协作、部分自动化 | 自建团队可采用，替代项目服务的一部分而非全部质量运营。 | 当数据敏感、规则频繁变化或长期量大时，自建可提升控制力。 |
| 自动驾驶／机器人内部数据团队 | 采集、筛选、标注、仿真、闭环评测 | 最直接的“自研”替代，控制权强但组织成本高。 | 把内外部 unit cost、迭代周期、漏标事故和数据泄露风险一并测算。 |

### 3.1 相对优势：跨模态与时序数据生产的潜在可迁移性

官网展示的点云连续帧、track ID、方向、语音和文本任务说明其产品设计不只面向静态图像。[S2] 对机器人，这比单纯框选图片更接近真实的数据闭环：同一物体跨时间的 identity、一段动作视频中的状态变化、多模态传感器对齐和困难样本复核，都需要项目规则与工具协同。

另一个潜在优势是“平台 + 服务”组合。数据管理和版本能力可让客户将数据集、标注版本、模型结果与再标注任务关联；自动预标注可把人工投入集中在长尾和审核。前提是它真的在客户 VPC 或合规环境中稳定运行，且能输出标准格式与完整 QA 证据。这些条件在公开材料中尚未逐项证明。[S1]

### 3.2 相对短板与风险：服务规模不能只靠“AI+RPA”判断

**质量可量化性不足。** 官网没有公开不同任务的 inter-annotator agreement、漏标率、重标率、时序 ID switch、点云定位误差、交付周期或责任分配。自动标注的准确率与客户数据分布、标签规则和人工审核策略高度相关，不能用“预训练大模型”做泛化承诺。[S1]

**客户和订单透明度不足。** 自动驾驶、AIGC 和“卓越企业”说明目标市场，不是具名客户／收入证据。若供应商收入依赖少数主机厂或一级供应商，项目周期、验收和回款将影响持续性；当前无公开客户集中度与续约数据。

**数据合规与分包风险。** 点云、车内音视频、地理位置、工厂现场、人物图像与机器人操作记录都可能包含个人信息、商业秘密或敏感数据。以远程人力、外包或 RPA 处理时，权限管理、终端控制、跨境与删除尤为重要。公开产品页不足以证明其满足这些要求。

**与软件工具的边界。** 数据管理和 AutoLabeling 可能增强毛利，但如果核心工作仍为项目交付，规模会受人员、QA 和客户定制化约束；反过来，若转为软件订阅，则需证明产品标准化和留存。公开材料未给出拆分，不能二选一地武断归类。

## 四、横纵交汇：数据闭环的价值不在“拥有数据”，在可控地改进数据

曼孚从标注／数据项目出发，再把数据管理、自动标注和模型训练并入产品界面，这一纵向路径符合数据服务行业的常见升级：把一次性人工劳动沉淀为规则、工作流、预标注与质量系统。其横向竞争位置也由此决定——它不应与大模型 API 直接比较，而应与能否在客户数据边界内持续降低每一单位“有效训练样本”成本的服务商比较。

今天最大的机会来自具身智能和自动驾驶都需要高频、长尾、多模态、时序一致的数据；最大的风险也来自同一处：客户很少愿意把核心传感器和行为数据交给缺乏可审计治理的外部平台。若公司只是更便宜的人工标注，就会被内部团队、其他供应商和开源工具压价；若能把客户专属规则、困难样本发现、自动预标注和高质量反馈做成安全的持续系统，才可能提高粘性。

| 情景 | 条件 | 对曼孚的影响 | 机器人公司的应对 |
|---|---|---|---|
| 最可能：人机协作数据生产持续存在 | 多模态数据增长快，自动标注降低单价但不消除长尾 QA。 | 平台化提高交付效率，仍以行业项目和长期服务为主。 | 外包可变需求，内部掌握 schema、验收和关键 QA。 |
| 最危险：客户内建或工具开源压价 | 标注工具成熟、客户担忧数据外泄、标准任务自动化。 | 项目毛利和客户留存承压，平台难以独立收费。 | 以可迁移数据格式、开放协议和多供应商竞标避免锁定。 |
| 最乐观：成为具身数据闭环伙伴 | 公司证明时序／多传感器质量、私有化安全、自动预标注和快速迭代。 | 从人力供应商升级为客户训练数据运营层。 | 先用非核心场景共建 benchmark，达标后扩展到机器人长尾数据。 |

## 五、对人形机器人公司的行动建议

| 决策 | 建议 | 理由与边界 | 下一步验证 |
|---|---|---|---|
| 采购 | **有条件试点** | 可用于视频、点云、操作演示、场景文本和语音等数据的清洗、标注、复标；先避开最高敏感的原始人脸、厂内保密操作与唯一训练集。 | 以 2–4 周盲测比较多家供应商：标注精度、时序一致、漏标、返工、TAT、单个有效样本成本。 |
| 自研 | **保留数据规范与最终 QA** | Ontology、任务规范、抽检规则、困难样本发现、训练数据版本和模型反馈必须由内部控制。 | 建立可导出的 schema、数据血缘、golden set 和供应商可替换流程。 |
| 投资 | **观察，不按融资传闻决策** | 数据服务赛道可形成稳定现金流，但当前公司收入、客户集中度、毛利与数据权属未透明。 | 索取经审计收入、合同期限、客户集中度、自动化率、人员结构、DPA、安全审计和 cap table。 |
| 并购 | **不建议当前主路径** | 未证实其具身数据、采集网络或可转让核心 IP，且服务型组织整合难度高。 | 只有在获得关键团队、可验证私有化平台、合规数据生产能力和客户同意可转移时，才进入资产／人才并购评估。 |
| 战略合作 | **优先于股权** | 可共同建立机器人数据标注规范、QA 金标集、困难样本回流和自动预标注评测。 | 合同明确数据不用于其他客户／模型训练、人员与分包限制、驻留、导出、删除与违约责任。 |

## 七、产业链分类复核（报告末尾结论）

**主分类：7 数据服务（高置信）。** 官网中最具体、最连续的产品和交付场景是数据标注、数据处理、项目管理、点云／视觉／语音／文本任务和自动化预标注。它们直接服务于训练和评测数据的生产。[S1][S2]

**正式次分类：不设。**

- **不设 5.1 训练框架或 5.2 推理框架：** “模型训练平台”“MaaS”是公开产品方向，但没有披露足以证明其核心收入／竞争优势来自训练或推理框架的架构、客户或技术证据。
- **不设 5.4 推理应用编排与知识库框架：** 数据管理、数据 API 不等于 RAG／知识库或 agent 编排平台。
- **不设 6.5／6.6：** 自动驾驶与机器人相关场景是数据服务应用对象，不将其自动上升为 VLA／世界模型公司。

**条件性观察：数据管理／自动标注的软件化。** 若后续证实谷仓、AutoLabeling 以独立订阅方式产生主要收入，并提供客户可验证的版本／治理能力，可在公司页补充“数据服务中的软件化工具”描述；现有分类规则没有更精确的独立二级标签，不应为单公司新建目录。
