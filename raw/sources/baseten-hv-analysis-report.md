# Baseten（BaseTen Labs, Inc.）横纵分析报告
> 研究截止日：2026-08-11 ｜对象类型：生产级模型部署与托管推理平台 ｜主体：BaseTen Labs, Inc.（官网隐私政策直接披露）

## 结论先行

Baseten 的可投资价值不在于它宣称“有一个更快的推理框架”，而在于它把模型性能工程、专用/自托管部署、多云 GPU 容量、自动扩缩、API、可观测性和前置工程师服务组合成可售卖的生产推理交付。官网列出 dedicated inference、预优化 Model APIs、Baseten Cloud、self-hosted/hybrid、训练与 Model Labs 等产品入口；隐私政策直接确认经营主体为 **BaseTen Labs, Inc.**。[S1][S2] 公开客户案例能证明 Writer 等客户的实际部署与指定测试条件下的收益，但不能证明 Baseten 整体收入、客户合同金额或同等性能可复制到所有模型。[S3]

对于人形机器人公司，Baseten 更接近**海外云端/私有 VPC 的高性能模型推理与部署供应商**，而不是应当收购的核心推理运行时，也不是管理本公司全部训练资源的通用调度器。它可能适合非安全关键的云端多模态助手、语音/视觉后处理、模型 API 快速上线和国际化弹性容量；不应未经本地、网络、数据主权和故障测试就进入机器人闭环控制链路。当前建议是 **P0 采购验证、战略观察，不启动投资领投或并购**。

主分类应为 **`5.2 推理框架`（高置信）**：公司以模型运行时、推理优化、部署和生产 API 为价值中心。可列 **`5.4 推理应用编排与知识库框架`（中置信）** 为次分类，理由是 Chains、模型网关/调用、结构化输出及 compound AI 工作流等公开产品边界；不列 `3.5 调度与编排软件`，因为自动扩缩和内部资源调度服务于其托管推理，而非对外出售的独立、跨集群作业调度产品。

## 一、研究边界、主体与证据标准

### 1.1 研究对象与法定主体

Baseten 是面向生产环境的模型部署和推理平台。官网当前的核心表述是“fastest model runtimes、cross-cloud high availability、developer workflows”，并把平台分为 dedicated inference、预优化 Model APIs、训练（Loops）和面向模型实验室的分发产品；部署可以在 Baseten Cloud、客户自有环境或混合形态运行。[S1] 隐私政策写明 Company 为 **BaseTen Labs, Inc.**, 地址为旧金山 201 Spear St, Suite 1600，因此本报告以该主体而非“Baseten”品牌单独研究。[S2]

这一主体确认只覆盖公开网站和服务关系。正式签约/投资前仍要核验公司注册状态、最新 cap table、商标、专有推理引擎和性能优化代码的 IP、云资源转售合同、数据处理协议（DPA）以及员工发明归属；隐私政策不是公司章程、股权名册或安全审计报告。

### 1.2 本报告如何避免把营销语变成事实

推理平台最容易被误读的四组概念是：模型生态不等于客户；模型运行时不等于公司拥有每一层底层 IP；自动扩缩不等于通用调度平台；客户案例中的某个 benchmark 不等于全产品线性能。本报告据此分层：

- **一手技术/产品资料**证明公开接口、部署形态、文档列出的功能和服务承诺；
- **官方客户案例**证明相应客户在该案例条件下使用过 Baseten，但不推导合同规模、续费或平台整体表现；
- **权威媒体**用于融资、创始团队和历史转向的交叉核验；对尚未完成融资严格标为传闻/报道；
- **研究判断**服务于机器人公司的投资、采购和自研选择，不当作 Baseten 的承诺。

## 二、纵向分析：从“让 ML 应用更容易上线”到推理交付栈

### 2.1 起点：Gumroad 的生产机器学习痛点，而不是先做 GPU 云

Baseten 的创业逻辑先于生成式 AI 热潮。2022 年 TechCrunch 的公司启动报道回溯称，联合创始人兼 CEO Tuhin Srivastava、CTO Amir Haghighat 和首席科学家 Philip Howes 曾在 Gumroad 共事；他们为反欺诈和内容审核自建机器学习系统，发现模型本身之外还需要 API、后端、通知、集成、运维和产品界面，才可能把模型变成业务能力。[S4] 三人因此决定把“从模型到生产”的工程摩擦产品化。

这段经历解释了 Baseten 与纯 GPU 租赁商的差别。早期产品并不只是一个可选 GPU SKU，而是让开发者能够部署 TensorFlow、PyTorch、scikit-learn 模型、构建 API 和定制应用 UI 的平台。公司当时的客户包括 Stanford、University of Sydney、Cockroach Labs 和 Patreon 等，应用涉及内容审核与反欺诈。[S4] 它的原始护城河设想是把 ML 工程的长尾工作打包，而不是仅靠硬件差价赚取套利。

### 2.2 2021—2022：私测、种子/A 轮和通用 ML 应用平台

TechCrunch 2022 年 4 月报道，Baseten 已私测约一年后正式发布，公开披露累计 **2,000 万美元**融资：种子轮由 Greylock 与 South Park Commons Fund 共同领投，A 轮由 Greylock 领投，AI Fund、Caffeinated Capital 及多位个人/机构投资者参与。[S4] 文中称这笔钱用于扩充技术/产品团队并加强市场与商务。该报道足以支持“截至当时公司获 2,000 万美元”的历史节点，但没有给出完整可审计的轮次金额拆分，也不应用作 2026 年的总融资或估值。

这一阶段的产品较宽：模型部署、开发者 API 和 UI 工具都在范围内。优点是低门槛，缺点是容易成为泛 MLOps 工具箱的一员，与云厂商和开源组件竞争。生成式 AI 的需求后来把市场焦点从“怎样让任何模型上线”变成“怎样让大模型、多模态、语音、图像模型在高并发下又快又便宜地运行”。Baseten 的纵向演进可以理解为主动收窄到更难、也更能收费的那一段：推理性能和生产交付。

### 2.3 2023—2024：把性能工程、专用部署与客户交付绑定

Baseten 当前官网将“model performance research、inference-optimized infrastructure、developer experience、forward deployed engineers”并列为平台组成，而不是只列一个 Python SDK。[S1] 这显示公司已从早期模型应用工具转向推理部署全栈：一边用定制 kernel、解码和缓存技术改善单模型性能，一边提供单租户/自托管、容量和现场工程服务，让客户不用自己经营全部运行时与集群。

Writer 案例给出了这个变化的一张截面。Writer 需要上线自研 70B 医疗与金融 LLM，Baseten 的性能团队与前置工程师针对模型和实际 sequence/batch shape 构建 TensorRT-LLM 引擎；案例在 **四张 NVIDIA A100、FP16** 的特定 benchmark 下报告 60% 更高 tokens/s、23% 更低 TTFT、35% 更低每百万 token 成本。[S3] 这不是 Baseten 自研了 TensorRT-LLM，也不是所有模型均可获得相同收益；它证明的是 Baseten 能把 NVIDIA 的 SDK、模型特征和客户工作负载结合为部署工程服务。

对商业模式而言，前置工程师是双刃剑。它有助于打下高价值客户、形成优化数据与交付口碑，也可能使收入依赖人力、难以像纯 API 那样快速复制。投资判断不能只看客户 logo，还要拆分有多少收入来自可复制的软件/平台、多少来自持续工程支持，以及定制优化是否可在同类模型/客户间复用。

### 2.4 2025—2026：推理平台多层化，训练成为相邻延伸而非主引擎

官网现在将产品分成四类。第一，**Dedicated inference** 为开放、自定义和微调模型提供专用推理部署；第二，**Model APIs** 让用户直接调用预优化模型；第三，**Loops** 与训练 Jobs 为微调/RL 和自带容器训练提供入口；第四，**Baseten for Model Labs** 为模型方提供推理分发/变现工具。[S1][S5] 这意味着它不再只是部署客户模型，而是试图在模型开发者、应用开发者与算力交付之间占据中间层。

Loops 的文档尤其需要准确阅读。它定位为长上下文 LoRA 微调和异步 RL 的 early-access SDK：trainer 负责 forward/backward/optimizer，sampler 从 trainer 发布的最新权重生成结果；两者可独立扩缩，checkpoint 由用户下载或一键部署到 Baseten Inference Stack。[S5] 这证实 Baseten 在做训练—推理衔接，但也明确显示其尚处 Early Access，不能把 Loops 当作已成熟、已大规模商业验证的分布式训练平台。

公开文档目录显示 Baseten 已提供模型 API、推理调用、异步推理、streaming、结构化输出、function calling、训练 Jobs、Slurm、部署、CI/CD、权限、审计日志、Cloud/Single-tenant/Self-hosted、多种可观测性等模块。[S6] 这证明其产品表面积很大，却不等于每项模块都由同一专有控制面实现，或每项都对所有客户、地区、云和硬件公开可用。文档存在是技术准入证据，不是收入和运营规模证据。

## 三、技术与商业边界：Baseten 到底卖什么

### 3.1 推理运行时与托管部署是第一性产品

Baseten 当前的核心卖点是为自定义、开放和微调模型提供高性能推理。官网称可在其云、客户云或单租户集群部署，并提供 multi-cloud/global capacity、冷启动、99.99% uptime、自动扩缩、模型管理、观测与工程支持。[S1] 这些均说明它是推理部署服务商，而非只出售代码库或一个模型路由 SDK。

从技术价值链看，客户交给 Baseten 的通常是模型权重、容器/运行时要求、流量和性能目标；Baseten 决定或协助决定引擎、batch、并行、量化、缓存、GPU、区域、扩缩和 API 服务方式。公司可以使用第三方底层组件，如 Writer 案例中的 TensorRT-LLM；其商业价值在于把这些组件、基础设施和 SRE/性能工程整合为可运维服务。[S3] 因而不应把 Baseten 称为“自研推理框架公司”而忽视其更大的托管平台与服务属性。

### 3.2 模型 API 与专用部署：两种收入与风险结构

**Model APIs** 更接近模型按 token/调用的可快速试用入口，适合用户验证或直接消费预优化模型；**Dedicated inference** 更接近为客户私有/自定义模型提供专用资源和性能调优，适合规模化、性能敏感或安全要求高的负载。[S1] 前者可能有更快开发者获客和更透明的计量，后者更可能带来较高合同价值、迁移成本与服务收入，但也更依赖 GPU 供给、容量承诺、工程投入和客户集中度。

这一区别直接影响估值。不能把 Model APIs 的消费式收入、单租户部署的合同收入、云资源转售、性能咨询和 Forward Deployed Engineering 混成一种“软件 ARR”。尽调时应分项索取 booking、收入确认、毛利、GPU/云成本、利用率、最短合同期、预付比例、支持人时和净收入留存。

### 3.3 Chains / compound AI：应用编排能力存在，但边界有限

官网称 Baseten Chains 为 compound AI 提供细粒度硬件与 autoscaling，主张提高 GPU 使用并缩短延迟。[S1] 文档还公开 function calling、结构化输出、异步推理和多模型/应用构建入口。[S6] 这足以支持把它作为推理应用编排的次级能力：它能组织多个模型/步骤的在线执行，并使部署、资源和接口更接近应用开发者。

但 `5.4 推理应用编排与知识库框架` 的“知识库”部分没有被公开资料充分证明。未见 Baseten 将 RAG 的数据摄取、向量数据库、权限、知识生命周期和企业知识治理作为核心可审计产品。因此它不应被误列为通用知识库平台；Chains 的证据更适合说明**推理工作流/服务编排**，不是完整的企业 AI 应用平台控制面。

### 3.4 自动扩缩不是独立的集群调度产品

Baseten 会在内部执行实例选型、扩缩、区域部署和容量管理，这当然涉及调度。[S1][S6] 但客户购买的是推理 SLA 与模型服务，不是一个可以纳管任意训练、批处理、容器和多厂商资源的独立调度器。公开资料也没有给出它对外提供跨云跨厂商任务队列、公平性、通用 Kubernetes API 或裸集群治理的证据。

因此，在产业链分类中不要因“autoscaling”把它升级为 `3.5 调度与编排软件` 主体。对于机器人公司，这意味着 Baseten 可作为某个推理业务的供应商，却不能替代内部的训练/仿真资源编排、边缘设备调度或多供应商 GPU 采购控制面。

### 3.5 数据、安全与部署的实务边界

BaseTen Labs 的公开隐私政策主要是网站服务的个人数据文本，不能代替客户 DPA、模型权重归属或安全承诺。[S2] 官网表示支持 single-tenant 和 self-hosted、展示 SOC 2 Type II 与 HIPAA 标识，并称可在客户 VPC 运行。[S1] 这些是有价值的采购线索，但受监管的机器人数据、视频、语音、地图和事故日志仍需审查实际区域、子处理商、加密钥匙、日志留存、人员访问、模型权重隔离、审计导出和跨境传输条款。

自托管也不是“完全没有供应商风险”。必须明确控制面是否外连、升级是否依赖 Baseten、紧急漏洞修复时谁拥有变更权、性能优化是否需要把模型/样本暴露给工程师，以及合同终止后镜像、配置和 metrics 的可迁移性。

## 四、横向分析：推理交付的竞争不等于推理 kernel 的竞争

### 4.1 当前生态位

Baseten 位于三类公司之间：底层推理运行时（TensorRT-LLM、vLLM、SGLang 等）、托管推理/部署服务（Fireworks、Together、Replicate、Modal 等）和大型云厂商（AWS、Google Cloud、Azure/NVIDIA 生态）。它的独特定位是用自有平台、云资源、性能工程师和专用部署把这些层组合起来，承诺让客户更快把模型变成稳定服务。[S1][S3]

| 路线/代表 | 核心产品 | 相比 Baseten 的强项 | Baseten 的差异与局限 |
|---|---|---|---|
| vLLM / SGLang | 开源推理引擎、社区与可私有化 | 源码可控、避免单一托管商、可按本地硬件深调 | Baseten 省去运行时/基础设施/SRE 负担；但客户需评估黑箱优化、成本和迁移风险。 |
| TensorRT-LLM / NVIDIA Dynamo | NVIDIA 深层 kernel/编译/服务优化 | 对 NVIDIA GPU 与网络栈有更深原生协同 | Baseten 可在其上做交付，Writer 案例即为如此；这也说明部分底层价值来自外部生态。[S3] |
| Fireworks / Together / Replicate / Modal | 开发者 API、托管推理或 serverless GPU | 各自在模型 API、云容量、开源/开发者社区或弹性体验上有优势 | Baseten 更强调 dedicated deployment、性能工程和自托管/混合形态；需逐项比较而非用“推理平台”一词合并。 |
| Hyperscaler | 云账户、区域、合规、GPU 与原生 AI 服务 | 已有企业采购、网络/存储/身份/数据产品 | Baseten 的价值是跨云、模型专用优化和更快交付；但也受上游 GPU/云价格与容量约束。 |
| KServe / Ray Serve / Kubernetes | 开源部署和服务编排 | 可控、可与自建集群深入集成、避免托管加价 | Baseten 可节省长期平台维护，但不是它们的简单替代；双方常可共存。 |

### 4.2 与开源运行时：买工程能力还是自己拥有运行时

开源运行时为团队提供源码透明度、模型/硬件自主适配和长期成本上限，代价是必须自己处理 kernel、批处理、扩缩、告警、容量、升级回滚和 24×7 事故。Baseten 的 Writer 案例证明其可通过 TensorRT-LLM 和工程师资源给客户带来显著结果。[S3] 对缺少推理系统团队、又需要快速交付的应用公司，这是合理外包；对已有强平台团队、对数据/网络有严格边界的机器人公司，开源 runtime 可能保留更大的控制权。

没有一种选择在所有情况下更优。真正应比较的是“达到目标 p99/成本/SLA 的全成本”：云 GPU、平台费用、工程师、on-call、失误成本、模型升级频率、区域合规和退出成本。Baseten 的首页和客户案例中的性能数据是候选假设，不能替代本公司模型与流量形态的 A/B 测试。[S1][S3]

### 4.3 与推理 API 平台：客户控制权和性能服务的差异

纯 API 供应商把模型选择、更新、容量和性能大多隐藏在服务后方，开发体验很快，但模型权重、微调、私有运行时和区域控制可能受限。Baseten 同时提供 Model APIs 与 Dedicated deployments，因此可覆盖从试用到自有模型服务的两端。[S1] 这有机会形成 land-and-expand：先用预优化 API 验证，再迁移到专用模型集群。

风险在于两种产品的经济模型不同。API 对价格、模型版本与接口稳定性敏感；专用部署对容量承诺、交付人力和客户集中度敏感。若公司用同一套叙事掩盖二者，投资人会高估可复制性。需要分别观察 API 的净消费留存与 dedicated deployment 的启动周期、项目利润和续约。

### 4.4 与云厂商：从“购买算力”到“购买一条结果曲线”

大型云厂商可以交付 GPU、网络、身份、数据和托管 AI 服务，通常在区域、采购合规和基础设施规模上更强。Baseten 的差异并不在拥有更大云，而在于对单个模型和单个负载做性能研究、由工程师协助并将结果包进部署。其官网的“in our cloud or yours”、self-hosted、single-tenant 和 forward-deployed engineers 正是对 hyperscaler 空白的回应。[S1]

这条路的上限很高，但经营质量要看它能否把一次性性能项目固化成重复模块。若每个客户都要深度手工优化，营收增长会伴随交付成本；若有足够多的模型族、引擎模板、测量数据和自动化工具可复用，则服务能反过来加强平台。公开资料不足以量化两者比例。

### 4.5 用户/客户证据：可证明部署，但不可证明总收入

Baseten 官网展示了 Writer、Abridge、Cursor、OpenEvidence、Retool、Wispr、Zed 等大量 logo 和案例入口。[S1] Writer 页面还含客户 CTO 的具名引语与具体测试条件，因此它是强于单纯 logo 的客户使用证据。[S3] 但仍要保留三层限制：案例由供应商发布；指标限定于某模型、A100、FP16、批量和 baseline；未披露合同金额、续约、平台总支出或客户能否自行复制优化。

类似地，模型库中列出 Kimi、DeepSeek、GLM、Whisper、NVIDIA Nemotron 等模型，证明 Baseten 提供或宣传相应 API/部署能力，不代表获得模型方独家授权，也不代表模型方为客户或投资方。[S1] 客户、模型生态、投资方和云伙伴应始终拆开记录。

## 五、横纵交汇：早期“把 ML 送上生产”的选择，为推理潮留下了接口

Baseten 的历史优势在于它没有等到 LLM 爆发后才发现部署问题。Gumroad 经验让团队较早把模型发布、API、集成和运维当成完整工程；2022 年的通用 ML 平台积累使其已有部署和客户进入生产的语言。[S4] 当大模型推理成为成本和体验瓶颈后，公司能够把重心收敛到性能、专用容量与交付工程，而不是从零补齐平台层。

这段历史也留下了包袱。它面对的不是一个可被单一算法垄断的市场：底层有 TensorRT-LLM/vLLM/SGLang 与芯片厂商，横向有 API/托管推理创业公司，向上有云厂商。Baseten 必须证明其平台与前置工程能持续把外部技术变成更快上线、更低成本、更稳服务的客户结果；一旦这条转换不再优于客户自建或 hyperscaler，它就会退化为昂贵的 GPU 转售/项目集成商。

### 5.1 三种情景

**最可能情景：高性能专用推理平台持续扩张。** 模型应用公司缺少推理系统团队，愿意为 dedicated deployments、性能工程和自托管选项付费；Baseten 在一批语言、语音、图像和 agent 客户中积累可复用的优化模板。商业价值来自更短上市时间和持续服务，不只是 token 价格。

**乐观情景：形成“模型实验室—应用客户—部署网络”的双边分发层。** Model Labs 让模型方通过 Baseten 分发/计费，Model APIs 让应用方快速试用，Dedicated/Cloud/Self-hosted 把重度客户留下，Loops 又缩短训练 checkpoint 到推理的路径。[S1][S5] 若这四层共享模型性能、使用与交付数据，公司可能形成比单点 API 更强的飞轮。需要验证的前提是模型方实际签约、平台能抽取合理 take rate、并且多云容量不侵蚀毛利。

**危险情景：推理优化商品化，估值快于现金流。** 开源引擎和云厂商把大部分性能优化内建，客户自行拥有模型和部署，GPU 价格/供应或客户集中度使托管利润承压；大量前置工程师使边际成本上升。若 2026 年媒体报道的超大融资估值成为市场锚，而收入/毛利和续费未同步验证，风险会被放大。[S7]

## 六、面向人形机器人公司的动作建议

### 6.1 采购：P0 先验证云端/私有 VPC 推理，不接管实时控制

建议做 6—8 周 P0，选两类负载：云端多模态助手/任务规划与语音或视觉后处理；不要首先选择机器人实时运动控制、安全避障或离线大规模训练。对比 Baseten Cloud、self-hosted/客户 VPC、现有云/开源 runtime 三组方案，测量 TTFT、TPOT、p95/p99、端到端视频/音频预处理、GPU 利用率、冷启动、模型升级、跨区故障、数据出境、每有效请求成本和工程人时。

POC 必须采用公司的真实模型权重、真实提示/图像/视频尺寸和预期并发。Writer 案例在四张 A100、FP16 上的成绩只能作为“性能团队有能力”的先验，不能当作机器人模型的预算依据。[S3] 若使用自托管，要求合同确认控制面连通性、日志/权重访问、KMS、镜像导出、升级窗口、事故响应与退出迁移。

### 6.2 训练与 Loops：观察、试用，不作为核心训练底座

Loops 的 trainer/sampler 分离与 checkpoint 一键部署在后训练—推理迭代上有吸引力，适合把某个 LLM/VLM 的离线 RL 或 LoRA 实验更快送到服务环境。[S5] 但它仍是 Early Access，且公开材料未证明对机器人多模态数据、物理仿真、奖励函数、分布式大规模训练和长期安全评测的完整适配。因此应以单个非关键研究项目试用，保留现有训练、数据和实验追踪主链路。

### 6.3 投资与并购：战略观察，不应追逐报道估值

**投资建议：保持战略观察并争取 POC/技术合作；当前不进入常规财务投资立项。** 正面证据包括有公开主体、有明确的生产服务和部署选项、具名客户案例、早期融资基础以及推理交付的真实需求。[S1][S2][S3][S4] 不确定项包括当前收入、毛利、客户集中度、云成本/容量承诺、平台复用度、2025—2026 融资条款和跨硬件支持范围。

若未来考虑投资，须取得：(1) 按 API、dedicated、self-hosted、工程服务和训练产品拆分的收入/毛利/NRR；(2) GPU/云采购、容量承诺、利用率和客户最小承诺；(3) 前二十大客户的合同期限、迁移成本与实际支持工时；(4) 专有代码、TensorRT/vLLM/SGLang 等第三方依赖的权利和版本治理；(5) DPA、安全、数据地域与应急处置；(6) 所有已完成/拟议融资的交割和清算优先权文件。

**并购建议：不启动。** Baseten 的价值依赖全球云容量、客户网络、生态中立性和一支性能/SRE 组织，交易成本很可能受高估值和投资者权利影响；收购后还可能削弱其对其他模型/应用客户的中立服务。只有当本公司在国际云端机器人模型服务上形成长期高支出、POC 明显优于自建、并且可取得团队/IP/合同控制权时，才值得重新评估少数股权或战略合作。

### 6.4 自研边界

本公司应自研与机器人差异化最强的部分：边缘—云任务划分、设备端确定性运行时、模型/数据/轨迹归因、仿真 reward、安全策略和跨区域数据治理。通用 LLM/VLM 推理部署、token 计量、模型 API、在线 autoscaling 和部分性能调优可以采购或与 Baseten 类平台合作。自研芯片时，则应把 Baseten 视为潜在的模型服务交付伙伴，不误认为其已经解决芯片编译器、驱动、通信库或跨 XPU 一致性能问题。

## 九、产业链分类复核（报告末尾结论）

**主分类：`5.2 推理框架`（高置信）。** Baseten 的承重产品是将开放/自定义/微调模型部署为高性能、可扩缩的生产推理服务；专用部署、Model APIs、模型运行时、性能优化和推理 API 都直接支撑这一点。[S1][S3][S6] 即使底层部分采用 TensorRT-LLM 等外部技术，用户购买的核心仍是推理交付能力。

**次分类：`5.4 推理应用编排与知识库框架`（中置信，限于“推理应用编排”部分）。** Chains/compound AI、异步推理、结构化输出、function calling、模型调用和工作流资源配置显示其有面向应用的推理编排能力。[S1][S6] 但没有充分证据证明其是知识库、RAG 数据治理或企业知识管理平台；报告不把该次分类扩张为完整知识库能力。

**不列入 `3.5 调度与编排软件`。** Baseten 的自动扩缩、multi-cloud capacity 和内部资源调度服务于托管推理交付；公开资料未证明它向客户提供独立的通用集群调度器、跨任意工作负载的队列/公平性控制面或资源管理软件。[S1][S6] 因此这些能力不能改变其主分类。

**不列入 `4.2 推理PD分离` 或 `4.3 推理跨XPU异构调度`。** 官网有性能优化和跨云主张，但未提供以 PD 分离为独立产品的公开架构/基准，也未提供跨 XPU 的版本化兼容矩阵与生产验证。[S1][S3] 不应把云部署、多模型或多区域说成异构芯片调度。

### 方法说明

本报告按横纵分析法，把 Baseten 从通用 ML 上线工具到生产推理交付栈的历时变化，与开源运行时、托管推理、云厂商和应用编排的同期竞争结构交叉分析。所有未获公开财务、合同或生产验证支持的结论均保留为尽调问题。
