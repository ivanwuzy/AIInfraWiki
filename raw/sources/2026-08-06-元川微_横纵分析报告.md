# 元川微（ArcheFlowX）横纵分析报告

> 研究对象：杭州元川微科技有限公司（对外称“元川微”/ArcheFlowX）｜类型：AI 实时推理芯片早期公司｜研究截止：2026-08-06｜完成：2026-08-06｜金额除特别注明外为人民币。证据等级：L1=法定登记、公司一手文件、监管披露；L2=投资方/合作方一手材料或可复现实测；L3=有署名媒体原创报道；L4=转述、公司宣传或尚待复核的信息。**该公司成立不足一年，尚无公开量产芯片、审计财务或独立客户验收材料；本报告的“价值判断”因此以证伪清单为中心，而不是把融资新闻扩写成商业化事实。**

## 一句话定义

元川微是一家于 **2025-09** 在杭州成立、以“LPU+”为名押注**硬数据流＋大容量片上 SRAM＋时空编译器**的早期专用推理芯片公司；它试图把 Agent/多模态推理中反复的数据搬运和运行时调度，预先固化为确定性流水执行，但截至研究截止日，其公开证据仍停留在 FPGA 验证、首代芯片研发和客户验证阶段，而非已量产的云、边、端产品。[S1](https://aiqicha.baidu.com/company_detail_61717401658964) [S2](https://news.qq.com/rain/a/20260417A078JY00) [S3](https://www.leiphone.com/category/chips/AGaAOgr50XhElaxq.html)

## 结论先行与研究边界

**投资判断：可进入“高技术不确定性观察池”，不应进入机器人关键算力的采购或重仓投资清单。** 团队与资本信号值得继续跟踪：公开报道将 CEO 杨滨描述为有超过二十年华为体系经验的芯片老兵，天使轮及 Pre-A 轮也获得多家财务、政府和产业资本参与。[S2](https://news.qq.com/rain/a/20260417A078JY00) [S3](https://www.leiphone.com/category/chips/AGaAOgr50XhElaxq.html) 但芯片投资的关键风险恰发生在“FPGA 可跑”之后：产品定义、编译器、后端、投片、封装、板卡、驱动、客户 workload、交付和回款缺一不可。公开报道称其计划于 **2027 年上半年投片**，这意味着截止日尚无回片，更不可能已有独立量产性能或可靠性证据。[S4](https://www.sohu.com/a/1012146983_114984)

**并购判断：当前不建议整体并购，也不建议以排他方式锁定。** 对未投片团队进行整体并购，实际买到的是创始团队、路线图与潜在 IP，而不是已验证产品；价格发现、核心员工留存、IP 归属和第一个 chip 的成败高度耦合。更合理的动作是建立技术交流/联合 benchmark 权利，必要时参与带有里程碑、反稀释与 IP 使用边界的少数股权融资；要等到 FPGA、仿真器、编译器及首硅在我方机器人模型上通过验收，再讨论更深绑定。

**研究边界。** 公开检索未发现可核验的公司官网产品页、SDK、GitHub 组织、芯片 datasheet、论文、专利清单、客户公告或审计财务报告。因此，所有“LPU+ 5—10 倍速度”“10 倍能效”“云边端同一架构”“首个国产 LPU”等均属于公司/融资新闻的宣称，不能作为投资模型的输入。[S2](https://news.qq.com/rain/a/20260417A078JY00) 本报告会解释该路线理论上解决什么问题，同时明确它在 Transformer、MoE、VLA 和机器人实时系统中可能失败在哪里。

## 纵向分析：从通信基带式数据流经验，押注 Agent 推理的下一段曲线

### 1. 成立前的判断：不是“再做一张 GPU”，而是从推理链条倒推硬件

元川微成立的市场窗口有两层。第一层是 AI 基础设施从预训练峰值算力向推理服务成本、首 token 延迟、token 间抖动和并发吞吐迁移。第二层是 Agent 工作负载把一次对话拆成检索、工具调用、规划、验证和重试等多次模型调用：对终端用户而言，慢的往往不是一段矩阵乘，而是每一段排队、KV cache、数据搬运和调度累积的尾延迟。雷峰网对杨滨的专访将其路线概括为“只做推理且只做最快的推理”，这一句是创始人战略主张，不是市场结果。[S3](https://www.leiphone.com/category/chips/AGaAOgr50XhElaxq.html)

杨滨的背景为路线提供了可理解性，但不应被浪漫化。公开媒体及企业信息平台称，他曾于 **2008 年赴美组建华为处理器团队**，于 **2012 年回国主导华为无线基带算法与芯片业务**；法定主体为杭州元川微科技有限公司，成立日为 **2025-09-23**，法定代表人为杨滨。[S1](https://aiqicha.baidu.com/company_detail_61717401658964) [S2](https://news.qq.com/rain/a/20260417A078JY00) 这类经历与硬件流水、固定资源调度、低延迟信号处理在工程方法上存在关联，却**不能**证明 LLM 推理芯片一定会成功：通信基带的算法图更固定、标准更稳定，而现代 LLM/VLM/MoE 的结构、上下文长度、量化方案和服务策略变化更快。

按公开报道，团队的 CTO 为“孙博士”，有 GPGPU/GPU/DSP 等高性能计算架构经历，首席软件工程师“Will 博士”有编译器、EDA 和异构系统软件经验；公司没有在可公开核验材料中提供两人的全名、履历、持股、前雇主授权边界或完整核心团队名册。[S3](https://www.leiphone.com/category/chips/AGaAOgr50XhElaxq.html) 因此尽调时必须把“有经验的团队”拆成可验证的问题：谁负责 architecture、RTL、DFT、physical design、compiler、runtime、firmware、board、量产质量和客户支持？核心人员是否全职？历史项目与本项目 IP 是否完全隔离？

### 2. 公司成立与最早融资（2025-09—2026-01）：先把路线和团队变成可融资主体

法定登记显示公司于 **2025-09-23** 成立，经营范围包含软件开发、集成电路设计及芯片产品销售等通用表述。[S1](https://aiqicha.baidu.com/company_detail_61717401658964) 这种登记能够确认主体与法定代表人，却不能用来证明已有芯片销售：新成立芯片设计公司通常必须先完成架构、前端、验证和融资，才可能进入流片/产品收入。

公开聚合资料称公司在 **2026-01** 完成近/数亿元天使融资，但可直接阅读的较完整融资新闻是其后 **2026-04-17** 的“数亿元天使轮系列融资”披露。该报道列出东方嘉富、元禾原点、峰瑞资本、源来资本、中芯聚源、深创投等“联合投资与追投”，并称浙江省科创投、杭州润苗基金关注支持，星宸科技和智微智能持续加注。[S2](https://news.qq.com/rain/a/20260417A078JY00) 这份来源不是公司审计文件，也没有给出每一主体的签约金额、首投/跟投、股权比例、交割日或优先权，因此只能作为 L3 融资线索；不能把所有列名机构自动写为直接股东，更不能从“产业资本”推导出订单。

天使轮资金用途被报道为首代 LPU+ 推理芯片的研发与量产。[S2](https://news.qq.com/rain/a/20260417A078JY00) 这正说明公司所处阶段：资本准备支持流片和工程化，不能说明已经具备量产供应。对于硬科技标的，融资金额最多证明有人愿意承担早期风险；它不证明综合性能、良率、软件生态或商业回报。

### 3. 架构定型和 FPGA 验证（2026-04）：LPU+ 的承诺与真正的技术难题

元川微把路线命名为 **LPU+**。按照公司融资新闻的说法，三个“基因”是：扁平化的大 SRAM 与计算单元连接、确定性硬件数据流、编译期静态调度；“+”指向为 LLM、多模态和 MoE 做的底层改动。[S2](https://news.qq.com/rain/a/20260417A078JY00) 其机制可用一个不那么营销化的方式理解：将计算图拆成带有明确数据依赖的时间—空间计划，编译器在运行前决定数据何时进入哪块 SRAM、哪个计算单元何时执行，尽量避免运行时的 cache miss、仲裁与动态调度。

这种设计有真实的理论价值。GPU 为了应付各种模型、图形/计算任务和动态并发，需要复杂的缓存层级、调度器和通用指令路径；固定推理图若能被完整编排，确实可能以更少的控制开销获得稳定的延迟。Groq 对其 Tensor Streaming Processor 的官方说明也强调静态调度、确定性执行和编译器映射，说明“硬件数据流＋编译器”不是凭空造出的概念。[S5](https://groq.com/architecture/) [S6](https://docs.groq.com/)

但三项承诺恰好也是三项产品风险。**第一，大 SRAM 并不等于大模型都装得下。** 权重、激活和 KV cache 在模型规模、上下文长度和 batch 提高时仍会迅速超过片上容量，最终必须跨芯片、访问外部内存或做分块，这时系统带宽、互连、编译器切分和尾延迟决定效果。**第二，静态调度对静态图友好，对 MoE 路由、可变长度请求、动态批处理、工具调用和多租户服务更难。** 若把所有可能性预留，资源利用率下降；若不预留，运行时就不得不回到动态处理。**第三，编译器是产品而不是附属工具。** 它必须在正确性、算子覆盖、内存规划、量化精度、调试可观测性和编译速度之间取舍；任何一个失败，都能使优秀硬件在真实模型上无用。

公司称已完成自研架构 FPGA 验证，性能指标达到设计预期，并计划让编译器在回片前借助仿真器验证优化。[S2](https://news.qq.com/rain/a/20260417A078JY00) 这是必要的正面进展，却还不是性能结论。FPGA 的频率、存储层次、板级网络、功耗、时序收敛、实际封装和量产 silicon 与 ASIC 不同；“设计预期”缺少公开模型、精度、输入输出长度、并发、温度、功耗和对照物，无法复现。正确的投资表述应是“已完成早期原型验证”，而不是“芯片性能已被验证”。

### 4. 天使轮系列与产品定义（2026-04—2026-07）：资本补齐不等于客户验证

2026-04 的融资新闻称元川微将在产业投资方协同下形成产品路标，并拓展云厂商、算力中心等合作。[S2](https://news.qq.com/rain/a/20260417A078JY00) 2026-07 的雷峰网报道进一步称，公司完成 **Pre-A 数亿元**融资，由 IDG 资本领投，孚腾资本、九坤创投、尚颀资本、顺禧基金、徐汇科创投参与；报道也称这是公司当年“第四轮融资”。[S3](https://www.leiphone.com/category/chips/AGaAOgr50XhElaxq.html) 由于没有股权登记、公司公告或投资方公告可交叉确认，“第四轮”与投资方清单仍标为 L3。

这轮钱投向 LPU+ 芯片、软件生态和产品工程化。从研发管理角度，它标志着团队已从架构证明走向产品定义：要决定制程、die 面积、SRAM 容量、封装、IO、板卡、散热、网卡/互连、主机接口、编译器语言和 SDK 表面。每一个选择都会决定客户是谁。若客户是云端 token 服务，优先级是每秒 token、首 token/p99、并发、集群网络和可运维性；若客户是机器人，优先级变成每瓦 token、尺寸、热、振动、摄像头/传感器接口、实时控制与断网降级。一个“云边端同一架构”可以共享编译器思想，未必能共享同一颗 die、封装或商业模式。

公司对外表示正与多家产业客户和云厂商进行产品验证/合作。[S3](https://www.leiphone.com/category/chips/AGaAOgr50XhElaxq.html) 这是存在需求访谈或原型合作的正面线索；反证是：未披露客户名称、产品型号、付费金额、验证通过指标、POC 时长、design win、订单、供货协议或回款。因此必须按“**正在验证，不等于客户；客户，不等于订单；订单，不等于收入**”记录。对想抢先绑定的机器人公司，最有价值的是在这一阶段争取把自己的多模态/控制 workload 写进产品定义，而不是接受单方发布会 benchmark。

### 5. 截止日状态：尚未投片，最关键的一年尚未开始

可阅读的报道称元川微计划 **2027 年上半年完成投片**。[S4](https://www.sohu.com/a/1012146983_114984) 该来源页面标示其内容为基于第三方数据生成，可信度弱于公司/监管文件，所以日期应视为公司计划而不是可执行承诺。即使计划不变，投片后仍有常见的时间和风险链：晶圆制造、封装、回片、bring-up、板卡、硅后调试、PVT、客户模型迁移、量产认证与供货；任何一环都可能改变成本、性能和交付期。

截至 2026-08-06，未检索到首代 LPU+ 的公开芯片型号、节点、TOPS/TFLOPS、SRAM/HBM 容量、TDP、单卡/单机/集群规格、SDK 下载、许可、实际客户、收入或独立评测。这个“空白”不是负面结论，而是公司处于实际阶段的边界。它同时决定了本报告的机器人建议：可作为联合定义和未来实验对象，不应作为 2026—2027 机器人量产 BOM 或核心在线推理的唯一依赖。

## 横向分析：LPU 是一条真实路线，不是一张自动获胜的通行证

### 竞争场景与比较框架

元川微瞄准的并非传统“国产 GPU 替代”一条赛道，而是低时延推理的专用架构竞争。最相近的是 Groq 的编译器驱动流式处理；Cerebras 的大晶圆与内存带宽路线、SambaNova 的数据流 RDU、d-Matrix 的数字 in-memory compute 则代表不同的“避开 GPU 通用性成本”的答案；NVIDIA 依然是客户评估一切可用性、框架生态和集群交付时的基准。元川微没有可公开规格，因此下表不是参数胜负表，而是“需要证明什么”的对照表。

| 玩家 | 已公开路线/商业状态 | 用户为什么会选择它 | 元川微相对位置与必须证伪点 |
|---|---|---|---|
| Groq | Tensor Streaming Processor、编译器和 GroqCloud；有公开 API/文档。 | 追求 token 流输出与确定性时延，能直接试用云服务。 | 技术哲学最接近；元川微尚无 silicon/API，不能以“国产 Groq”替代实际比较。[S5](https://groq.com/architecture/) [S6](https://docs.groq.com/) |
| NVIDIA | GPU＋CUDA＋TensorRT-LLM、从单卡到系统的生态。 | 模型覆盖、开发者、工具、服务商与多租户运维。 | LPU 要在特定 workload 上以更低成本/延迟胜出，但不能忽略 CUDA 迁移、集群和供应服务成本。[S7](https://nvidia.github.io/TensorRT-LLM/) |
| Cerebras | Wafer-Scale Engine 和推理服务。 | 极大单芯片 SRAM/带宽、减少切分通信，且已有服务入口。 | 证明“大 SRAM”可有价值；元川微需说明更小、更低成本 LPU+ 在模型/批量上的边界。[S8](https://www.cerebras.ai/product-system) |
| SambaNova | Dataflow 架构 RDU、DataScale 与企业 AI 系统。 | 希望购买面向模型执行而非单卡的整机/软件方案。 | 证明数据流商业化要求系统软件和客户交付；元川微目前未公开系统级产品。[S9](https://sambanova.ai/) |
| d-Matrix | Corsair 推理加速器，强调数字 in-memory compute 和推理效率。 | 数据中心推理的内存带宽/能效优化。 | 与 LPU 争夺同一“搬数据成本”问题，但采用不同硬件路径；元川微必须拿出 TCO 和精度证据。[S10](https://www.d-matrix.ai/products/) |

### 1. Groq：最合适的技术类比，也是最危险的估值捷径

Groq 的官方资料将其架构描述为由编译器安排的数据流式执行，强调低延迟和确定性；它同时提供开发者文档、API 和云服务。[S5](https://groq.com/architecture/) [S6](https://docs.groq.com/) 这让用户可以不先购买芯片，而先用同一模型/提示词检查输出 token 速度、API 兼容、限制、速率和稳定性。对于一家推理公司来说，这种可试用性也是产品的一部分。

元川微承认 LPU 的硬流水、时空编译器和大带宽存储与 Groq 有共同问题意识，但宣称自己的 LPU+ 从 Transformer/MoE/多模态时代出发而非复刻旧架构。[S3](https://www.leiphone.com/category/chips/AGaAOgr50XhElaxq.html) 这个主张有合理性：早期模型与今天的 MoE 路由、长上下文和工具调用不同。但它还没有回答更难的问题——MoE 的 token 到专家映射是动态的，服务端的 batch 组合和上下文长度也在变化；如果静态图无法吸收这些动态性，运行时效率会迅速回落。真正的对比不应是“都叫 LPU”，而是同一模型、相同精度、固定与混合请求分布下的 p50/p99、tokens/J、tokens/元、首 token、编译时间和重试率。

**开发者反馈差异。** Groq 有公开文档、快速开始和 API 错误说明，开发者可以留下可观察行为；元川微截止日未见公开 SDK、仓库或文档，因而没有可评估的独立开发者口碑。这不是“社区很差”，而是“尚未形成可供外部检查的社区证据”。投资尽调应把 SDK alpha、compiler error dump、模型支持矩阵和至少三家非投资方用户的 POC 日志列为前置条件。

### 2. NVIDIA：专用芯片真正的竞争对手是“总体工程成本”

NVIDIA TensorRT-LLM 的公开文档展示了从模型优化、量化、KV cache 管理到 serving 的软件层；它的护城河不是仅一项矩阵性能，而是框架、算子、模型、调试、社区、整机和云服务组合。[S7](https://nvidia.github.io/TensorRT-LLM/) 元川微以“推理相较训练对既有软件生态依赖更低”为创业机会的说法，方向上只对一半：固定模型、固定 batch 的离线推理确实较容易换芯片；但 Agent、VLM 和机器人是软件变动很快的系统，依赖的不是训练框架本身，而是推理框架、量化、图像/音频预处理、通信和可观测性。

因此，元川微即使在某种固定模型上有 5 倍速度，也未必在客户账上胜过 GPU；必须把迁移工程师月数、模型升级周期、并发利用率、服务中断、备件和二次开发一起计入 TCO。反过来，若某个机器人或边缘产品模型长期冻结、成本/功耗极敏感且实时性可被量化，专用架构有机会绕开 CUDA 的普适性溢价。赢面来自**有选择地缩窄问题**，而不是从第一个产品就覆盖一切云边端工作负载。

### 3. Cerebras：大存储路线说明“搬数据”是真问题，也说明系统边界很硬

Cerebras 公开销售的 wafer-scale 系统把超大规模片上计算和内存带宽作为差异化能力，并以系统/服务而非裸 IP 交付。[S8](https://www.cerebras.ai/product-system) 这是元川微“把芯片面积更多留给 SRAM”的观点最好的旁证：在推理中，权重与激活搬运常常比峰值乘加更限制性能。

但 Cerebras 的例子也提供反证。大容量片上存储并不自动消除模型规模、系统网络、功耗和可运维性问题；商业客户仍需要完整的编译器、模型支持和服务。元川微若主张不依赖先进制程/高端 IP，应说明首代芯片的 SRAM 容量、SRAM 宏来源、良率、外部内存/互连方案和模型分片策略。当前没有公开数据，故无法判断其会落入“SRAM 很大但装不下目标模型”，还是“SRAM/外存协同足以覆盖目标 token 负载”的哪一侧。

### 4. SambaNova 与 d-Matrix：专用推理不是芯片竞赛，而是产品交付竞赛

SambaNova 用数据流路线交付企业 AI 系统，d-Matrix 则以数字 in-memory compute 优化数据中心推理。[S9](https://sambanova.ai/) [S10](https://www.d-matrix.ai/products/) 两者提醒投资人：客户不会为“架构名称”付款，而会为在特定模型、精度、吞吐、延迟、功耗、可用性和采购条件下完成服务付费。

元川微的报告材料中尚没有板卡、服务器、云服务、驱动、模型仓库或企业支持承诺。短期内，这不是劣势本身——早期公司本来应该集中在首硅和编译器——但它限制了其可被认定为“推理基础设施”的程度。若 2027 年回片后仍只有硬件 benchmark 而没有可重复的模型/服务层，客户很可能选择已经能交付系统的 GPU、Cerebras、SambaNova、d-Matrix 或国产 GPU/NPU 方案。

## 横纵交汇：一支“懂硬流水”的团队，能否跨过模型动态性这道河

元川微最有意义的历史选择，是从通信/处理器工程经验出发，不把 GPU 当作唯一正确形式，而把 Agent 推理的末端体验拆成数据流、内存、调度和 QoS 问题。它成立不久便获得数亿元天使轮和 Pre-A 资本支持，说明资本市场认可“低延迟、确定性、效率”的问题存在。[S2](https://news.qq.com/rain/a/20260417A078JY00) [S3](https://www.leiphone.com/category/chips/AGaAOgr50XhElaxq.html)

历史同时塑造了最危险的偏见：无线基带/固定数据流的成功，会让团队自然相信更多事情能在编译期决定；可 Agent、MoE、VLA、机器人传感器和多租户服务恰恰充满动态性。最初的架构优点若不能容纳这些变化，就会成为今天的包袱。反过来，如果时空编译器能将动态问题分层——固定算子段静态流水，稀疏/路由/服务层保留受控的动态机制——LPU+ 才有可能不只是“中国版 Groq”的营销比喻。

这也是它与机器人公司的潜在交点。机器人本体并不需要把所有模型都放到专用硬件上：视觉前处理、固定检测/跟踪、低层策略和安全监控高度周期性，可能适合确定性路径；语言规划、开放世界 VLM、开发调试和模型频繁升级，则应保留 GPU/CPU/可重构层。元川微若愿意接受这种分层，而不是宣称一芯云边端全覆盖，才可能找到第一批真实产品场景。

### 三个未来剧本

| 剧本 | 触发逻辑 | 对公司意味着什么 | 对人形机器人公司的行动 |
|---|---|---|---|
| 最可能：首硅推进、先锁定窄场景 | 2027 年前后按计划投片；固定 LLM/视觉/Agent 子任务获得 FPGA/仿真器和早期 silicon 数据；软件仍在补齐。 | 获得首批 POC 和产业客户，但尚无法直接挑战 GPU 通用性；估值依旧主要由团队和里程碑驱动。 | 保持技术交流，提供匿名/脱敏 workload 作编译器测试；不放入量产 BOM。 |

## 面向人形机器人公司的策略建议

### 工作负载岗位：把训练、推理、数据闭环拆开

**训练：不匹配。** LPU+ 的公开目标是实时推理，未披露训练反向传播、optimizer、分布式通信、HBM、训练框架或集群案例。[S2](https://news.qq.com/rain/a/20260417A078JY00) 人形机器人 VLA/WAM/世界模型的预训练、微调与仿真训练仍应由成熟 GPU 或经过独立验证的数据中心加速平台承担。

**在线推理：理论上相关，现实上尚不可采购。** 未来可测试的机器人子工作负载包括固定视觉检测、姿态/轨迹模型、事件触发安全网络、短上下文多模态分类和边缘 token 生成；但公司未投片、无公开器件，因此 2026—2027 只能共同定义 workload，不能承诺延迟、功耗、成本或供货。不要把 Agent 的云端 token 延迟直接映射为机器人控制环延迟：控制需要硬实时、安全状态机、传感器时间同步和失败降级。

**数据闭环：可能贡献筛选/压缩，不代替数据基础设施。** 若未来芯片能在边缘以确定性功耗运行固定感知模型，可做采集数据的事件筛选、质量评分、压缩和隐私前处理，降低回传带宽；但它不提供标注、数据版本、仿真、训练调度或治理。协同价值应以“可用帧比例、误筛率、GB/小时、瓦时/小时”测量，而不是以“LPU 适合具身智能”概括。

**供应安全：目前不可判断。** 中国主体和产业投资方只是正面线索；制程、代工、SRAM 宏、EDA、封测、板卡、电源、网络和驱动供应均未披露。直到给出 BOM、第二来源、产能预留、生命周期与合规声明前，不应将其视为“国产安全供应”。

### 投资、并购与合作矩阵

| 选项 | 当前建议 | 逻辑 | 触发条件与否决条件 |
|---|---|---|---|
| 采购 | **不建议** | 没有可采购芯片、SDK、价格、交期或服务 SLA。 | 仅在首硅板卡、SDK、量产保障和独立 benchmark 出现后进入 RFI。 |
| 联合 POC/产品定义 | **建议有限开展** | 早期可把机器人多摄/VLM/控制分层 workload 写进编译器/芯片需求，获得信息权。 | 必须签署数据、模型、代码和成果 IP 边界；不得提供可反向工程的核心权重/数据。 |
| 战略投资 | **观察，里程碑后小额介入** | 团队和数据流路线有期权价值，技术/投片/市场不确定性极高。 | 前提：FPGA/仿真器可复现、关键团队确认、投片预算/供应链可审查、独立客户 POC；否则不投。 |
| 整体并购 | **不建议** | 未投片团队价值高度依赖人员和未来产品，难以估值与整合。 | 仅在首代 IP、编译器、客户和核心团队均可独立验证，且我方有明确自研芯片需求时重估。 |
| 自研参照 | **可作为“数据流＋编译器”研究参照，不作为立项依据** | 提醒我方端侧芯片不能只看 NPU MAC，也要看内存与编译器。 | 自研需独立满足规模、团队、软件、供应链和量产 ROI 门槛。 |

### 必须完成的下一步验证

1. **架构白盒会**：要求提供数据流 ISA/IR、SRAM 层级、外存/互连、动态 shape/MoE/长上下文的处理方法、回退路径和 PPA 预算；“硬流水”不能只用框图回答。
2. **编译器验收先于芯片验收**：以我方一个固定视觉模型、一个 VLM、一个 MoE/Agent 子任务测试编译成功率、精度损失、编译时间、memory plan、调试可见性和错误定位；所有数值必须可重复。
3. **FPGA/仿真器基准**：同一模型版本、tokenizer、精度、prompt、输入长度、batch、并发与温度下，比较 GPU/现有 NPU；输出 TTFT、ITL、p50/p99、tokens/J、准确率、编译时间和重试率。
4. **首硅 gate**：回片后完成 bring-up、功耗、热、稳定性、板卡、驱动、72 小时/多周压力测试后，才谈小批 POC；禁止用 FPGA 宣称量产规格。
5. **商业/供应尽调**：核对四轮融资的 primary/secondary、实际 cap table、产业股东与客户合同；索取投片节点、foundry/OSAT、SRAM/EDA/IP 风险、现金 runway、关键人锁定和 IP 来源声明。

## 产业链分类复核

**唯一主二级分类：1.4 其他 AI 芯片架构（LPU）。**

**理由：**元川微宣称的收入/价值创造中心是面向实时推理的自研 LPU+ 专用架构，核心差异是硬数据流、片上 SRAM 与时空编译器，而非 GPGPU 的通用并行计算、TPU/NPU 的既有 ASIC 分类或 Scale-up/Scale-out 通信产品。[S2](https://news.qq.com/rain/a/20260417A078JY00) 依据分类规则，LPU 被明确列为 1.4 的示例，且公司没有已商业化的其他主营能力足以改变主标签。因此总表当前的 **1.4 其他 AI 芯片架构**方向正确；可将说明细化为“LPU+ 数据流实时推理芯片（未投片/性能待核验）”。

**可选次分类：不设置。** 时空编译器可能是未来护城河，但现有证据只支持它是服务自家 LPU+ 的内部工具链，而不支持其独立向第三方销售或跨厂商提供“2.1 加速计算平台”/“2.2 AI 算子开发、迁移与适配”价值。把软件工具链列为次分类会把路线图当成已商业化业务；应等 SDK、客户、独立收入或跨硬件适配证据出现后再复核。
