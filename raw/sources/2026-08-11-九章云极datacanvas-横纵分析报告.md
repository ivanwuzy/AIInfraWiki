# 九章云极（DataCanvas）：从 AI 基础软件走向“AI 工厂”控制面的横纵分析报告

> 研究截止日：2026-08-11｜研究对象：北京九章云极科技股份有限公司（品牌：九章云极／DataCanvas）｜类型：智算云与异构算力管理平台｜建议主分类：**4.1 跨厂商训推算力调度平台（中等置信）**；本报告不设正式次分类。

## 一句话结论

九章云极真正值得研究的不是“是否又多卖了一种 GPU 云”，而是它正尝试把异构算力纳管、资源调度、容器／Slurm、训练环境、计量结算和 Token 服务做成同一控制面。这个方向恰好击中机器人公司面临的多芯片训练、弹性推理与成本归集问题；但公开证据仍主要来自公司产品页，尚不足以证明其调度软件已作为独立产品在第三方多厂商集群中规模化收费，也不足以证明客户名单、利用率和降本数字对应可审计订单。因此建议：**采购受控 PoC，保留战略观察权，暂缓股权投资和整体并购。**

## 研究边界与证据口径

本报告研究的是官网版权所列的**北京九章云极科技股份有限公司**，并把 DataCanvas、Alaya NeW Cloud、Alaya NeW OS、九章智算云、九章智算操作系统视为同一品牌／产品组合。[S1] 但 2025 年 12 月媒体仍报道“北京九章云极科技有限公司”发生工商变更、注册资本增至 4,884.691 万元。[S10] 公开资料不足以确认有限责任公司向股份有限公司的改制时间、两者的法律承继、各轮融资的签约主体和 IP／合同承接，故不能把品牌层的融资、合作或产品收入直接等同于目标股份公司的资产。

## 纵向分析：一条从基础软件到算力商品化的路径

### 2013—2020：以机器学习工程化与 AI 基础软件起家

公开报道将九章云极的成立时间置于 2013 年，早期产品叙事围绕 AutoML、AI 中间件、AI 基础软件和 DataPilot，而不是今天的 GPU 租赁或模型 API。[S11] 这段起源很重要：它解释了公司后来为何把“让更多开发者可使用算力与模型”理解为软件和工作流问题，而不只是一笔算力采购生意。

这种历史路径也带来约束。AutoML／开发平台时代积累的客户与交付经验并不自动转化为大模型集群运营能力；万卡训练、异构芯片适配、调度器可靠性和云服务 SLO 都是另一组更重的工程命题。公开材料尚未给出早期软件产品的留存、收入或技术资产如何迁移至 Alaya 产品线的可审计链条。

### 2021—2023：资本加速与“从算法平台到智算基础设施”的转折

2021 年 5 月，公司获报道为 3 亿元 C 轮融资，尚珹资本、赛富联合领投；2022 年有 C+ 轮，龙门投资领投、达泰资本和中关村发展集团等参与，金额未公开。[S10] 2023 年 10 月，36 氪与财联社均报道 D1 轮约 3 亿元，中电智慧基金、华民投、太平创新／太平资管等为参与方。[S10][S11]

这几轮资金与大模型周期重叠，产品叙事也从算法工具向 Alaya、DingoDB、模型与算力基础设施迁移。[S11] 这里的关键决策不是单纯“增加一朵云”，而是把过去的开发者入口延伸到算力供给和集群调度：一旦客户在同一平台上做环境、训练、资源配额和计费，公司有机会获得比短期 GPU 转售更高的迁移成本。反面是，云服务会将公司带入高资本开支、低毛利和区域项目交付的竞争。

### 2024—2025：Alaya NeW 组合把异构资源、训练与云服务捆在一起

官网现行产品体系以九章智算云 **Alaya NeW Cloud** 与九章智算操作系统 **Alaya NeW OS** 为核心。公司将 OS 描述为“大规模 AI 算力管理核心底层架构”及“AI 算力超级调度器”；AI Factory 页面进一步描述异构 GPU／NPU、多智算中心、跨地域调度、万卡集群和算电协同。[S1][S4] 这些说法直接支撑“公司在做异构训推调度”，但仍是厂商自述，未公开硬件支持矩阵、调度策略、故障恢复数据或独立客户的生产记录。

Cloud Container Infrastructure（CCI）则给出较具体的交付形态：虚拟／弹性容器集群、专属 Slurm 集群、AI Lab、极核训练、长时 GPU 容器、专属 GPU 集群和面向分布式训练任务的 GPU 智能调度。[S3] 它显示公司既有平台层，又有云服务层；然而公开资料未区分其中哪些是可单独许可的软件，哪些只能作为自营云的交付组件。这个边界决定了公司究竟是高粘性的控制面供应商，还是“工程能力较强的智算云”。

资本侧，财联社报道 2025 年 7 月赛富、中关村科学城、启辰星参与，9 月芜湖含元参与，12 月北京人工智能产业投资基金经工商变更入股；金额和各轮边界多数未披露。[S10] 2026 年 1 月投资界又报道北京信息产业发展投资基金、北京市人工智能产业投资基金联合领投、启辰星跟投的一轮战略融资，金额未披露。[S12] 两篇报道可能涉及相邻或同一交易的不同阶段；在取得工商档案和交割文件前，不能重复累计为两笔独立融资。

### 2026：从“调度算力”改写为“AI 工厂／Token 规模化交付”

2026 年的产品叙事有清晰转向。6 月的公司新闻提出 AI 工厂战略，强调从 DCU 到 Token 的产出与计量；随后上线 Token Plan，并称适配 GLM-5.2、提供标准化按需付费服务。[S7][S8] 这把过去偏技术的资源管理语言翻译成可被采购部门理解的产出单位：客户买的不只是 GPU 小时，而是模型调用与可核算的推理能力。

7 月版本迭代又披露智能队列调度、资源配额和开发工具，覆盖训练、推理、多模态与具身场景。[S5] 同月公司称其 DCU 与 Alaya OS 可覆盖异构芯片统一折算、计量／计价／结算及全域调度，并被列入工信部相关典型案例；该新闻并未给出独立主管部门文件或客户对账数据，因此只能理解为公司对入选及产品能力的陈述。[S6]

公司已把“算力租赁”与“软件控制面”绑得更紧。好处是，资源利用率、配额、容器、训练和结算的数据若真正沉淀在一个系统中，替换成本会提高；风险是 Token 服务又将其置于模型 API、推理云与大云厂商的价格竞争中。一个尚未公开回答的问题是：调度器能否跨出公司自己运营的云，成为客户私有／混合环境的控制面？

## 五类合作网络：不要把生态名单写成订单簿

### 投资方／股东

从已披露名单看，九章云极的资本网络兼有市场化 VC、地方产业资本与国资背景基金。[S10][S12] 这有利于区域智算中心和产业项目的资源协同，却不证明任何投资方仍为当前股东、拥有何种权利，或能带来经常性云服务采购。现行股权和各法人之间的控制关系是尽调优先项。

### 客户／订单

财联社报道提及三大运营商、考拉悠然、格灵深瞳、三维家等合作／客户叙事。[S10] 官网另称 CCI 已服务 200+ 企业／团队。[S3] 两者均没有披露合同金额、期限、验收、回款、资源量和是否为付费客户。报告将其定位为**候选客户线索**，不把它们写入已确认订单，也不以此推算 ARR。

### 产业与供应链合作

公司的可见产业角色更像“算力资源与软件控制面的集成者”：向上需要 GPU／NPU、数据中心、电力与网络资源；中间层提供容器、Slurm、调度及计量；向下交付训练、推理和 Token 服务。[S1][S3][S4] 官网对异构 GPU／NPU的描述不等于已确认与每个芯片厂商建立正式合作，更不等于拥有一个可审计的多厂商资源池。对供应安全而言，要逐项核实芯片来源、可用区域、资源所有权、排他／保底条款和网络跨域能力。

### 技术、科研与高校网络

2026 年公司报道与上海交通大学 WNM 的合作：九章云极为其提供核心算力支持并被称为生态伙伴，首席科学家缪旭参与相关活动。[S9] 这可以确认存在研究与算力支持关系；它不证明公司拥有模型 IP、取得独占授权，或形成商业客户收入。任何联合研发应进一步核验背景 IP、成果归属、开源许可证、数据边界和发表权。

## 横向分析：与谁竞争，客户究竟买什么

| 对照对象 | 主要产品形态 | 相对九章云极的差异 | 对机器人公司的启示 |
|---|---|---|---|
| 无问芯穹 | 多芯片资源池、训推优化、模型服务与端云协同 | 更强调芯片—模型的系统优化与多芯片池化；九章云极更强调云、调度、计量结算和 AI 工厂运营 | 两者均不能只比 GPU 单价，应使用同一模型、两类 XPU、同一 SLO 比较完成时间和总成本。 |
| 趋境科技 | 侧重推理跨 XPU 适配、推理服务与 PD 分离方向 | 趋境的价值锚点更靠近推理运行时；九章云极覆盖训练、容器、集群与算力经营，但可能更重项目交付 | 若瓶颈是在线机器人推理，应优先验推理稳定性；若瓶颈是训练资源治理，再评九章的控制面。 |
| AutoDL／并行科技等 GPU 云 | 按需 GPU、容器、科研／开发者云服务 | 产品边界清楚、采购简单；九章云极的差异必须由异构调度和计量结算的净收益证明 | 短期补算力可选通用云；九章只有在多资源池和组织级治理中跑出收益才值得更深绑定。 |
| 华为昇腾及大型云／运营商智算平台 | 芯片—编译—云服务或自有云—客户交付的一体化栈 | 大厂有采购规模、硬件生态、销售与运维优势；九章的机会是客户不愿锁定单一芯片／云时的中立控制层 | 验证它是否真能降低跨芯片迁移和调度成本，或只是把大厂能力再封装一层。 |

九章云极并不应与纯 Kubernetes 厂商做一维竞争比较。CCI 中的容器和 Slurm 说明其确实覆盖云原生／集群管理功能；但客户购买它的价值主张更接近“把多种算力变成可治理的训练、推理和 Token 产出”。[S3][S4] 这也是为什么其最强对手既包括异构调度平台，也包括 GPU 云、模型服务商和大云厂商。

横向的短板同样明显：无问芯穹等同类已将“多芯片池化”作为直接产品表述，推理专门厂商可在单一 SLO 上做得更深，大云则拥有资源、客户和硬件合作的规模优势。九章需要拿出第三方可复现的证据，证明它在异构集群上的作业排队、GPU 有效利用、故障恢复、模型迁移、计费准确性和单位 Token 成本能够同时改善；缺少这些，AI 工厂更容易停留在营销语言。

## 横纵交汇：早期软件基因正在成为机会，也可能成为包袱

从 AutoML／AI 中间件到 Alaya OS，再到 DCU 和 Token Plan，九章云极延续的是同一个问题：如何把复杂 AI 基础设施转成开发者与组织可以购买、调度和核算的服务。[S1][S7][S8][S11] 历史上的软件基因使其有理由重视调度、环境和计量，而不是只做裸金属租赁；2026 年把 DCU 和 Token 放在一起，则是试图把技术控制面变成财务控制面。

这条历史也决定了它今天的风险。产品面同时覆盖云、集群、训练、推理、模型服务和 AI 工厂，边界很宽。若各模块共享同一套资源画像、调度策略、计量账本和客户数据，宽度会形成迁移壁垒；若它们只是按项目拼接，宽度就会吞噬研发与交付资源。公开信息还不能裁决这两种解释。

| 剧本 | 演化路径 | 可观察触发器 | 我方动作 |
|---|---|---|---|
| 基准 | 在若干区域智算中心和企业客户中，把异构调度与 Token 计量做成续费服务 | 提供经审计合同、续费、硬件支持矩阵、SLA 与同模型跨 XPU benchmark | 采购可退出 PoC，并保留第二供应商。 |
| 上行 | 成为国产异构资源的控制面，DCU 计量被合作方采纳，软件能部署到客户私有／混合集群 | 第三方集群部署、独立性能复测、软件许可收入与正向毛利、客户迁移案例 | 在 IP、收入和技术门槛均核验后考虑小比例战略入股。 |
| 下行 | Token／云服务价格战压缩价值，调度器被大云和芯片生态下沉，项目收入难以续费 | 资源利用率、回款与续费走弱；芯片适配周期拉长；主体和资产边界仍不清 | 不做投资或整体并购，仅保留开源／标准接口与多云架构。 |

## 面向人形机器人公司的建议

### 采购与合作：可做 8—12 周双轨 PoC

建议以非关键项目启动、可单方退出，且不承诺独家或最低消费。

1. **异构训练线**：用同一视觉—语言—动作（VLA）或视觉模型，在至少两类 XPU 与一个现有云环境中重复训练／微调；记录收敛、精度、排队时间、实际 GPU 利用、失败恢复、工程人天和每次有效实验成本。
2. **推理与计量线**：在固定上下文、并发和 SLO 下比较端侧／云端推理的 TTFT、TPOT、goodput、单位 Token 成本、限流、计费账单与故障降级；不采用厂商内部测试数字替代我方测试。[S13]
3. **治理验收线**：要求交付硬件支持矩阵、API、日志、权限隔离、数据删除、模型权重和业务数据不出域安排；验证客户能否导出作业定义、指标和账单，避免形成不可迁移的资源黑箱。

成功条件应包括：模型精度／任务成功率不劣化；预先定义的完成时间或总成本优于对照组；作业和账单可审计；任一芯片／区域故障可恢复。若只展示“设备利用率”而没有作业成功率和总工程成本，则不能判为成功。

### 投资：先核四个硬条件

在估值讨论之前，至少取得：（1）股份公司与有限公司的完整承继、股权和 IP 链；（2）前十大客户的合同、回款、续费和毛利拆分；（3）软件许可、云服务、项目集成与 Token 服务的收入拆分；（4）两类芯片、第三方集群、我方模型上的独立复测。满足后可考虑少数股权战略投资，优先换取透明的技术路线、联合验证和非排他采购权，而不是用投资代替产品验收。

### 并购与自研：暂不建议整体并购，控制面保留自研接口

目前不建议整体并购：产品和主体边界、客户收入及 IP 承接尚未充分公开，且云资源业务会带来资产、合规和合同负担。若 PoC 成功，较可行的是对调度、计量、异构适配或训练平台团队建立能力合作／小范围人才与技术收购选项，而不是买入全部云服务资产。

我方应自研并保留跨云作业描述、模型／数据元数据、成本账本和 SLO 指标接口，避免把机器人训练数据闭环、部署控制和供应商切换权外包。九章云极可成为候选控制面，但不应成为唯一控制面。

## 产业链分类复核（按当前分类规则）

**主分类：4.1 跨厂商训推算力调度平台（中等置信）。** Alaya NeW OS 被公司明确称为 AI 算力超级调度器；官网公开描述异构 GPU／NPU、多智算中心、跨地域训推调度，CCI 则展示容器、Slurm 与 GPU 智能调度，2026 年又补充队列和配额管理。[S1][S3][S4][S5] 这些能力最贴近跨资源池的训练／推理算力调度，也比单纯“云服务”更能解释其技术差异化。置信度只能为中等，因为证据主要是自述，且公开资料尚未证明在第三方多厂商集群中作为独立软件的收入和可移植性。

**不设正式次分类 3.6 集群管理软件。** CCI 的虚拟集群、Slurm、容器与管理能力是真实产品线索。[S3] 但没有证据显示其以独立集群管理软件为主要价值承载或单独售卖；当前更像主平台随云服务交付的组件。将其列为正式副类会夸大商业边界。

**不设正式次分类 4.4 多厂商算力池。** “异构 GPU／NPU”“多智算中心”和跨地域调度证明多资源能力方向，[S4] 但未证明可商业化调度的外部多厂商资产池、资源产权、跨云可用性或收入。异构并不自动等于已运营的多厂商算力池。

**不设正式次分类 5.3 分布式训练工具。** HyperTrain／极核训练和多机多卡一键启动提供了分布式训练线索。[S2][S3] 但通信栈、断点恢复、有效吞吐、模型规模、独立基准与软件收入均未公开，且能力看起来绑定云服务交付。待有独立价值承载证据后再升级为副类。

若不受任务清单候选范围限制，当前商业承载也可能被归入 **8 其他（智算云／算力服务）**；但在 `4.1／3.6／4.4／5.3` 四项中，4.1 最能概括其声明的核心技术优势，同时已在本节充分披露“云服务为主、独立软件待证”的边界。
