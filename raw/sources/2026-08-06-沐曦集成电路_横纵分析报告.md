# 沐曦集成电路（MetaX）横纵分析报告

> 研究截止：2026-08-06｜对象：公司/高性能通用 GPU 平台｜证据等级：L1=上市公司公告、年报、公司一手文档；L2=具名媒体/合作方；L3=开源社区或独立测试；L4=传闻或不可复核转述。  
> 研究问题：沐曦的训推 GPU、互连和 MXMACA 软件生态是否足以成为人形机器人训练、仿真和推理供应安全的战略选项？

## 一句话定义

沐曦集成电路（上海）股份有限公司（MetaX，科创板 688802）是一家从 2020 年成立起即押注云端通用 GPU 的上市公司：以曦云 C 系列覆盖训练/推理/科学计算、以 MetaXLink 做多卡互连、以 MXMACA 尝试承接 CUDA 应用迁移；它已形成真实出货和千卡集群商业化证据，但仍处于高研发投入、持续亏损和供应链/软件生态追赶并存的扩张阶段。

## 面向人形机器人公司的结论先行

| 维度 | 判断 | 建议动作 | 进入下一阶段的触发条件 |
|---|---|---|---|
| 投资 | **不建议以一级市场方式新增财务投资**：公司已于 2025-12-17 上市，市场价格、流动性与锁定期应按二级市场框架评估。其 2025 年营收 16.44 亿元、累计销量超 5.5 万颗是实质去风险信号，但归母净亏损仍为 7.89 亿元。 | 建立跟踪仓位/战略研究关系，而非用“国产替代”给予无条件溢价。 | 连续多个报告期的毛利、回款、存货周转和 C600 量产爬坡符合预期；估值与可比公司/替代采购 TCO 有安全边际。 |
| 并购 | **不建议整体并购。** 上市主体、规模化股东和完整软硬件团队使控制权交易成本极高，也不匹配我们对 GPU 的当前需求。 | 不排除围绕机器人编译器、算子、应用支持的小型合作/人才项目；不以并购获得训练 GPU 供应。 | 只有出现可剥离、与机器人软件高度匹配且 IP/人员可留存的业务单元时再做资产级评估。 |
| 战略协同 | **优先级高于砺算等图形优先厂商，但应先 POC。** C500/C600 与 MXMACA、MetaXLink 的公开定位直接覆盖训练和分布式推理；曦彩 G 系列仍在研，数字孪生图形任务不应假定已可交付。 | 采购少量 C500/C600 条件下测试：VLA/VLM 后训练、仿真数据管线、模型量化推理、2–128 卡通信、故障恢复和混合 GPU 调度。 | 与 NVIDIA/AMD/摩尔线程在同一机器人模型、数据、精度、并行策略和功耗下，达到预设吞吐、收敛、稳定性、迁移工时和成本门槛。 |
| 自研决策 | 沐曦的价值主要在训练/推理 GPU 平台；它不能证明本公司应复制一颗云端 GPGPU。 | 将其作为“采购/合作”的高门槛参照物：比较 GPU IP、HBM、互连、编译器和生态的全栈投入。 | 自研只有在本公司负载足够稳定、量足够大、软件和供应链团队齐备、相对采购有可量化优势时成立。 |

## 纵向分析：五年从团队集结到上市与规模化交付

### 创立：从 AMD 背景的整建制团队切入云端通用 GPU（2020）

沐曦于 **2020-09** 在上海成立。创始人陈维良任董事长、总经理，联合创始人彭莉任硬件架构负责人、杨建任软件架构负责人；公司 2025 年年报称三人具备 GPU 设计、量产和软件生态经历，研发团队 675 人、占员工 73%。[2025 年报，L1](https://static.cninfo.com.cn/finalpage/2026-03-27/1225036092.PDF) 创业的核心选择是通用 GPU 而非单一 ASIC：从一开始同时覆盖 AI 训练/推理、通用/科学计算及未来图形渲染，并将软件栈当作产品本体的一部分。

这种定位带来一条清晰的因果链。GPU 的价值不仅由芯片峰值决定，还由 HBM、卡间互连、集群通信、编译器、算子库和框架迁移共同决定；沐曦随后把 C 系列、MetaXLink 和 MXMACA 绑定为同一平台。它因此可以服务持续变化的模型负载，却也必须与 CUDA 的十余年工具、开发者和故障知识库正面竞争。

### 产品演进：先推理，再训推与互连，再走向国产供应链（2021—2026）

沐曦按场景分三线产品：曦思 N 系列面向云端/边端推理和视频处理；曦云 C500/C600 面向训练、推理和科学计算；曦彩 G100 面向云游戏、数字孪生、云渲染和专业制图，**仍处于研发中**。[年报产品表，L1](https://static.cninfo.com.cn/finalpage/2026-03-27/1225036092.PDF) 因而不能因官网已列“曦彩”而将其当成机器人仿真可采购卡。

C 系列的关键不只是单卡。年报称 MetaXLink 支持 2–128 卡拓扑和超节点；MXMACA 是完整工具链并宣称高度兼容 CUDA 生态。公司声称截至 2026-03-13，软件栈有 30 万注册用户、5591 万 API 调用、16 万文件下载，支持 6000 余 CUDA 应用和 1000 余模型。这些是强信号但仍是公司统计口径，需在 POC 用具体版本、提交记录和可运行模型验证。[年报，L1](https://static.cninfo.com.cn/finalpage/2026-03-27/1225036092.PDF)

2025-07-24，公司在 WAIC 发布曦云 C600，年报称其为“基于全国产工艺”的产品、带来算力/精度/HBM 技术升级，2025 年末风险量产，预计 2026 年上半年量产销售。这里必须区分：**风险量产与量产销售不是同一状态**；截至本报告日，尚应向公司索取实际良率、交付批次、HBM 来源与客户验收证明。[年报，L1](https://static.cninfo.com.cn/finalpage/2026-03-27/1225036092.PDF)

### 商业化：已越过“无产品”阶段，尚未越过盈利拐点

2025 年年报披露营业收入 **16.440855 亿元**，同比增长 121.26%；归母净利润 **-7.894463 亿元**，亏损同比收窄 43.97%；研发投入 10.273929 亿元、占营收 62.49%。截至 2025 年末，公司称 GPU 累计销量超过 55,000 颗、部署于 10 余个智算集群，覆盖国家人工智能公共算力平台、运营商平台和商业智算中心。[年报，L1](https://static.cninfo.com.cn/finalpage/2026-03-27/1225036092.PDF)

这组数字改变了沐曦的性质：它不再只是“将来能做 GPU”的项目，而是有规模出货的硬件/集成解决方案商；但亏损、62% 研发强度和 Fabless 供应链也说明其仍需靠产品更新和回款持续支撑。收入增长不能自动代表可持续利润，尤其当产品代际、晶圆/HBM、板卡和服务器集成均占用现金时。

### 用户/开发者回声：公开文档和社区是积极信号，独立生产证据仍少

与闭源交付的国产加速器相比，沐曦确有可观察的软件入口：MXMACA 公开社区、开发文档和软件下载页面；官方 GitHub 组织发布了 `gpuBenchmark` 等项目。[GitHub，L3](https://github.com/MetaX-MACA/gpuBenchmark) 这降低了验证门槛，也支持“软件栈并非仅宣传”这一判断。

但 GitHub 的仓库、issue、star 或官网注册数不能代替真实训练稳定性。公开可检索材料中，独立、可复现的 C500/C600 对 Llama/VLA 训练收敛、通信效率、长时故障率、容器调度与机器人仿真性能横评仍少于 NVIDIA 的公开资料；公司自测或合作方测试须明确标成 L1/L2。本次建议不使用“性能超过 H20”一类媒体标题作为投资结论。

## 横向分析：在云端 GPU 赛道的竞争位置

| 代表玩家 | 路线与用户选择理由 | 相对沐曦的位置 | 机器人公司应如何看待 |
|---|---|---|---|
| NVIDIA | CUDA、NVLink、DGX/网络/框架与大量开发者构成完整训练事实标准。 | 沐曦的 MXMACA 目标正是降低 CUDA 迁移成本，但兼容声明不是等同性证明。 | NVIDIA 是性能、可用性和工程效率基准，同时也是供给/合规风险暴露。 |
| AMD | Instinct/ROCm 以开放软件和数据中心 GPU 对抗 CUDA。 | AMD 是最贴近沐曦“硬件+开放软件生态”叙事的国际对照，但软件和供应规模仍有数量级差异。 | 以 ROCm、MXMACA 的具体框架/算子覆盖、迁移工时和集群运维进行盲测。 |
| 华为昇腾 | NPU+昇思生态，国产智算中心和政企采用广。 | 昇腾不是通用 GPU 路线，却是预算和国产训练项目最强替代方案之一。 | 若负载较稳定，NPU 可能有能效优势；若模型/算子快速变化，通用 GPU 的灵活性可能更重要。 |
| 摩尔线程 | 全功能 GPU 与 MUSA 软件栈，兼顾 AI、图形和数据中心。 | 与沐曦同为国产通用 GPU 的直接比较项；沐曦更明确强调 C 系列训练、互连和已披露规模化出货。 | 同一 VLA 后训练和推理实验中直接比较，而非按融资/上市热度选择。 |
| 壁仞科技 | 高端通用计算 GPU，面向数据中心训练/推理。 | 与沐曦争夺高端国产算力与供应链资源；二者都面临 CUDA 生态和先进供应链约束。 | 可作为高端训练替代方案，采购前重点核验实际供货、软件版本和服务能力。 |

沐曦的横向优势并不在“单点宣传跑分”，而在已经把**通用 GPU、C500/C600、2–128 卡互连、CUDA 迁移软件、集群交付**同时带到商业化。劣势同样清楚：NVIDIA 的生态深度、国际供应链和开发者存量仍无法由文档数量追平；国内玩家之间也会争夺有限的客户、HBM/封测、集成人和软件人才。


### 把五个竞争者拆开看：沐曦不是在同一条起跑线上竞赛

**NVIDIA：护城河是训练工作流，而不只是一张卡。** 对机器人团队，NVIDIA 的优势是从 PyTorch/JAX、CUDA kernel、NCCL、profiler 到机器人仿真/视觉框架的连续性；问题则是出口限制、获取周期与价格波动。沐曦最合理的比较方式不是宣传“替代 NVIDIA”，而是把一个已收敛的 VLA 后训练任务迁移到 MXMACA：代码修改量、缺失算子、数值一致性、每 token/每 step 成本、分布式 hang 的恢复时间，全部要同 NVIDIA 基线一起记录。只有这些指标成立，C500/C600 的国产供应安全才会转化为研发效率，而非新增运维负担。

**AMD：是最有启发性的“非 CUDA”参照。** ROCm 证明开放工具链可以进入高性能 AI，但也表明驱动、框架版本和 kernel 覆盖会决定用户体验。沐曦与 AMD 一样不能只销售峰值 FLOPS；其 MXMACA 若能把 CUDA 代码在有限改动下运行，便会缩短客户迁移期。反对证据是，沐曦目前没有像 ROCm 那样广泛的独立全球生态和社区维护者。因而“兼容 CUDA”应被拆为 API 编译、算子正确性、性能、分布式通信、debuggability 五个待验收层次，而不是一句二元结论。

**昇腾：是采购预算中的替代品，而非架构上的同类。** 昇腾 NPU 可在特定模型和政企集成场景中获得强生态支持；沐曦 GPU 的相对价值在于灵活的 GPU 指令/编程范式、已有 CUDA 工作负载的迁移以及多类科学计算。人形机器人模型处于快速迭代期，GPU 的通用性可能更有价值；如果模型结构、精度和部署形态稳定，NPU/ASIC 的成本或能效又可能胜出。因此本公司不应把“国产算力”当一个桶，而应在每个 VLA、世界模型和视觉推理负载上比较。

**摩尔线程：最直接的国产 GPU 可比对象。** 两家公司都要完成硬件、软件、生态和客户交付四重工程。区别在于沐曦的已披露重心更偏 C 系列云端训推、MetaXLink 与千卡集群，摩尔线程则长期维持全功能 GPU 的多场景产品叙事。用户最终不会因两家公司是否都“全栈”而选择，而会因特定模型能否准时跑完、驱动响应速度、可供卡数和服务器集成商是否可用而选择。应在同一机房、相同 CPU/网络、相同模型版本上做 A/B，而不可混用厂商峰值或不同测试脚本。

**壁仞：提醒沐曦高端训练市场的供给与软件挑战仍在。** 壁仞聚焦数据中心通用计算，其可替代性使得沐曦不能单靠“国产高端 GPU”获得长期溢价。反过来，沐曦已披露的累计销量、集群部署和公开文档，是相对容易审阅的产业化信号。对我方，两个对象都应通过硬件供货、软件升级、运维 SLA 和模型可复现性来评价；没有这些，融资规模或市场声量都不是机器人训练采购依据。

### 用户与开发者材料的可解释部分及其边界

沐曦的公开 C500 用户指南是一个有用但有限的工程信号：文档列出 x86/Arm、Ubuntu/CentOS/麒麟等兼容范围，包含 `mx-smi`、`mx-report`、日志导出、容器和虚拟化章节，说明产品已面向管理员而非只面向演示部署。[曦云通用计算 GPU 用户指南，L1](https://developer.metax-tech.com/api/client/document/preview/376/C500_UserGuide_CN.html) C500 产品页进一步给出 64GB 高带宽显存、全链路 ECC、2/4 卡 MetaXLink、最小 1% 颗粒度虚拟化和最大 350W 功耗。[C500 产品页，L1](https://www.metax-tech.com/prod.html?cid=107&id=21) 这些是 POC 配置和隔离策略的可用输入，而不是性能承诺。

开源 `gpuBenchmark` 仓库则提供了较小的、真实可审计的开发者痕迹：仓库声称以 CUDA 语言编写计算、内存、算子和算法 benchmark，覆盖 MetaX 与 NVIDIA，并说明用 A100 和 MetaX GPU 测试；研究日页面显示公开仓库只有 6 stars、2 forks、0 issues、1 次提交。[仓库主页，L3](https://github.com/MetaX-MACA/gpuBenchmark) 前半部分表明至少存在跨平台测试意图；后半部分反而提醒我们不要把它当成大规模第三方社区认同或生产压力测试。没有足够的外部 issue、独立贡献或长期调度故障资料时，产品可靠性须以现场 POC 取证。

对比之下，年报的“30 万注册用户、5591 万 API 调用”是公司内部统计，可能包含下载、试用和教育用户；GitHub star 也不等于活跃使用。两类指标回答的是不同问题：前者说明公司有分发渠道，后者说明公开协作规模仍小。报告将二者并列，正是为了避免把“文档可获取”误写成“开发者生态已成熟”。

### 机器人 POC：应把可测指标写进采购/合作协议

以下为本报告的**建议性验收设计，不是沐曦已公开达成的性能**。目标是把“可迁移、可用、可供货”变成可审计事实。

| 阶段 | 负载与对照 | 必测指标 | 通过/否决逻辑 |
|---|---|---|---|
| 0：安装与兼容 | C500 单卡；我们当前 CUDA 容器为对照 | 从裸机到容器成功率、驱动/固件版本锁定、框架导入、算子缺失数、代码修改行数 | 一项关键自定义算子无法替代即暂停，先由供应商给修复计划；不要以绕开负载的 demo 通过。 |
| 1：正确性与推理 | 视觉编码器、VLM、量化 VLA；NVIDIA 同精度对照 | 固定输入输出误差、tokens/s 或 samples/s、P50/P95 延迟、显存占用、重启后可复现性 | 误差阈值由模型所有者预设；吞吐必须同时报告 batch、序列长度、量化、驱动与功耗。 |
| 2：训练与通信 | 8 卡、再扩至 32/128 卡的 LoRA/后训练及 world-model 小规模预训练 | 每 step 时间、扩展效率、all-reduce 带宽、MFU、loss 曲线、48/168 小时无人工干预运行、故障恢复 | 不仅看首小时跑通；若扩容后吞吐下降或 loss 不一致，MetaXLink/MXMACA 价值尚未证明。 |
| 3：数据闭环/仿真 | 多相机数据解码、重放、合成数据/数字孪生渲染前后处理 | 端到端数据吞吐、存储/网络瓶颈、GPU 利用率、可观测性、每千帧/每万 step 成本 | 曦彩 G 系列尚在研时，图形渲染不列为其交付承诺；可先用 C 系列计算负载评估。 |
| 4：供应与运营 | 小批量后再谈集群 | 交期、备卡/RMA、驱动 CVE/升级 SLA、HBM/板卡二供、能耗、实际回款/合同条款 | 供应商拒绝提供版本支持、备件与升级边界时，不把其放入关键训练路径。 |

这套设计还解释了为何不应把云端 C600 直接等同为机载机器人芯片：350W 级 C500 是数据中心板卡形态，机器人机载控制关心的功耗、热设计、实时确定性、功能安全和生命周期都不同。沐曦可以成为训练和云端推理底座候选人；要进入本体侧，仍需独立评估低功耗边缘产品与安全架构。

## 横纵交汇洞察与三种剧本

早期全建制团队与连续融资，解释了沐曦为何能较快从芯片设计走到多代产品、互连和规模出货；这也是它比图形优先 GPU 创业公司更接近机器人训练栈的历史根源。反面是，越早选择“全栈通用 GPU”，越必须长期负担软件兼容、模型 Day 0 适配和集群售后的成本。2025 的营收跃升与亏损共存不是矛盾，而是这一商业模式在扩大交付期的正常压力测试。

1. **最可能：成为中国云端训推的第二供应商之一。** C500 持续出货，C600 完成良率/客户爬坡，MXMACA 把主流开源模型迁移成本降到可接受水平；收入增长快于研发摊销，但短期仍需高投入。观察信号：C600 量产销售、应收账款/存货、毛利、具名/可验证集群扩容。
2. **最危险：供应链和生态的双重挤压。** 先进制程/HBM/封测受限或成本上升，C600 量产延期；与此同时热门模型/框架的算子和分布式通信落后，客户转回 NVIDIA、昇腾或其他国产卡。观察信号：风险量产长期未转销售、重大客户集中度恶化、开发者 issue 堆积和回款周期拉长。
3. **最乐观：从单卡替代进化为国产训练平台。** MetaXLink 超节点、MXMACA 与主流框架/模型形成稳定组合，万卡集群经独立验收，C600 的国产供应链降低交付不确定性；在具身智能世界模型、VLA 后训练和推理中出现可重复案例。观察信号：公开可复现分布式训练结果、机器人客户复购、软件社区外部贡献和长期 SLA。

## 产业链分类复核

**唯一主分类：1.1 GPGPU（AI GPU）。** 沐曦的主价值创造是设计和销售用于训练、推理与通用计算的 GPU 板卡、服务器和集群；C 系列、HBM、MetaXLink 与规模化智算部署均指向 AI GPU 硬件平台，因而 1.1 比单列软件更能反映收入来源和核心技术优势。

**次分类：2.1 加速计算平台（CUDA-like）。** MXMACA 是公司可复用的迁移/编译/调试/性能工具链，且是获取训练客户的重要护城河；但软件栈服务于自家 GPU 的销售与交付，当前公开证据不足以支持将其视为独立于硬件、以软件订阅为主的价值捕获，因此只能列为次类。

**分类建议：** 总表若仅将其标为“GPU”，建议补充上述主/次层级，并在公司页明确“云端训练/推理优先；图形渲染 G 系列尚在研”。不要因其适配具身智能相关模型就转入第 6 类模型公司，亦不要把 CUDA 兼容表述升级为已验证的完全等价。
