**主体与品牌边界（先读）**：本报告唯一研究主体是**中科视拓（南京）科技有限公司**（下称“中科视拓”）。AutoDL 是该主体在服务协议中作为乙方提供的 GPU 云服务品牌；协议原文写明“AutoDL平台，即中科视拓（南京）科技有限公司”[S1](../raw/sources/2026-08-09-autodl_service-official.md)。AutoDL 隐私政策则称中科视拓及其子公司**视拓云（南京）科技有限公司**共同提供网站、云服务或产品，并将“视拓云”作为政策简称[S2](../raw/sources/2026-08-09-autodl_privacy-official.md)。因此，视拓云是独立法定主体/关联运营主体，不能把其合同、融资、客户、IP 或经营数据自动归入中科视拓；当来源把两者混称（例如政府稿和媒体稿将中科视拓简称“视拓云”）时，本报告保留原文并标示主体不确定。研究截止日固定为 2026-08-09，不使用截止日后的资料。

**分类裁决**：主分类沿任务清单归入 **8 其他——GPU 算力租赁/云服务**。AutoDL 的可验证价值来自算力零售、容器云运营、镜像/API 与开发者服务的组合，而非芯片设计、通用训练框架或独立数据服务；“服务器设计、生产和销售”“十万卡/万P调度”等仅在公司/媒体自述层面成立，暂不据此新增二级类。[S3](../raw/sources/2026-08-09-autodl_about-official.md)[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)

## 一、执行摘要：它卖的不是一张 GPU，而是低摩擦的算力使用权

中科视拓的核心产品 AutoDL 将 GPU 租赁做成面向科研人员、学生和中小企业的 C 端零售：按秒计费、实例容器化、镜像和文档降低环境配置成本。官方协议与计费页确认中科视拓是服务合同和国内收款主体[S1](../raw/sources/2026-08-09-autodl_service-official.md)[S5](../raw/sources/2026-08-09-autodl_price-official.md)。截至 2025 年 9 月媒体报道（原始采访为中国证券报）披露，AutoDL 公测四年累计注册用户“超70万”、服务 142 所 985/211/双一流高校、800 多所其他高校和超过 6000 家企业；2024 年收入 1.85 亿元、同比增长 87.24%，创始团队对 2025—2027 年扣非净利润作出 4000 万/8000 万/6000 万的承诺[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)。官网学术合作页（未标注发布日期，抓取于截止日）又称已服务近 1,000 所高校和超 100 万用户[S6](../raw/sources/2026-08-09-autodl_academic-official.md)；两组口径存在时间/统计范围差异，不能拼接成单一增长曲线。

东方国信于 2024 年向中科视拓投资“6000 万元战略融资”（南京江北新区官方稿）[S7](../raw/sources/2026-08-09-nanjing-jbe-newzone-视拓云-6000万融资.md)；2025 年媒体披露其收购 33.3529% 股权，将持股由 17.6471% 提至 51%[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)。这条资本线把 AutoDL 从纯 C 端零售拉向“东方国信企业客户与 IDC 资产 + AutoDL 零售渠道”的协同，但交易对价、股东清单和业绩承诺原始协议仍需尽调。

对人形机器人公司，AutoDL 更像低成本的训练/微调/推理弹性池，而不是生产级关键任务云。采购可从小规模训练、数据预处理和离线评测切入；涉及机器人数据、模型权重和长时间多卡训练时，必须用 SLA、数据隔离、可迁移性和故障补偿闸门验证。投资可观察但不宜在主体/IP/客户复购未核清前下注；并购优先级低于合作。

## 二、纵向轴：从容器云红利到资本控股

### 1. 萌芽（2018—2020）：容器云让 GPU 资产变得可运营

南京江北新区官方稿称，中科视拓（稿件简称“视拓云”）成立于 **2018 年 12 月**，业务起点是裸金属 GPU 云，并延伸至 AI 云计算、算力 C 端零售、算力资产运营、开发者社区和 AI 服务器设计生产销售[S7](../raw/sources/2026-08-09-nanjing-jbe-newzone-视拓云-6000万融资.md)。王梓丞在 2025 年采访中解释，2019 年前算力投资和技术门槛高；容器云成熟降低 GPU 集群管理成本，AI 应用扩张带来“性价比优先”的需求[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)。这解释了早期路径：不与阿里云等比拼全栈云，而以闲置/分散 GPU 的统一管理和零售定价切入。

尚未找到可复核的一手工商档案、创始团队完整名单、2018—2020 年客户合同或产品版本记录。王梓丞可被一手采访确认是“创始人之一、总经理”，其他创始人、技术负责人和股权比例均未证实[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)。

### 2. 产品成形（2021）：AutoDL 公测与科研用户飞轮

AutoDL 官方高校合作页称平台上线于 **2021 年 9 月**；同页以公司自述口径称累计近 1,000 所高校、超 100 万用户[S6](../raw/sources/2026-08-09-autodl_academic-official.md)。2025 年采访则说“核心产品 AutoDL.com 于 2021 年 9 月公测”，早期用户来自对价格敏感的科研院所师生，之后渗透企业[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)。

产品锁定了三个关键习惯：

- **按秒计费**：实例开机开始、关机结束，时长精确到秒；按量/包年包月可转换[S5](../raw/sources/2026-08-09-autodl_price-official.md)。
- **容器和镜像优先**：GPU、CPU、内存按 GPU 数量比例分配，GPU 对实例独占；文档覆盖 JupyterLab、SSH、VSCode、CUDA、PyTorch、分布式训练等[S8](../raw/sources/2026-08-09-autodl_about-official.md)[S9](../raw/sources/2026-08-09-autodl_service-official.md)。
- **可复现与社区**：CodeWithGPU.com 提供代码索引、镜像和模型托管；其与 AutoDL 的关系在政府稿和媒体稿中被描述为同一运营生态，但法定主体/IP 归属未单独披露[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)[S7](../raw/sources/2026-08-09-nanjing-jbe-newzone-视拓云-6000万融资.md)。

### 3. 规模化运营（2022—2023）：从单实例到企业弹性部署

官方文档显示，AutoDL 已将产品从交互式容器扩展到企业弹性部署：ReplicaSet 维持副本数，Job/Container 管理批任务；企业用户可按 GPU 型号、数量、CPU、内存和价格约束调度[S10](../raw/sources/2026-08-09-autodl_elastic-official.md)。Pro API 支持企业认证后通过 token 创建实例、指定地域/GPU 数量/镜像/CUDA 下限，并查询实例状态[S11](../raw/sources/2026-08-09-autodl_instance_pro_api-official.md)。普通 API 提供余额和累计消费查询[S12](../raw/sources/2026-08-09-autodl_common_api-official.md)。这些是“平台化”而非简单转售的可验证产品证据。

公开性能实测以 PyTorch 1.9、ResNet50 和 ViT 单卡为主，说明公司在 GPU 选型和基准呈现上服务开发者，但不等价于多机多卡训练效率或机器人 VLA 工作负载验证[S13](../raw/sources/2026-08-09-autodl_gpu_perf-official.md)。

### 4. 资本与纵向整合（2024）：东方国信入股、6000 万元战略融资

2024-06-03 南京江北新区管委会披露：中科视拓完成 **6000 万元战略融资，投资方为东方国信**；官方稿同时称中科视拓成立于 2018 年 12 月，运营 AutoDL 和 CodeWithGPU[S7](../raw/sources/2026-08-09-nanjing-jbe-newzone-视拓云-6000万融资.md)。稿件没有披露投前估值、股份比例、董事席位或资金用途。2025 年媒体回溯称东方国信早在 2024 年 3 月参股，持股 17.6471%[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)；3 月入股与 6 月融资的法律关系（同一轮还是分步交割）未确认。

### 5. 控股与 TO B 扩张（2025）：从零售渠道到双向资产协同

2025-09-05 中国证券报报道，东方国信收购中科视拓 **33.3529%** 股权，持股从 17.6471% 增至 **51%**，成为控股股东[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)。报道所述协同是：东方国信导入企业客户和 IDC/IaaS 资产；中科视拓以 AutoDL 零售渠道消化算力、支持东方国信算法研发，并把 C 端小微企业需求向后端大数据/定制 AI 服务转化。交易对价、交割日、剩余股东、控制协议、品牌/IP/数据授权均未在该报道中披露。

同一报道给出经营指标：2024 年收入 **1.85 亿元**（同比 **+87.24%**）；创始团队承诺 2025—2027 年扣非净利润不低于 **4000 万、8000 万、6000 万元**；运营超过 **2 万张、20 多型号** GPU/国产加速芯片，底层容器云宣称可管理“十万卡、万P”；AutoDL 价格可低至大型云刊例价“一到两折”[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)。这些数字均为媒体引述公司/交易文件口径，尚无审计财报或合同复核，不应直接作为估值事实。

### 6. 截止日产品状态（2026-08-09）：面向 C 端、企业和硬件的三条线

官方“关于我们”页将视拓云（南京）科技有限公司描述为从事 AI 云计算、C 端算力零售、算力资产运营、开发者社区和 AI 服务器设计生产销售，称 AutoDL 是全国最大的 C 端平台之一，具备“万卡/千P”调度能力[S3](../raw/sources/2026-08-09-autodl_about-official.md)。由于该页面主体写的是视拓云而非中科视拓，报告只把它作为关联运营自述，不迁移至中科视拓的法定能力清单。

AutoDL 收款页显示国内对公账户户名为中科视拓（南京）科技有限公司；国际汇款收款名为 SEETACLOUD TECHNOLOGY CO., LTD.，说明跨境收款主体与国内法定主体存在差异，具体公司登记和委托关系需核验[S5](../raw/sources/2026-08-09-autodl_price-official.md)。AI 服务器页提供整机销售、三年质保和托管到 AutoDL 机房的选项，但未披露制造商、产能和 IP 归属[S14](../raw/sources/2026-08-09-autodl_server-official.md)。

## 三、横向轴：四类真实替代方案

### A. 大型公有云 GPU IaaS：阿里云、腾讯云

阿里云 GPU 云服务器提供包年包月、按量、抢占式，覆盖单卡至万卡集群，连接容器、NAS、VPC、云安全和跨 28 个地域，并强调故障巡检、节点替换、机密计算和具身智能/模型训练场景[S15](../raw/sources/2026-08-09-aliyun-official.md)。腾讯云 GPU 云服务器提供 GPU IaaS、HAI 一键 AI 环境、HCC 高性能集群、TACO Infer/Train、qGPU 和 RDMA，并展示深圳地铁、微众银行、晶泰科技等客户案例[S16](../raw/sources/2026-08-09-tencent-official.md)。

相对大型云，AutoDL 的差异是更窄但更深的“按秒零售 + 预置镜像 + 社区教程 + 低价”。短板是地域/合规/企业 SLA、机密计算、专有网络、跨区容灾和成熟账单体系的公开证据明显少于阿里/腾讯。对于人形机器人研发，AutoDL 可替代公有云的低成本实验层；涉及机器人视频、遥操作轨迹和未发布模型的生产训练，公有云的隔离与合规能力更可审计。

### B. GPU 供给市场（Marketplace）：Vast.ai

Vast.ai 官方定位为 GPU marketplace/developer platform，公开 20,000+ GPU、40+ 数据中心、68+ GPU 类型、按供需定价、按秒计费，并提供 CLI、Python SDK、REST API、GPU Cloud、Serverless 和多节点 Cluster[S17](../raw/sources/2026-08-09-vast-official.md)。其供给弹性和 API 原生能力强于 AutoDL 的单一平台资源池，但 marketplace 的主机质量、地理合规和供给方异质性带来稳定性与数据驻留风险。AutoDL 以统一镜像、客服和价格体验换取供给范围较窄；Vast 以可编程采购和实时价格换取运维复杂度。

### C. Serverless 推理平台：Runpod Serverless

Runpod Serverless 把 Docker worker、endpoint、按请求拉起/空闲关停和按实际计算时间付费组合起来；官方文档明确冷启动与模型加载时间是关键性能变量，并支持 ComfyUI worker 和 API 调用[S18](../raw/sources/2026-08-09-runpod-official.md)。这是真实的产品替代：当机器人公司把视觉模型、语音模型或仿真服务封装成 API 时，Runpod 的 scale-to-zero 比 AutoDL 长驻容器更贴近线上推理。AutoDL 的优势仍在交互式训练、数据盘、镜像复现和按实例控制；其弹性部署尚未公开冷启动、P95 延迟或按请求计费指标。

### D. 自建/托管 GPU 集群

人形机器人公司可以购买 8 卡服务器并自建机房，或使用 AutoDL 的服务器托管选项。AutoDL AI 服务器页称整机三年质保，并可托管于其机房[S14](../raw/sources/2026-08-09-autodl_server-official.md)。自建方案在数据主权、长期利用率和定制网络上更强，但要承担采购折旧、运维团队、电力和供应链风险；AutoDL 采购/托管则降低前期 CAPEX，却把可用性和迁移责任交给服务商。对机器人公司，只有当 GPU 利用率持续高、工作负载稳定且数据合规要求高时，自建才可能胜出。

中国证券报引述开票数据称 AutoDL 累计服务 142 所 985/211/双一流高校、800 多所其他高校和超过 6000 家企业[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)；官方页称近 1,000 所高校、超 100 万用户[S6](../raw/sources/2026-08-09-autodl_academic-official.md)。这是聚合数量，不是可公开核验的客户名单、订单金额或续费率。没有证据把任何具体人形机器人公司列为客户。

### 4. 产业合作网络（资产、供应、渠道，不等同技术合作）

来源提及服务器生产、AIDC/机房、算力资产运营和东方国信 IDC 资产导入[S3](../raw/sources/2026-08-09-autodl_about-official.md)[S4](../raw/sources/2026-08-09-sina-东方国信控股视拓云报道.md)。具体机房运营商、GPU 供应商、服务器 OEM、网络和电力合作方均未披露。AutoDL 服务器托管是可购买产品，不证明客户或供应商关系[S14](../raw/sources/2026-08-09-autodl_server-official.md)。

### 5. 技术/联合研发网络

AutoDL 自述拥有底层容器云平台、Pro API、弹性部署和跨 GPU 型号调度[S10](../raw/sources/2026-08-09-autodl_elastic-official.md)[S11](../raw/sources/2026-08-09-autodl_instance_pro_api-official.md)。官方高校页称与东南大学、天津大学、北京理工大学建立长期产学研机制，但未披露项目名称、成果、IP 归属或联合研发合同[S6](../raw/sources/2026-08-09-autodl_academic-official.md)。因此只能记录“合作机制自述”，不能升级为联合专利或共同产品。

### 6. 高校/科研渊源网络（人才、赞助、培养）

官方页称赞助 VALSE、PRCV、CSIG 青科会、中国多媒体大会、RACV 等活动累计“超 300 万元”，并称公司高管担任高校工程博士/硕士校外导师、联合培养研究生和参与创业孵化[S6](../raw/sources/2026-08-09-autodl_academic-official.md)。这些构成获客和品牌网络，不等于高校客户采购或股权关系；具体高管姓名、导师聘书、学生项目和赞助合同未公开。

## 六、冲突与开放问题

1. **主体冲突**：服务协议乙方为中科视拓；隐私政策称中科视拓及子公司视拓云共同服务；“关于我们”页则只写视拓云运营 AutoDL[S1][S2][S3]。需取得两家公司统一社会信用代码、商标/域名登记、软件著作权、数据控制者协议和客户合同模板，确认何种业务由谁开票、谁承担 SLA。
2. **规模冲突**：2025 年报道“超 70 万用户、142+800 高校、6000 企业”与官方页“超 100 万用户、近 1000 高校”不同[S4][S6]。可能是时间更新、自然人/企业账户口径或两个主体合并统计；不得计算增长率或市场份额。
3. **融资冲突/断点**：6000 万元战略融资（2024-06）与媒体回溯的 2024-03、17.6471% 股权比例缺少协议串联；2025 年增持对价未披露[S4][S7]。需调取东方国信公告、审计报告、股权转让协议和工商变更。
4. **技术兑现**：“十万卡/万P”是管理调度能力而非自有 GPU 数量；“2 万张、20 多型号”未说明自有/托管/ marketplace 组成[S4]。需第三方压测多机 NCCL、故障恢复、GPU 利用率、跨地域调度和机器人 VLA 训练。
5. **IP 与社区归属**：CodeWithGPU.com、镜像、模型、文档由哪个主体持有和授权不清；视拓云的独立融资/运营报道不得迁移给中科视拓。需知识产权清单与关联交易披露。
6. **财务质量**：收入 1.85 亿及利润承诺未有公开审计口径；需拆分算力转售毛利、硬件销售、托管、社区和关联方收入，核对应收账款与 GPU 折旧。

## 七、横纵交汇：优势是路径依赖，短板也是

AutoDL 的低价不是单一采购优势，而是 2018—2021 年把容器云、闲置 GPU 和科研用户需求同时锁定后的结果：容器化降低运维，按秒计费降低试错门槛，镜像/社区降低迁移成本，用户规模再反向提高 GPU 采购和调度利用率。这个飞轮在 C 端成立，却尚未被公开证据证明能无缝迁移到企业级多租户合规和机器人长周期训练。

东方国信控股是第二个路径锁定：它可能补上 IDC 资产和 TO B 销售，但也会引入大客户定制、低毛利项目和关联交易治理压力。相较阿里/腾讯的全栈云安全，Vast 的全球供给市场和 Runpod 的 serverless，AutoDL 的位置是“国内开发者友好的中间层”：比公有云便宜易用，比 marketplace 更统一，比 serverless 更适合交互式研发；在跨地域容灾、企业 SLA、机密计算和 GPU 集群网络上则明显欠缺公开证据。

### 三个剧本

- **最可能（基准）**：东方国信导入部分企业客户和闲置资产，AutoDL 保持科研/中小企业零售优势，逐步增加企业弹性部署和推理 API；收入增长但毛利受硬件折旧、机房和大客户折扣约束。触发信号：续费率、企业 ARR、GPU 利用率和 SLA 公开改善。
- **最危险**：GPU 供给价格下跌或大客户挤占资源，低价零售变成资本密集型转售；主体/IP/数据责任不清导致合规或安全事件，客户转向阿里/腾讯的机密计算或 Runpod/Vast 的 API 采购。触发信号：故障赔付争议、应收账款上升、用户规模增长而收入不增。
- **最乐观**：十万卡调度得到第三方验证，东方国信把企业客户和 IDC 资产规模化接入，AutoDL 成为国内中小企业 AI 训练/推理入口，并以镜像、模型、API 和硬件托管形成多元毛利。触发信号：审计收入、跨厂商 GPU 集群实测、头部机器人/制造客户公开复购和 99.9% 以上 SLA。

## 八、面向人形机器人公司的动作建议与验收闸门

### 采购：先做可撤销的实验层

建议采购 AutoDL 按量 GPU，用于数据清洗、仿真渲染、小模型训练、VLA 微调和离线评测；不把未经验证的 AutoDL 作为唯一生产训练云。合同闸门：

1. 由中科视拓盖章确认服务主体、数据控制者、分包机房和视拓云边界；发票、收款账户和 SLA 必须一致[S1][S5]。
2. 以机器人实际工作负载做 30 天 POC：8 卡/多机 NCCL、显存错误、断点续训、对象存储吞吐、P95 启动和故障恢复；指标与阿里/腾讯基线对比[S15][S16]。
3. 明确数据不出指定地域、客户专属网络/加密、删除证明、模型权重归属和事故通知；自定义服务协议对公开端口和违规内容责任较重，不能直接承载敏感机器人数据[S9](../raw/sources/2026-08-09-autodl_service-official.md)。

### 合作：把东方国信协同变成可验收项目

可谈联合方案但不预付长期排他：东方国信提供 IDC/企业资源，AutoDL 提供零售控制面；目标是机器人中小供应商的弹性训练池。闸门是 3 个真实客户、跨两类 GPU 的端到端训练成本下降 ≥20%、月度可用性 ≥99.5%、故障恢复 ≤30 分钟，并由合同规定数据和 IP 责任。达不到则仅保留按量采购。

### 投资：观察性条款优先

在取得审计财务、股权名册、东方国信交易协议、两主体 IP/数据清单前，不建议直接股权投资。若要投资，要求：分主体收入和毛利、GPU 自有/代运营比例、企业客户净留存、前十大客户集中度、关联交易、创始团队锁定与回购/业绩承诺条款。估值只能基于审计 EBITDA/现金流区间，不能把“十万卡”宣传数字当资产。

### 并购：暂不列入首选

并购只有在以下闸门全部通过后才进入候选：中科视拓与视拓云的合同、商标、代码、镜像、模型托管和员工归属可无争议转移；东方国信控股结构与剩余股东同意；连续 12 个月企业客户复购和 GPU 利用率达标；安全、合规、数据删除和多机训练通过第三方审计。否则并购会把主体混淆、资本承诺和基础设施折旧一并买入。

### 自研：只自研控制面适配，不自建 GPU 云

人形机器人公司应自研数据/模型流水线、任务编排、成本监控和跨云抽象层，把 AutoDL、阿里云、腾讯云等作为可替换后端；不建议复制其 GPU 资产和机房。自研闸门：连续 6 个月 GPU 利用率 >60%、外部云年化支出超过自建 TCO 1.5 倍、数据驻留要求无法由云合同满足、并拥有 24×7 运维团队和备件预算。未达到前，采购+多云抽象的期权价值更高。

## 九、结论

唯一研究主体是**中科视拓（南京）科技有限公司**；AutoDL 是其服务协议明确的 GPU 云品牌。**视拓云（南京）科技有限公司**是隐私政策列出的子公司/关联运营主体，关于其独立业务、融资、客户和 IP 的信息必须单独核验。中科视拓的主分类建议维持 **8 其他（GPU 算力租赁/云服务）**。截至 2026-08-09，最稳妥动作是“小额采购 + 多云对照 + 主体/IP 尽调”，合作可行、投资观察、并购暂缓、自研聚焦控制面；任何升级都以可验收的训练效率、SLA、安全和财务闸门为前提。
