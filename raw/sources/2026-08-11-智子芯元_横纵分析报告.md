# 智子芯元（深圳）科技有限责任公司横纵分析报告

> 研究截止日：2026-08-10｜公司简称：智子芯元｜唯一研究主体：**智子芯元（深圳）科技有限责任公司**｜对象类型：AI 算子开发、模型迁移与性能调优软件公司｜研究目的：为人形机器人公司的采购、合作、投资、并购与自研决策提供尽调前判断
>
> 口径说明：官网、媒体采访和融资报道只能证明相关主体“公开这样表述”，不自动证明性能、客户交付、订单、收入、回款、IP 权属或规模化商业化。融资金额保留来源原文中的“千万级”“数千万元”等模糊口径，不做累计金额推算。

## 结论先行

**当前建议：进入技术观察池，优先做受控 PoC；暂不进入生产关键路径，不建议仅凭公开材料立即投资或整体并购。**

智子芯元公开呈现的核心命题很清楚：国产异构算力的难点不仅是有没有芯片，还在于模型、算子、编译器、工具链、数值精度和性能调优之间存在大量人工工作。公司以“AI + 运筹优化”为方法叙事，通过 KernelCAT、ModelBridge、Kerminal 等名称，尝试把任务理解、方案搜索、代码修改、编译纠错、Profiling、硬件在环验证和回归测试组织成一个 Agent 式工程流程。[S1][S2][S3][S5][S6]

这使它更接近一家**算子工程与异构迁移自动化软件公司**，而不是芯片公司、推理框架公司或 CUDA-like 全栈平台。公开证据能够支持其在昇腾场景展示过 DeepSeek-OCR-2、Qwen3-14B 的迁移或调优案例，也能支持其官网正在推广本地化 Kerminal 算子开发产品；但尚没有足以独立验证的代码、完整测试条件、客户验收、SLA、订单、回款、续费、跨后端生产部署或第三方长期用户评价。[S3][S5][S6][S13]

真正值得下注的问题不是“Agent 会不会写 kernel”，而是：它能否在客户私有模型、真实版本组合和长尾失败条件下，持续交付**正确、可审计、可回滚、可维护且比人工更省总人时**的结果。只要这一点尚未由客户和公平基准闭环，38 分钟、30 分钟、28 token/s、40% 提升和“10 分钟生产级算子”等数字都只能作为 PoC 线索，不能作为估值或采购事实。[S3][S5][S6]

| 动作 | 当前判断 | 核心理由 | 升级触发条件 |
| --- | --- | --- | --- |
| 采购 | **仅允许沙箱 PoC** | 无公开客户验收、生产 SLA、支持矩阵和版本维护证据 | 在我方模型与目标 XPU 上通过正确性、性能、回归、安全和总人时验收 |
| 合作 | **优先、小范围、非排他** | 能以低成本验证其是否真正降低迁移与算子工程成本 | 明确数据隔离、代码/IP、退出机制、人工接管和失败责任 |
| 投资 | **观察，不立即立项** | 融资可见，但客户、收入、毛利、股权、IP、估值依据未闭环 | 取得客户合同/回款、cap table、交割文件、可审计 benchmark 与核心团队资料 |
| 并购 | **当前不建议整体并购** | 产品与资产边界早期，可能高度依赖少数人员，成果转化链待核 | 核心代码可转让、团队可留任、研究院成果权属清晰，且 PoC 显示不可替代价值 |
| 自研 | **保留薄层核心能力** | 机器人关键模型的 profiling、算子回归和后端知识不能完全外包 | 若第三方覆盖不足、供应连续性弱或性能差距超过内部阈值，扩大 kernel/编译团队 |

## 一句话结论

**智子芯元（深圳）科技有限责任公司是一家从深圳市大数据研究院孵化、以“AI + 运筹优化”辅助高性能算子开发、模型迁移和异构计算调优的早期基础软件公司；其公开产品方向有真实工程价值，但截至截止日，商业交付、跨后端能力、性能可复现性与 IP 权属仍未达到投资或生产采购所需的证据强度。**

## 纵向分析：从研究院问题意识到算子工程 Agent

### 阶段一：方法来源——把“模型迁移”拆回工程问题

读特采访将丁添介绍为深圳市大数据研究院副研究员、智子芯元创始人，并称其博士毕业后进入华为 2012 实验室，把运筹优化与人工智能用于无线通信等产业问题；2023 年进入深圳市大数据研究院。[S5] 这段履历可以解释公司为何没有从“再做一颗芯片”出发，而是从已有芯片如何被更高效使用出发。

国产算力迁移经常被宣传成模型转换，真实工作却横跨模型图、算子覆盖、编译器、运行时、库、显存/内存布局、框架插件、数值精度、Profiling 和版本兼容。一个模型能在目标卡上启动，不代表它已经正确，也不代表性能、稳定性和维护成本达标。公司公开方法把非标准化的理解与策略交给 AI，把性能搜索交给运筹优化。[S5] 这是有逻辑的分工：Agent 擅长组织步骤、调用工具和修改代码，数学搜索擅长在约束空间中寻找更优组合。

但方法论成立不等于产品壁垒成立。需要核验的是：优化变量如何定义、搜索空间如何裁剪、性能目标是否同时约束正确性与资源、失败样本是否反馈到规则或模型、客户私有代码是否能合规复用经验。公开材料没有论文、架构白皮书、专利权利要求、代码或消融实验，因而只能确认公司这样描述方法，不能确认算法独创性和不可替代性。

### 阶段二：2025 年公司化——KernelCAT 与昇腾案例

读特报道写道，2025 年丁添及团队在深圳市大数据研究院内部讨论后决定将想法公司化，并称同年 8 月智子芯元正式成立；东方财富转载科创板日报也把成立年份写为 2025。[S5][S7] 由于未取得工商设立文件，本报告将“2025 年成立”作为经营时间线，不把 8 月写成法律设立日。

早期公开产品是 KernelCAT。读特将其称为“全自动的 AI 模型迁移工具”，并转述一个案例：将 DeepSeek-OCR-2 多模态模型部署到华为昇腾平台并完成推理验证，耗时 38 分钟。采访中给出的目标交互是，用户以自然语言下达“把模型部署到华为 910B 推理卡”之类的任务，系统搜索方案、配置环境、编写代码并交付可运行结果。[S5]

这段材料证明了三点：团队公开聚焦国产算力迁移；产品入口强调自然语言与端到端执行；昇腾是最早可见的展示后端。它没有证明：38 分钟包含全部环境准备和人工介入；模型版本、权重、精度、输入条件和 CANN 版本一致；工具覆盖任意模型与芯片；产物可长期维护；DeepSeek 或华为是客户。把一次媒体案例扩张为通用平台或客户交付，会越过证据边界。

### 阶段三：2025 年末融资与 ModelBridge——从“跑通”走向“调优”

2025 年 11 月 11 日，36Kr 时氪分享文章标题称智子芯元完成“数千万元种子轮融资”，正文写“千万级人民币种子轮”，投资方为真格基金、英诺天使基金、松禾资本，深蓝资本为后续独家财务顾问。[S6] 同一来源内金额口径不一致，因此本报告完整保留两种原文，不选取其中一个做精确累计；深蓝资本也不列为投资人。

该报道又引入第一款产品 `ModelBridge`，称其在 2025 华为全联接大会亮相：30 分钟完成 Qwen3-14B 在昇腾 Atlas 上的全自动适配与推理部署；2 小时后单卡吞吐达到 28 token/s，相比“官方社区最新镜像（双卡）”提升 40%。[S6]

从纵向看，公司叙事已经从“能迁移”进到“能调优”。这比单纯模型转换更接近可付费价值，因为客户最终购买的不是演示，而是更少工程人日、更低成本或更高吞吐。然而该数字缺少模型版本、精度/量化、Atlas 型号、输入输出长度、并发、首 token 延迟、显存、功耗、软件版本、人工介入次数和可复现脚本。单卡与双卡如果测试条件不同，40% 也无法用于横向排名。其合理用途是构造 PoC，不是证明领先。

### 阶段四：2026 年 Kerminal 产品化——从单次迁移到本地工作台

当前 KernelCAT 官网把体系描述为“一个底层引擎、两大产品线”：Kerminal 面向算子开发与计算加速，KerWork 面向通用桌面任务执行。[S1] Kerminal 官网定位为“AI 驱动的算子开发平台”，公开列出 AI 算子开发、内核调优、编译纠错、硬件在环验证、本地文件读写与命令执行、Plan/TODO、多层审批、CUDA 至 CANN 迁移、Profiling、热点定位、算法重构和自动回归。[S1][S3]

这是公司最关键的产品收敛。早期 ModelBridge 强调模型级迁移，Kerminal 把工作单元下沉到 kernel、编译和性能工程，并强调本地化、安全与人工审批。若这些能力真实可用，它更可能进入客户研发流程：不仅交付一次结果，还积累项目上下文、错误模式、回归资产和后端知识。

同时，官网的“10 分钟交付生产级算子代码”“微秒级延迟优化”仍是宣传主张。[S3] 没有公开支持矩阵、benchmark、源码、用户 issue、失败率、人工接管率、日志格式、版本维护承诺或客户验收。尤其“本地执行”需要访问客户代码、编译环境和硬件，安全性不能由“多层审批”四个字替代，必须验证网络出口、遥测、模型调用位置、凭据、命令隔离、日志脱敏和回滚。

### 阶段五：KerWork 与双线扩张——复用底座还是分散资源

KerWork 官网将产品描述为桌面执行助手，可读取本地资料、调度软件或浏览器并交付文档和代码；页面称 macOS 已上线，Windows 和 Linux 即将推出。[S4] 这说明团队可能把同一套 Agent 计划、工具调用、权限控制和执行框架扩展到通用工作场景。

这条扩张存在两种相反解释。一种是正向复用：通用 Agent 底座、权限与交互能力由更广产品线打磨，再回流 Kerminal。另一种是资源稀释：算子工程需要编译器、硬件和性能专家，通用桌面 Agent 又面对完全不同的产品竞争，早期团队可能难以同时建立两个市场。公开材料没有收入、活跃用户、团队分配或产品优先级，不能裁决。投资前必须问清 KerWork 是独立商业主线、获客实验，还是 Kerminal 的通用执行底座。

### 阶段六：2026 年融资可见度上升——交易仍不能重复累计

2026 年 6 月 22 日，东方财富转载科创板日报称智子芯元完成“数千万元天使+轮融资”，鼎峰科创、英诺基金、首程控股联合领投，同创伟业跟投。[S7] 同日证券之星转载智通财经称，首程资本旗下公司管理的基金投资智子芯元（深圳）科技有限责任公司。[S8]

两条材料日期相同且都涉及首程，极可能描述同一轮融资或同一交易链的两个披露角度。缺少基金名称、投资协议、交割日和金额拆分，因此本报告不把首程投资另算一轮，也不推算累计融资、投后估值、持股比例、董事席位和控制权。融资报道能说明资本关注度提高，不能替代商业验证。

## 横向分析：它竞争的不是一家公司，而是四条完成任务的路线

### 竞争场景

公开资料不足以可靠枚举智子芯元的直接商业竞品，也没有客户、价格和市场份额可供同口径比较。更合理的横截面是从客户购买决策出发：客户为了把模型迁到目标硬件、开发高性能 kernel、修正编译错误并持续维护，当前有四条替代路线。

| 替代路线 | 代表方案 | 客户购买/选择理由 | 对智子芯元的压力 |
| --- | --- | --- | --- |
| 芯片原生软件栈 | 华为 CANN、Ascend C、ATC、AOE、分析迁移与精度/性能工具 | 后端信息完整、与硬件和版本同步、原厂支持责任较清楚 [S9] | 若 Kerminal 只是自然语言包装，原生工具增强后会吸收其价值 |
| 成熟 GPU 计算/推理栈 | NVIDIA TensorRT、AMD ROCm/HIP | runtime、编译器、库、通信、profiling、框架与运维相对完整 [S12][S14] | 说明跨后端迁移远不止代码翻译，需持续覆盖整个工程栈 |
| 开源编译器与 DSL | Apache TVM、Triton | 可控、可修改、能力沉淀在内部，适合强 compiler/kernel 团队 [S10][S11] | Kerminal 必须证明更低总成本且产物可接管，避免闭源黑箱锁定 |
| 人工工程与集成服务 | 内部工程师、芯片厂支持、系统集成商 | 能处理私有代码、长尾故障、责任和紧急回退 | 当前最现实的替代；Agent 要在总人时、成功率、维护上胜出 |

### 与 CANN/AOE：底层依赖，不宜假设为被替代对象

CANN 官方文档覆盖驱动之上的框架支持、Ascend C/TBE/AI CPU 算子开发、毕昇编译器、图与 DataFlow、HCCL、ATB、ATC、AOE、脚本迁移、精度调试、性能调优和模型/算子查询。[S9] 它具备 Kerminal 不应也难以短期复制的硬件知识和版本责任。

智子芯元更合理的位置，是把原生能力编排成一条可理解、可执行、可验证的工作流：识别目标，选择工具，修改代码，编译运行，比较精度与性能，保存失败原因和回归资产。[S3] 若能显著降低人日而不损失可控性，它是原生栈之上的生产力层；若只是调用已有脚本并生成看似合理的代码，客户会回到原厂工具或人工服务。

昇腾优先还带来集中风险。公开案例和 CUDA→CANN 主张都聚焦同一生态，尚未证明在第二种非 NVIDIA 后端上有等强能力。[S1][S3][S5][S6] 原厂工具持续吸收 Agent、迁移与自动调优功能时，公司需要依靠跨后端抽象、错误知识、客户工程数据、可审计体验或交付效率维持差异。

### 与 TVM/Triton：客户是在买抽象能力，还是买交付过程

Apache TVM 是深度学习编译器，公开文档覆盖模型导入、端到端优化、代码生成、算子融合、Runtime、TensorIR、MetaSchedule、Relax 与自定义 codegen。[S10] Triton 是面向并行编程的语言和编译器，以 Python 风格编写高吞吐 DNN kernel，并提供 MLIR、调试和编程文档。[S11]

这两类方案把能力留在客户内部，优势是可控、可修改、可长期积累；代价是需要编译器、后端和性能工程人才。Kerminal 的潜在价值不是取代 TVM 或 Triton，而是把理解任务、生成/修改 kernel、调用编译工具、Profiling 和回归组织成较低门槛的过程。[S3]

横向验收应聚焦四件事：生成代码是否正确且可读；性能是否在公平基线下稳定；失败是否可解释、能否人工接管；停止采购后客户能否维护产物。若答案是否定的，“自动化”会把工程复杂性从显式工具链移进不可追踪的 Agent 状态，反而增加机器人公司模型代码和生产环境的风险。

### 与 TensorRT/ROCm：成熟栈定义了“迁移完成”的最低含义

TensorRT 官方文档将其描述为把训练模型编译成 GPU 专用 engine 的 SDK，包括 builder 和 runtime；不支持的算子需要插件，实际加速取决于模型、精度、batch 和 GPU。[S12] ROCm 官方文档则列出编译器、runtime、数学库、通信库、profiling/debug、PyTorch/JAX、vLLM/SGLang 以及集群部署运维组件。[S14]

这些成熟栈提醒我们：迁移不是“跑通一个模型”即可完成。算子覆盖、runtime、精度、内存、通信、容器、监控、版本兼容、故障恢复和回归都要进入交付。智子芯元公开展示的是上层自动化入口和个别案例，尚不能与完整加速计算平台的确定性能力等同。

### 与人工工程：真正的基准是端到端总成本

人工路线昂贵、排队且经验容易锁在个人，但它能处理非标准模型图、私有算子、异常精度、紧急回退和责任界面。智子芯元要替代的不是某条命令，而是一部分人工诊断、搜索和重复劳动。

PoC 必须比较从任务创建到可复现交付的**总人时**，而不只计算 Agent 自己运行的分钟数。还要测量：首次成功率、最终正确率、数值回归、性能稳定性、人工审批与接管次数、失败诊断质量、驱动/框架升级后的维护成本、代码可读性和供应商退出成本。只要这些指标缺失，“38 分钟”就可能只是把此前准备时间隐藏在演示之外。

### 用户与商业模式视角

本次未检索到可信第三方用户访谈、GitHub issue、独立评测、长期运维评价或公开价格。[S13] 不应虚构“Kerminal 用户口碑”。根据产品形态，只能提出三类潜在买家假设：缺少 kernel 团队的模型/应用公司；需要国产化迁移的系统集成商或算力运营方；希望提高内部性能工程师杠杆的芯片与基础软件团队。

同样，商业模式仍待核验。可能的收入承载物包括开发者订阅、企业私有化许可、按项目专业服务、按硬件后端或席位收费、联合交付分成。不同模式对毛利和壁垒含义完全不同：若收入主要依赖专家驻场，公司更像带工具的工程服务；若标准软件能在不同客户重复交付并续费，才接近可规模化基础软件。

## 横纵交汇：历史选择如何塑造今天的位置

### 优势与风险具有同一个根

智子芯元的优势来自一个正确的问题定义：国产算力的瓶颈不仅是峰值算力，还包括迁移、算子、编译和调优的人力成本。丁添的运筹优化和产业工程背景，使公司能够把 Agent 的任务理解与数学搜索结合，而不是只做聊天式代码补全。[S5] 昇腾案例又让它从高痛点、政策与产业需求都强的场景切入。[S5][S6]

同一历史也制造了风险。研究院环境适合快速证明方法，商业客户要求在不同代码、硬件、版本、安全制度和责任边界中重复交付；昇腾优先帮助建立早期案例，也可能形成单后端依赖；自然语言入口降低操作门槛，却可能把工具链复杂性藏进黑箱；KerWork 复用 Agent 底座，也可能分散算子团队。

所以，公司今天最关键的分水岭不是再发布一个更漂亮的 demo，而是把隐性的工程判断产品化：支持矩阵要明确，失败要分类，日志要可审计，产物要能接管，版本升级要可回归，客户案例要能由对方验证。做到这些，历史路径会沉淀为工程知识资产；做不到，历史上的“AI + 数学”会停留在融资叙事。

### 三个未来剧本与触发条件

#### 最可能剧本：国产算力迁移与算子服务的人机协同工作台

公司先在昇腾或少数国产后端积累模板、错误知识和优化流程，以企业私有化软件加专业服务交付。它不替代 CANN，只减少迁移和调优的人日，并允许人工接管。

**触发条件：**出现至少两个可验证的付费客户；在同一后端多个模型上维持正确性和稳定收益；软件收入或续费可与驻场服务分离；提供日志、回滚、版本支持和安全材料。

**对我方含义：**适合非排他 PoC 和小额采购，但仍保留内部 benchmark 与关键 kernel 能力，不把生产连续性完全交给单一供应商。

#### 下行剧本：展示强、交付弱，退化为项目制工程服务

公开 demo 在私有模型、长尾算子或版本升级中需要大量人工兜底；原厂工具吸收自动迁移功能；通用 KerWork 分散团队；客户以一次性项目采购，毛利和复购受限。

**触发条件：**PoC 失败率高或人工介入不可披露；没有第二后端；客户不愿提供复购证明；收入高度集中于定制项目；核心人员离开即影响交付；产品无法离线或通过安全审计。

**对我方含义：**停止资本动作，只按明确成果、里程碑和源代码托管购买服务；关键工作回归内部团队或原厂支持。

#### 上行剧本：形成跨后端、可审计的优化资产层

Kerminal 在 CUDA、CANN 及至少另一类非 NVIDIA 后端上持续生成可复现 kernel、迁移补丁、性能回归和错误诊断；每次客户工程都沉淀为合规可复用的规则与基准资产。公司成为芯片厂、模型团队和终端企业之间降低硬件替换成本的工具层。

**触发条件：**多后端生产客户与独立 benchmark；标准软件收入和高续费；核心数据/IP 权属清晰；后端升级可快速适配；形成开发者生态、API 或合作伙伴交付网络。

**对我方含义：**可讨论战略投资、联合开发或少数股权，以锁定机器人工作负载支持和自研芯片适配优先级；估值仍应由收入质量与壁垒而非宣传性能决定。

## 面向人形机器人公司的动作建议

### 采购：先验证非安全关键工作负载

机器人公司的潜在相关负载包括 VLM/VLA 视觉编码器、Transformer attention、视觉预处理、自定义 CUDA kernel、仿真与数据处理、离线评测和边缘/服务器推理。Kerminal 对 CUDA→CANN、Profiling、编译纠错和硬件在环的公开主张，与“从 NVIDIA 路径迁移部分训练/推理到国产 XPU”有潜在交集。[S1][S3]

建议从可脱敏、可回退、非安全关键的子图开始，不直接让其接触机器人原始数据、核心权重、运动控制代码或生产凭据。采购合同应把交付物写成可运行代码、构建环境、测试报告、日志、回归脚本和维护承诺，而不是只购买“迁移成功”。

### 合作：设计四阶段、可证伪的 PoC

| 阶段 | 任务 | 验收指标 | 失败说明 |
| --- | --- | --- | --- |
| 1. 可用性 | 一个可脱敏视觉/VLM 子图从 PyTorch/CUDA 迁至指定国产 XPU | 构建成功、算子覆盖、数值误差、人工介入、完整日志 | 无法处理我方基本图结构或环境约束 |
| 2. 性能 | 冻结模型、精度、输入、batch、硬件、软件版本，与人工/CANN 基线比较 | 首 token、P50/P95、吞吐、显存、功耗、编译时间、总人时 | 宣称收益无法在公平条件复现 |
| 3. 工程性 | 加入一个自定义算子，并做一次驱动/框架升级 | 回归通过率、失败解释、回滚时间、代码可读性与接管 | 只能一次性 demo，不能维护 |
| 4. 安全与商业 | 隔离环境审计权限、数据流、合同与退出 | 网络出口、遥测、模型调用、凭据、IP、SLA、迁移权 | 不适合接触模型和生产代码 |

对照组至少包括目标芯片原生工具链和内部工程师现有流程。不得只与没有版本说明的“社区镜像”比较。[S6][S9]

### 投资：以价值归因而非融资热度立项

当前可关注三个信号：国产算力迁移痛点真实；“AI + 运筹优化”具有差异化方法叙事；公司连续获得早期机构融资报道。[S5][S6][S7] 但缺少客户、收入、续费、毛利、跨后端、产品安全、IP、完整股权和公平 benchmark，无法证明价值由标准软件而非少数专家服务创造。

只有在取得至少两个可验证付费客户、清晰软件/服务收入拆分、跨后端复现结果、客户留存、代码/IP 权属和 cap table 后，才建议进入投资委员会。投资条款应关注核心人员留任、研究院成果权属陈述保证、开源/第三方模型合规、客户数据隔离、重大后端依赖和下一轮稀释。

### 并购：当前不整体收购，保留人才与资产选项

早期公司的核心价值可能集中在少数人的隐性经验、私有代码和客户工程上下文。若这些资产无法依法转让，或离开创始团队后不能维护，整体收购会买到一个难以接管的黑箱。KerWork 与 Kerminal 的资产、团队和商业边界也需要拆开。

更可逆的顺序是：技术服务协议 → 联合 PoC → 非排他许可或代码托管 → 对核心团队/IP 的专项尽调 → 再评估人才、资产或整体并购。并购前必须证明核心代码、数据和专利可转移，研究院成果转化清楚，关键人员愿意留任，且目标工作负载上的优势难由原厂工具、开源方案和小型内部团队复制。

### 自研：保留不可外包的薄层能力

建议我方长期自持四项能力：目标模型 benchmark harness；关键算子的正确性与性能回归；目标后端的 profiling、编译和故障知识；生产部署的运行时、安全与回退边界。第三方可以放大迁移和代码生成效率，但不能成为唯一理解模型性能问题和最终产物的人。

若机器人特有算子、低 batch 实时推理、视觉预处理或安全关键链路无法由第三方可靠覆盖，应优先扩充内部 kernel/编译小组。收购一家 Agent 公司不能免除长期维护后端、模型和实时系统的责任。

5. 客户停止订阅后的产物维护权、数据/规则可携带性、源代码托管和退出迁移安排。
6. 原厂工具、开源编译器、通用 coding agent 进入该市场时的差异化和防御策略。
7. 与机器人 VLM/VLA、低 batch、实时性和端侧约束相关的专门 benchmark 与产品路线。

## 方法说明

本报告采用横纵分析法：纵轴追踪公司从研究院孵化、KernelCAT/ModelBridge 展示、融资到 Kerminal/KerWork 产品化的演进；横轴从客户完成相同任务的四条路线比较其生态位。研究遵循“法定主体优先、承重事实可回溯、公司自述不升级为独立验证、合作不升级为订单、展示不升级为商业化”的证据规则。

## 审慎产业链分类结论

### 主分类：**2.2 AI算子开发、迁移与适配**

这是截至 2026-08-10 最能反映智子芯元核心技术优势和价值创造方式的二级分类。理由不是公司使用了“AI”“平台”或“国产算力”等宣传词，而是公开产品反复围绕客户可购买的任务展开：算子开发、kernel 调优、编译纠错、CUDA 至 CANN 迁移、硬件在环验证，以及模型迁移和性能优化。[S1][S3][S5][S6] 如果未来形成收入，当前最可合理推定的承载物也是 Kerminal/KernelCAT 的软件许可、私有化部署或相关工程服务，而非芯片、算力中心、训练框架或模型产品。

该分类仍标注“**商业交付待核验**”：公开资料尚无具名付费客户、订单、回款、续费、生产 SLA 或独立 benchmark，故只能确认产品与技术定位，不能确认规模化商业化。

### 次分类：**暂不设置已成立次分类**

以下方向只作为观察项，不列为次分类：

- **2.1 加速计算平台（CUDA-like）：不纳入。** 智子芯元未公开证明其拥有驱动/运行时、独立编译器/IR、主流框架后端、多卡通信库、开发者 API、完整工具链和多代芯片支持。Kerminal 更像编排既有后端与算子工程的工作流层，不满足 `2.1` 的五项硬条件和 70 分准入要求。[S3][S9][S14]
- **5.2 推理框架：不纳入。** ModelBridge 和模型部署案例只证明公司曾展示模型适配与推理验证，不证明其交付独立 runtime、推理 engine、服务框架或算子覆盖体系。[S5][S6][S12]
- **4.1/4.3 异构调度：不纳入。** “跨平台迁移”解决代码与后端适配，不等同于在运行时跨厂商调度训练/推理任务，也没有多 XPU 资源池、调度策略或生产集群证据。
- **3.4/3.5/3.6 集群软件：不纳入。** 当前产品聚焦开发工作流和本地执行，没有容器平台、集群编排、资源管理或大规模运维交付证据。
- **KerWork 对应的通用 Agent：不改变主分类。** KerWork 是同主体的通用桌面执行产品线，但尚无证据证明它是核心收入来源或应在现有 AI infra 分类中建立稳定次标签。[S1][S4]

若后续尽调证明 Kerminal 主要收入来自标准化算子/迁移软件并有真实客户交付，应继续维持 `2.2`；若实际收入主要来自通用桌面 Agent 或项目制人力服务，应重新评估主分类，不能沿用宣传定位。只有在其独立软件栈满足 `2.1` 全部硬条件并达到评分门槛后，才可把 `2.1` 作为次类或重新讨论主类。
